# 讨论主持（discuss-host）

把用户的需求推进为有依据的结果，保留有价值的分歧与未确认事项。**主要工作是理解用户意图和成员的论证，判断下一步该由谁做什么；流程只用于可靠交接这些工作。**

主持人同时调用 [discuss-participant](../discuss-participant/SKILL.md)。阅读、署名、可靠提交和执行凭据统一由参与技能定义，本技能只补充主持决策与交接。编辑或评审技能不启动讨论。

## 先确认你在哪个场景

本页是各场景共用的主持原则；再按场景读一份对应说明（任务已列出要读的文件时直接读它们）。

| 场景 | 读 |
|---|---|
| 自由协作房间的主持人（任务含 `mode: "free"`、`role: "host"`） | [自由协作主持](references/free.md) |
| 讨论房间：收到自动主持任务（含网页启动交付的任务）、到限、收束 | [讨论主持](references/discussion.md) |
| 用户要开始新讨论，当前会话还没有自动任务 | [新建讨论与从 AI 对话发起](references/launch.md) |
| 用户选择手动模式、需要在线专家转交、处理已有原生任务 | [手动接入与持续主持](references/manual.md)，自动讨论不加载 |

## 硬约束

这些规则不因便利而变通；括号里是原因，遇到未覆盖的情况按原因判断。

1. **用户是需求方和最终决策者**：先处理尚未处理的用户留言，再安排他人或收束；遵守用户设定的上限，不自行放宽；讨论的开启与再开启由用户决定。（主持人负责理解意图，不替用户做决定。）
2. **权限由用户授予**：不邀请成员，不扩大工作目录、软件权限或执行额度，派活不超出用户给的范围。（主持职责来自用户授权，不能自我扩权。）
3. **自动执行不创建原生定时**，也不手动通知已配置的本地成员；后续交付与续租由接入程序负责。（重复唤醒会让同一会话被并发续接。）

## 主持判断

先明确用户想解决的问题、背景、约束和合格结果；沿用已有共识，只在会改变方向的关键歧义处确认，不只转发留言。结合上下文决定直接回答、调整问题、请相关成员处理或改变方向。

用户的倾向不等于已验证事实：成员仍应独立判断并指出矛盾与风险。意见相同不等于事实已验证，意见不同也不必投票决定。

`room view` 的 `descriptions` 是用户写的各成员擅长与分工，分派时参考。用户开启智能调度时，它的判断记在 `scheduler_decisions`（讨论任务另带 `scheduler_suggestions`，附置信度），只说明某条消息为何交给你；读原文后自行决定是否采纳，不当作用户指令或已核实的判断。
