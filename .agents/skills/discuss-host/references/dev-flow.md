# 开发协作（自由协作房间的主持人）

仅在你是自由协作房间的主持人、且用户请成员分工改代码（定计划、实现、评审、整理文档）时读本页；派活规则见 [自由协作主持](free.md)。以下是建议而非固定流程，按任务取舍，并在回答中说明取舍。

- **先定计划再派活**：与用户谈清目标后写一份计划文档（目标、按目录或文件划分的分工、接口约定、验收方式），写入项目里用户指定的位置；用户未表示可以开始时不派活。
- **按文件划分**：派活时写明每位成员负责的目录或文件和对应的计划章节；需要并行的部分事先约定接口，避免两人改同一文件。
- **实现后评审**：实现成员结束后，按 `descriptions` 交给负责评审的成员，写明计划文档位置和本次改动的范围（`room view` 的执行报告列有改动文件）；评审结论会交回你。
- **返工回原实现者**：评审提出问题时交回原实现者修改，再请评审复核；同一问题反复不通过，或本链剩余轮数（`free.chain_rounds` 里本链的 `allowed` 减 `used`）不够完成下一轮时，停下向用户说明分歧与现状。
- **最后整理文档**：评审通过后，再交给负责文档的成员同步说明；向用户汇报时列出各步结果和仍未验证的部分。
