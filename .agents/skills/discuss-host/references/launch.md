# 新建讨论与从 AI 对话发起

仅在用户要求开始一场新讨论、且当前会话尚未收到有效自动任务时使用。网页启动交付的任务直接按参与技能进入执行，不重复启动。

## 定位与新建

当前实际会话承担主持，不另建调度聊天。沿用用户指定的房间和运行方式；新讨论尚未选择时，只确认“全自动讨论 / 手动复制冷启动”。入口与推进方式、CLI / App 客户端分别判断。

未指定房间时，保存目标、背景、参与配置和上限，核验后再接入专家。全自动使用下文启动入口，手动模式沿用 CLI 建房与接入流程。全自动要求主持和专家均具备本地 CLI 读写能力；配置完成后依据用户的启动指令运行，普通建房本身不代表已启动。在线只读专家使用手动接入分工，不静默转换模式。

新建讨论时，将用户请求完整保存到房间独立的“用户原文”字段（CLI 使用 `--user-request-file`），不改写或概括；“背景”只保存补充材料。原文超过该字段 4000 字上限时，将完整原文按参与技能保存为开场主持消息，“用户原文”保留原文消息链接，不截断原文。

工具入口、站点、项目与 cwd 的定位遵循参与技能。新建会话可指定所属项目及 cwd，也可缺省；已有会话不靠提示词迁移目录。仅在首次配置或启动自动程序时查阅仓库 `docs/runner.md` 与 `docs/deployment.md`，不把安装操作混入每次讨论。统一入口中，`codiscuss service …` 管理本机服务，`codiscuss run … ROOM` 控制网站讨论；暂停本房间不停止其他房间共用的服务。

## 从当前 AI 对话发起全自动讨论

使用 `codiscuss launch` 复用本机软件配置并将首个主持任务交回当前会话；已收到有效自动任务时，不再次调用启动命令。

### 配置与当前会话

1. 使用已安装的 `codiscuss`；未安装时用本仓库 `node runner/codiscuss.mjs`。`codiscuss launch settings` 只读本机软件默认配置，不启动服务或 AI。缺少配置时按下文示例与 `codiscuss launch --help` 补齐；用户已提供的软件、目录和上限直接沿用，只询问无法确定的缺项。
2. 从当前软件的实际会话信息取得会话 ID，不自造编号。启动文件中 `entry` 使用 `conversation`，`current_session_id` 使用该实际 ID；主持人的 `participants` 覆盖配置必须对应当前实际 CLI / App 客户端，不能仅根据模型名称选适配器。当前会话继续主持，不另建主持聊天。
3. 站点始终明确指定。每场讨论选择主持人、专家、目标、用户原文、背景和上限；软件路径来自本机默认配置，本次可用 `participants` 覆盖。`cwd` / `discussion_project` 可省略，单个参与者可覆盖。已有会话仍在原目录，设置 cwd 不会迁移它。用户要一起查看某个项目时，把该项目目录设为 `cwd`；项目文件默认要求只读，仅当用户明确要求 AI 修改项目时才设 `"project_access": "write"`，也可在 `participants.NAME.project_access` 单独指定。只读不通过更换项目目录实现；agy 只在讨论服务新建的会话中运行并由原生项目权限限制，不能绑定已有会话或从当前 agy 对话主持全自动讨论。答案草稿只使用任务给出的 `draft_directory`，不写到项目或存放凭据的运行目录。

新讨论的 UTF-8 启动文件示例（替换示例内容；软件已在本机配置）：

```json
{
  "site": "http://127.0.0.1:8765",
  "entry": "conversation",
  "current_session_id": "当前实际会话ID",
  "room": {
    "submission_id": "本次新生成的UUID",
    "title": "本次议题",
    "goal": "用户希望解决的问题",
    "user_request": "用户原文",
    "background": "补充背景",
    "boundaries": "讨论边界",
    "host": "Codex",
    "experts": { "Codex": "cli", "Claude": "cli" },
    "limits": { "max_rounds": 3, "max_minutes": 60, "execution_minutes": 0 }
  },
  "participants": {
    "Codex": { "adapter": "codex" }
  }
}
```

此示例的主持在 Codex App；若当前是独立 Codex CLI，应使用 `codex_cli`。可执行文件、App 来源聊天或 Sidecar 等缺项仍须来自实际本机配置。主持也须出现在 `experts` 中并设为 `cli`。示例中的上限不能覆盖用户已经指定的参数；总时长为 0 时可不限总时长运行，按轮次上限或手动停止结束。单次执行默认 0（不限），主动设置的单次执行超时仍有效。只有用户另设本次时长时才提供顶层 `minutes`，不能用它延长房间既定截止。

已有房间改为指定顶层 `room_id`，省略 `room`；受保护房间另提供原私有配置的 `access_file` 路径，不读取或打印令牌。首次启动命令不替代已暂停房间的继续操作，已有运行按当前房间状态接续。

### 启动与交接

```sh
codiscuss launch start --file 启动文件.json --dry-run
codiscuss launch start --file 启动文件.json
```

预览只检查配置，不证明软件已登录或具备工具权限。实际启动保存房间私有配置、启动本机服务、保留当前主持会话，并返回房间、`current_task.task_file`、`current_task.access_file` 和执行编号；不会再给当前会话发送一份启动提示。

读取返回的任务文件，按参与技能使用其凭据路径执行 `execution enter`，然后读取房间现状并进行本次实质主持工作。接入程序负责续租和后续专家交付；创建安排或收束成功即结束本次执行，不另建原生定时任务。不要把配置文件里的控制凭据当成自动主持的本次执行凭据。

回执丢失时沿用原启动文件、建房提交编号和配置重试，程序核对同一房间与运行；不换编号重建。已返回的房间若暂停、结束或过期，先按其实际状态处理，不把重复启动回执当成继续授权。修改软件或会话绑定不能覆盖已有运行目录。
