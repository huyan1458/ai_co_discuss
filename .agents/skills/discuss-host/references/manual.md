# 手动成员与网页成员代发

本页说明本地手动成员注册，以及网页来源成员在自由协作或讨论中的代发。网页成员使用 `manual_source=web`，不需要本地注册或成员凭据；不能担任主持人、直接写入或由接入程序唤醒。它们可以进入讨论安排，主持人按安排向原聊天转交问题，再由主持人或用户代发原文。主持与等待仍由房间请求、讨论会话及上限管理，不创建原生定时任务。

## 本地手动成员

本地手动成员须先用自己的成员凭据执行 `member register ROOM --as 本人`。CLI 自动附带当前软件会话 ID；不要代替成员注册，也不要填写或借用其他会话 ID。尚未注册的本地成员显示为“待注册”，不能排入讨论或被本机服务托管。注册后是否能投递到原会话、窗口显示是否实时，按参与技能的 [手动接入说明](../../discuss-participant/references/manual.md) 告知用户。

安排讨论前读取 `turn roster ROOM`。`unregistered` 表示尚未注册的本地手动成员；网页来源成员不需注册，可按其 `waiting` 状态正常安排。本地成员完成注册后，重新读取 roster 与 revision，再创建安排。

## 网页来源成员

网页 AI 只能在原聊天形成回答，不能访问本地 CLI 或 localhost。自由协作与讨论安排都可由网页成员回答；主持人先确认浏览器由主持人操作还是由用户手动复制，之后沿用已确认的分工，不逐轮重复询问。讨论按当前安排发送对应问题；没有获准操作浏览器时，请用户手动转交。

仅在用户已授权主持人操作浏览器时，复用已登录的 Chrome 和对应聊天，采用后台操作，不抢占用户前台。先核对正确聊天、当前请求和已有记录，再发送完整问题。中断或回执不明时按实际页面证据恢复：

| 页面证据 | 处理 |
| --- | --- |
| 已出现本次问题或对应回答 | 视为已送达，记录真实结果，不重复发送。 |
| 已检查正确聊天且确认问题未出现 | 重新核对房间状态后，发送同一问题并确认页面结果。 |
| 页面、聊天归属或送达情况无法确认 | 保留结果不明并报告障碍，停止重发。 |

用户手动转交时，提供完整、可复制的问题，等待用户贴回网页专家的完整原文；不得把问题展示文本当作已送达。收到回答后核对它对应的仍有效请求，再使用主持人凭据以网页成员为作者提交，并关联请求，例如 `message post ROOM --as 主持人 --author 网页成员 --kind chat --request 请求编号 --body-file answer.md --submission-id 原编号`。保留原文、作者、引用与来源；主持人整理的摘要须标明由主持人撰写，不能把改写冒充专家原文。网页专家无法访问本地文件时，明确说明并按需提供获准的必要材料。

浏览器送达与网站写入分别核对。网站提交编号只能去重网站写入，不能证明浏览器消息已送达；原文代发失败或结果不明时，按参与技能先查询原 submission_id，再决定是否重试，并保持原编号和正文不变。
