# 名单变化与异常

专家名单变了，或讨论中有请求失败、成员卡住时读本页（任务的 `discussion_request.cause_kind` 为 `member_change` 或 `request_failed` 时任务会列入）。其余规则见 [讨论主持](host.md)。

## 名单变化

用户邀请、请回、暂离或移除专家后，以 `room view` 中最新的 `experts` 和 `queued_turns` 为准。

- 新邀请的专家：自动专家已追加到现有队列的末尾，手动专家注册后才加入；保留当前发言及原计划，不重排或重复安排。尚无安排时，把新专家放在本轮尚未发言的原专家之后。
- 暂离、移除或请回会作废原排队安排，再按最新名单重排。
- 新加入或请回的专家先补独立观点，再进入交锋；给它的题目写明本轮在讨论什么、要它回答什么和读哪些编号，不只写欢迎语。
- `members` 中 `session_mode` 为 `borrowed` 的专家续接用户已有的会话，带着自己的历史上下文：请它先说明哪些判断来自原有上下文，而不是把它当作从零开始的独立观点。

## 处理异常

任务有 `host_workflows: true` 时，讨论中出现的问题你自己处理，诊断与恢复的做法和边界见 [房间控制与恢复](../../discuss-host/references/control.md)；讨论里另有三点：换上来的专家按上文“名单变化”先补独立观点；调整本轮顺序用 `host-control order`，名单变化后按最新 `turn roster` 重排；暂停、继续或结束整场用 `host-control discussion`，目标提前完成仍按 [到限与收束](host-closing.md)。讨论的轮数、时长上限由用户设定，你不能调高；没有该字段时这些操作请用户在网页上做。
