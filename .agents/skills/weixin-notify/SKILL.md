# 微信通知

将简短通知或问题发送给本机扫码绑定的用户。入口是 AI CoDiscuss 项目根目录的 `weixin_bridge.mjs`，需要 Node.js 24+ 及支持 `codex queue` 的本机 Codex。先从当前项目或用户指定路径核实仓库根目录；下列命令均在该目录执行，从其他目录调用时改用已核实的绝对路径。`notify` 和 `ask` 都记住实际来源聊天，并确保同一个后台微信收件器运行；发送命令本身随即退出。用户可直接回复普通通知，无需预先把通知改成提问。回复由官方 `codex queue` 插入来源聊天，不要求聊天主动读取，不扫描历史，不使用全局 Hooks 或模型 API 中转。

## 聊天命名

聊天名称要让用户在微信通知和会话列表中辨认来源。按本聊天实际的项目、对象、问题或测试目的起简短、有辨识度的中文名称，不把“发送微信测试消息”“发个通知”等泛化动作当作多个窗口的共同标题。例如确实在做对应任务时，可用“微信回信路由核验”“新聊天创建验证”“会话列表排版”。

首次通知前，若当前自动标题未命名、过于泛化或已知与其他窗口重名，用桌面 `set_thread_title` 调整当前聊天标题，再使用这个实际名称发送。多个同类任务优先突出真实差异；确实没有内容差异时，补充简短、易记的区分词，避免继续同名，不虚构任务用途。用户明确指定的标题沿用；仅调整当前聊天，不批量改名其他窗口。`/new` 创建聊天时也遵循此规则，不仅在通知正文或 `--title` 中另造一个名称。

## 调用

用户要求“发到微信”“完成后微信通知我”，或本任务已有通知授权时，直接执行，不为每条通知重新确认。授权只覆盖约定任务及触发条件。需要未来定时唤醒时须另有调度机制，本技能本身不负责定时或监控其他聊天。

1. 首次使用时运行本地检查：

   ```powershell
   node weixin_bridge.mjs notify-status
   ```

   `configured` 表示存在本地凭据，`context_available` 表示有缓存的发送上下文；两者均不证明远端登录或令牌仍有效。凭据文件缺失或明确过期时，按下文登录。

2. 微信不能渲染 Markdown，正文使用纯文本、自然段和普通序号；不写粗体星号、Markdown 标题、表格或代码围栏。Emoji 仅用于标识来源或关键状态，保持专业克制；正文默认不用，确有必要时最多 1 个功能性符号，不使用卖萌表情、连续表情或装饰性点缀。程序自动添加来源图标，正文不重复手写来源头或叠加同义图标。链接直接写网址，代码保留原字符和换行。根据任务写结果或待决定问题，保持简短。程序会转换常见 Markdown，但不要依赖转换补救复杂排版。正文加来源头最多 3500 个 UTF-8 字节，不静默截断。

3. 用文件工具写入 UTF-8 临时文本文件，生成一次 UUID 作为 `message-id`。将本次编号和正文文件路径保留在调用上下文；然后执行：

   ```powershell
   node weixin_bridge.mjs notify --message-id '<本次UUID>' --text-file '<正文文件的绝对路径>'
   ```

   输入短而且能安全引用时也可使用 `--text`。不要拼接不受信任文本为 shell 命令。程序默认取 `CODEX_THREAD_ID`，只读查询该聊天的名称，自动加上 `💬 Codex（聊天名称）：`；不要在正文手写来源头或内部编号。已通过桌面工具核实名称时可传 `--title '<实际名称>'`，省去元数据查询。默认只发给扫码用户，无需别名或收件人参数。通知命令只处理这一个编号。

   首轮自动标题可能尚未生成。若程序提示当前聊天尚未命名，按上文“聊天命名”设置实际标题，再沿用同一编号和正文重试；或使用桌面工具已核实的实际标题。不要传“未命名聊天”或未保存的自拟名称来跳过检查。

4. 按 JSON 回执报告结果；需要再次核对时：

   ```powershell
   node weixin_bridge.mjs notify-status --message-id '<同一UUID>'
   ```

## 发问并把微信回复送回当前聊天

明确向用户提问时可使用 `ask`；普通通知继续使用 `notify`，两者都能把回复送回来源聊天。同样准备 UTF-8 正文文件及一次 UUID，然后执行：

```powershell
node weixin_bridge.mjs ask --message-id '<本次UUID>' --text-file '<正文文件绝对路径>'
```

命令默认读取当前进程的 `CODEX_THREAD_ID`，也可显式传 `--thread '<已确认的当前聊天UUID>'`；没有实际 UUID 时停止并报告，不能用选中的窗口或虚构编号代替。仅支持这台电脑的原 Codex 聊天，保持桌面应用运行。首次调用会隐藏启动一个微信收件器，后续调用复用；其他聊天无需手动绑定别名。

微信只显示 `💬 Codex（聊天名称）：` 和纯文本正文，程序在标题与正文间加空行，确保分开显示；不展示问题编号或聊天 ID。程序按微信服务器消息 ID 或完整引用正文查找来源，旧编号头仅用于兼容历史引用。普通回复回最近成功发出通知或问题的聊天，`notify` 和 `ask` 一视同仁；发送顺序按回执完成顺序记录，重复查询旧编号不改变目标。手动选定窗口后立即绑定，只要有 Codex 新消息成功发到微信，就自动改绑到该通知窗口；失败、不确定的发送和系统回执不覆盖已有选择。创建新聊天期间也遵循此规则，但已暂存消息仍交给对应新聊天，迟到登记不覆盖后来的通知绑定。引用消息仍可明确回到旧聊天，重名或不完整引用无法确定时不猜测。

发送后可结束本轮，等待 queue 输入；不循环调用 skill 读取消息。收到 `[微信] 请用 $weixin-notify 回复。`（旧消息可能为 `[微信用户回复；…]`）后，按空行后的正文继续当前任务，并通过 `notify` / `ask` 回复微信；无需复述来源提示或内部编号。微信文字不会自动点击工具审批按钮或提交结构化输入控件。

需要诊断收件器与最近投递状态时运行 `reply-status`；已保存但未投递为 `received`，官方 queue 受理为 `queued`，结果不明为 `uncertain`，未找到有效归属为 `ignored`。`queued` 不代表聊天已执行；已卸载聊天可能要在桌面打开后才处理。结果不明时不换号重投。收件器停止时可用 `listen-start` 恢复，或下次从聊天调用 `notify` / `ask` 自动启动；没有安装开机任务。

## 微信便捷命令

用户可在微信单独发送 `/help` 查看用法、`/status` 查看当前目标与投递状态。只需记住 `/resume`：不带参数查看会话列表，带序号切换，序号后还可附带消息。`/sessions` 与 `/rusume` 仍兼容为列表命令，不接受参数。每次列表从 1 连续编号，当前对话排首位，名称后加 `（当前绑定）`，每条用空行分隔；编号映射跨重启保持，新通知不改变映射，再次查询列表才刷新。列表后可单独发送数字，例如 `3`，直接绑定该次列表的第 3 项。选定窗口或发送普通正文、引用后结束选号，之后数字恢复为普通聊天内容；无效序号只提示，可继续选。名称取最近通知或登记记录，旧未命名条目省略；不展示内部目录编号或 UUID、不扫描桌面全部聊天。以上命令由收件器直接回复，统一以 `🔔 系统通知：` 开头；切换成功简写为 `已切换：序号 · 名称`，切换和清理正文不再添加成功图标，无需 Agent 执行或再发送一份回应。

支持 `/resume 序号 消息`，例如 `/resume 2 你是窗口几？`：切换成功后，只有序号后的正文经 queue 交给选中聊天；该聊天按普通微信来信处理并发送回答。省略正文时只切换，序号无效则不切换也不投递；重复来信不重复切换或发送。正文中的命令词不作为桥接命令再次解析。

`/clear` 仅清理旧对话列表并保留当前对话，不接受参数；不新建或删除实际 Codex 聊天，也不删除消息去重和引用关联。清理跨重启保持，并清除最近列表的编号映射，切换前需重新查看列表；对应窗口再次发出新通知后进入候选目录，下次列表重新编号。收件器直接处理，无需 Agent 执行。`/new [问题]` 专门用于新建聊天。

命令支持大小写，忽略前置空白后，只识别新正文开头。任何以 `/` 开头的输入都先经过命令校验；单独 `/`、未知命令和错误格式 / 参数直接提示，绝不回落到 AI 消息队列。普通正文和网址中间的 `/` 不受影响。`/resume` 不带参数只查看列表，带序号才改变后续普通消息的路由并接收可选的本次正文，普通引用仍回原聊天；切换前暂存的新聊天消息仍交给对应新聊天，迟到登记不覆盖新的手动选择。`/clear` 不取消新建请求或改变暂存消息归属。`/status` 只报告桥接状态，不代表 Codex 正在运行。

收件器兼容复制命令时附带在命令前或命令名后的 `U+200B` 零宽空格；普通正文和 `/new` 问题内容不被清洗。

## 处理 /new

用户在微信发送 `/new [问题]` 后，收件器先显示本机 Codex 项目列表，回复序号后才创建，`0` 表示无项目；附带问题保留为首条消息。项目编号与 `/resume` 会话编号分开保存，重启或项目排序变化不改已展示编号。未选定时的无效序号或普通文字只提示先选项目，不投给旧聊天。`/clear`、普通文字、引文或 `/newspaper` 均不创建聊天。

选择完成后，收件器直接调用桌面 `create_thread`：所选项目使用其 ID 与本地项目目录，`0` 使用 `projectless`；不创建 worktree、不指定模型、不复制旧历史。无需来源 AI 转发。再次 `/new` 替换尚未确认的选择；查看 `/resume` 会话列表或成功切换会结束待选项目，但已开始创建的请求及其暂存消息保留。所选项目已不可用时提示重新选择，不擅自换项目。

桌面未连接时保留请求，恢复后再尝试；创建已发出但结果不明时停止自动重建，新聊天自身登记可补全绑定。不要因等待而在来源聊天再建一份。内部编号不发给微信用户，也不因讨论此功能而自行新建聊天。

仅兼容升级前已经入队的 `[微信 /new 请求；内部编号：…]`：按以下旧请求恢复步骤执行，不在原聊天回答新问题：

1. 在来源聊天调用 `node weixin_bridge.mjs new-claim --request-id '<内部编号>'`。只有 `claimed: true` 才继续创建。已经 `creating` 表示先前创建结果需核查，不自动再创建；`completed` 使用已登记的聊天，不重复。
2. 使用桌面 `create_thread` 工具新建本机 `projectless` 聊天，`prompt` 原样使用上一步返回值，标题结合首条消息按“聊天命名”取有辨识度的中文名称。不要 fork、复制旧问答、指定其他模型或创建 worktree。返回的提示仅包含本次首条消息和微信接入说明，不包含旧聊天历史。
3. 工具成功后，立即调用 `new-complete --request-id '<同一内部编号>' --thread '<工具实际返回的新threadId>' --title '<实际中文标题>'`。创建结果不明时先核对，不再创建。期间没有后来的手动选择或通知绑定时，成功登记后普通微信消息切到新聊天；此前为该请求暂存的消息自动释放给新聊天。旧聊天无需再答新问题。

## 新聊天接入

新聊天首条提示会给出内部请求编号。先用本聊天的 `CODEX_THREAD_ID` 执行 `new-complete --request-id '<该编号>'`；它会读取真实聊天名称，重复登记同一聊天无副作用。若编号已对应其他聊天，停止并报告，不抢占路由。随后处理首条用户消息，并通过本技能把回答发回微信。用户只发 `/new`、没有问题时，发一句已就绪并等待。

此接入只配置微信路由，不读取来源聊天历史，也不更改工具审批策略。回复仍由桌面 Codex 实际执行；创建尚未完成时后续消息为 `waiting_new`，不会误投旧聊天。

## 回执与恢复

| 状态 | 处理 |
| --- | --- |
| `api_accepted` | 微信 API 已受理；不是手机已显示或用户已读。重复调用原编号不会再发送。 |
| `waiting_context` | 尚未发送。请用户在扫码连接的机器人聊天中发一条消息，然后执行下文 `sync`，再沿用原编号和原文调用。 |
| `pending` | 尚待发送；若 `last_error` 为 `iLink 拒绝（-14）`，重新扫码后沿用原编号。其他情况先看 `context_available`。 |
| `failed` | 微信明确拒绝；保留错误码并说明原因未知。`-2` 时可先刷新用户来信上下文，确认修复后用新编号进行一次新的发送；不要循环换号尝试。 |
| `uncertain` | 回执丢失或结果不明；停止发送并向用户报告。不要换编号重发，也不要删除记录。 |
| `not_found` | 此账号下没有该编号；核对原命令是否执行及是否使用同一组数据文件。 |

发送/同步命令退出码：`0` 为本次操作就绪或 API 受理，`2` 为等待、拒绝或不确定；`1` 为输入、配置或请求错误。`notify-status` 的 `0` 只代表本地查询成功，以 JSON 状态为准。进程意外退出时先查原编号；不要凭超时判断消息未发出。

同一编号只能配同一正文；问题编号还固定来源聊天。默认复用项目 `data/weixin-account.json` 与 `data/message-bridge.sqlite3`；不要因失败换数据库或打印其中 token。`notify` 不获取收件锁，可与后台收件同时发送。`listen`、`sync`、`login` 与旧 `run` 的收件互斥；遇锁时核对现有收件程序，不要为了普通发送停进程。旧 `coder_notifier` 不应与此收件器同时消费同一账号。

## 登录或刷新上下文

首次登录或明确的 `-14` 登录过期：运行 `node weixin_bridge.mjs login`，将返回的本地 `qr_path` 作为图片展示给用户。扫码后运行同一入口的 `login --complete`；需要手机验证码时附 `--verify-code`。只有 `connected` 表示登录确认；`waiting` 可继续完成同一次登录，二维码 `expired` 才重新申请。用户需要参与扫码时如实说明，不能假装完成。

用户向扫码连接的机器人发来消息后运行一次：

```powershell
node weixin_bridge.mjs sync
```

此命令仅在后台收件器未运行时使用，最多等一次 40 秒请求，只刷新上下文，不执行或保留正文。后台收件器运行时会自动刷新上下文并保存回复，无需 `sync`；用户发来新消息后沿用原编号和正文调用。`context_refreshed: true` 才表明一次同步取得了新上下文。

调用结束即结束本次技能工作。安装、数据与故障处理见项目根目录的 `docs/weixin.md`。
