# 自由协作房间

用于协作房间中没有 `discussion_request` 的自由协作请求。讨论仍使用 `mode: "free"`；有讨论请求时读 [讨论请求](discussion.md)。主持人另读 discuss-host 的自由协作一节。

## 回答请求

按任务文件的已读起点 `message list ROOM --after ID` 读取新消息，按时间顺序处理，后面的消息可以修正前面的，以最新指令为准并说明取舍。任务的 `request_messages` 可能指向已读起点之前的原回答，须用 `message view ROOM ID` 补读。

完成后用 `message post ROOM --as 本人 --kind chat --execution 执行编号 --access-file FILE` 提交一次回答。手动接入的成员没有执行编号：从 `room view` 的 `free.requests` 找到自己的待处理请求，回答时用 `--request 请求编号` 关闭。

任务需要多步操作时，在关键转折处（读完材料、改定方案、验证结果）用一两句中文写出进展，不另调命令：本机接入程序会把这些中途说明显示在网页的处理中卡片，让用户知道你在做什么。只写进展与判断，不复述工具输出，不写读技能、执行编号、提交命令之类的操作步骤（用户看不懂也用不上），不代替最终回答；几步就能答完的简单请求不写。

任务的请求带 `sequence` 时，你是主持人安排的依次接力中的一棒：`sequence.message_id` 是主持人的安排原文，`request_messages` 是上一棒的回答；按安排完成你这一棒，答完程序直接交给 `sequence.next`（没有则交回主持人），不要等别人或自己点名下一位。

## 主动发言

不是房间派来的任务、而是用户在你自己的窗口里要你在房间发言时（主持人另外可在需要主动说明、派活或补交失效执行的结果时自行使用），用 `message post ROOM --as 本人 --kind chat --proactive --access-file FILE` 提交（凭据用你最近一次任务的 access_file）。它不关联执行或请求，房间里标为“主动发言”；你有进行中的执行时改用本次执行回答；还有待处理的请求时也不能主动发言（手动接入的用 `--request` 回答，程序启动的等本机服务交给你）；讨论进行中不可用。普通成员的主动发言不能派活；主持人可以同时 `--to` 派活或 `--continue`，从这条消息起算一条新任务链，同样受轮数上限约束。

## 共享工作目录

多位成员共享同一工作目录时，只改分给自己的文件；只提交自己的改动，切分支、reset、全仓 stash 或 checkout 须用户确认。（目录不加锁，越界改动会覆盖别人的工作。）

## 提到其他成员

普通成员可在回答中用 `--to 显示名` 或正文 `@显示名` 提到他人，不能点名自己；这不会派发任务，也不会通知对方。显示名是 `room view` 中 `members[].label`（如 `Gemini`），正文称呼也用它，不写 `name`（成员 ID，如 `Antigravity`）。需要别人补充时，在回答里写明缺什么，由用户或主持人决定是否请对方处理。
