# 交付交互式可视化

只在你判断回答需要用户亲手操作（拖动参数看变化、点开分步讲解、可点的界面原型）时读本页。怎么设计页面由你决定；本页只写房间网页怎样显示它、给了页面什么、有哪些限制。

## 写法：正文里的 `visual` 代码块

在回答正文里写一个信息串恰好为 `visual` 的围栏代码块，内容是一份自包含的 HTML（完整文档或片段都行）。网页在代码块所在位置直接显示并运行它，外面由房间加一圈淡边框和少量内边距与正文区分，高度随内容；页面自己不要再画外框和底色；下方一行小字可收起、看源码、放大到预览窗口、在新标签页打开、下载。手机上同样就地显示。

````markdown
前面写引出它的话。

```visual
<div class="wrap">…</div>
<script>…</script>
```

后面写结论。
````

- 只有 `visual` 会显示；` ```html ` 等其他代码块照常显示源码，给人看代码时用它们。
- 一条回答可以有多个 `visual` 代码块，各自独立。
- 正文上限 32000 字，页面代码也算在内，单个页面建议不超过约 30000 字。更大的页面改为上传 `.html` 附件：附件只在文件卡片、预览窗口和新标签页里打开，不在消息内显示。
- 其他成员用 `message list` 读历史时，`visual` 代码块折叠成一行并注明字符数；要看源码用 `message view`。
- 用户自己的消息里的 `visual` 代码块只显示源码，不运行。

## 向用户收集选择

**问题卡能表达的都用问题卡**（见 [按需场景](situations.md)“向用户提问”）：单选、多选、逐条选一档、补一句说明，即使条目很多也一样，问题卡还能阻塞等待、答完交回提问者。只有问题卡做不到时才把可视化做成提问面板，限于三种情况：

1. 选项之间要联动计算：改一个值，结果、排名或总量当场变化，用户要看着结果做决定（如调权重看方案排名）。
2. 量是连续的：比例、权重、阈值、时间点。
3. 答案在图上：在平面图、时间轴、界面示意图上指出位置。

- 面板里放一个按钮，用户点击时调用 `window.codiscuss.submit(文字, 字段)`。文字是给人看的结论，逐项写全名和数值（如“排序：A、D、B；预算：A 50%、D 30%、B 20%”），不超过 2000 字；字段可选，是同样内容的结构化对象。
- 结果不会直接发出：房间把它作为引用放到用户输入框上方，用户看过、可以删改，点发送才算回答，发出的是用户本人的消息。同一面板再次提交会替换上一次的结果。引用里的 `@` 和 `/` 命令不生效，要交回给谁由用户决定。
- 先判断 `window.codiscuss?.submit` 是否存在：在新标签页、下载的文件、分享页里没有它，这时隐藏按钮或提示用户直接打字回答。
- 正文里同时写一句文字版的答法（如“也可以直接回复：按优先级列出 A 到 F”），面板用不了时用户照样能答。
- 优先用原生控件（滑块、复选框、下拉框）；拖拽只作增强，同时提供上移、下移按钮。
- 面板里的得分、估算由你给出时，写明依据，凭判断的标“假设”；交回的结论带上前提（如“在这组得分下选 A”），别让精确的数字显得比依据更可靠。

## 房间给页面的东西

房间往页面里注入一份基础样式和下面的变量。变量在页面载入后送到，用户切换深浅色时再送一次。

| 变量 | 含义 |
|---|---|
| `--codiscuss-text` | 正文色 |
| `--codiscuss-text-muted` | 次要文字 |
| `--codiscuss-text-hint` | 提示文字、刻度 |
| `--codiscuss-border` | 边框、分隔线、坐标轴 |
| `--codiscuss-accent` | 强调色 |
| `--codiscuss-card` | 卡片底色（控件底、需要与背景区分的色块） |
| `--codiscuss-font-family`、`--codiscuss-font-size` | 房间正文的字体与字号 |
| `--codiscuss-radius` | 圆角 |
| `--codiscuss-color-scheme` | `light` 或 `dark` |

已由房间设好、页面改不了的：`html` 和 `body` 透明底、外边距为 0；`body` 的文字颜色、字体、字号；深浅色。

已有默认外观、可以覆盖的：`button`、`select`、文本类 `input` 有边框、圆角、底色和内边距；滑块、复选框、单选框用强调色；键盘焦点有描边。

## 约束

- **不设页面底色，不设 `body` 字体和颜色**：设了也不生效。需要色块时用 `--codiscuss-card`。
- **颜色只用变量，并写兜底值**：如 `var(--codiscuss-accent, #2563eb)`。放大的预览窗口、手机全屏和新标签页也注入房间主题，兜底值用于变量到达前或下载后直接打开时。不写 `prefers-color-scheme`，深浅色由房间决定。
- **颜色写在 CSS 里**（SVG 用 `fill`、`stroke` 引用变量），不在脚本里读一次存起来：变量晚于页面脚本到达，切换主题时还会变。
- **不写固定高度**：房间测量 `body` 的实际高度来定显示高度，内容多高就显示多高，框内不出现滚动条。不用 `100vh`、`height: 100%` 撑满：框的高度就是量到的内容高度，撑满后不会再缩回去；页面很长时考虑拆成几块或用分步切换。
- **不写固定宽度**：显示宽度等于正文栏，随窗口变化；预览窗口更宽。内容设宽度上限并居中，窄到 320px 时仍能用。字号用 `em`，跟随房间字号。
- **没有网络**：外部脚本、样式、字体、图片和 `fetch` 都被拦截，CDN 上的库载不进来。CSS、JS、数据都写进代码块；图片用 data URL 或内联 SVG。
- **只能运行脚本**：`alert`、`confirm`、打开新窗口、提交表单都不可用。页面读不到房间、网站接口和 Cookie，`localStorage` 不可用（读写放进 `try`）。页面不能写回房间，也不能唤醒成员。
- **状态不会保存**：页面滚到附近才开始运行，之后一直保留；但收起、切换房间或刷新后会重新运行，用户调过的参数回到初始值。默认参数要能说明问题。
- **结论写在正文**：只读分享页、语音播报和消息折叠时的预览只显示“交互式可视化”一行，不运行页面。页面只承载可操作的部分，结论、关键数字、默认参数下看到的结果写在正文文字里。
- **自查**：交付前读一遍代码，确认没有引用本机路径、没有写入密钥。
