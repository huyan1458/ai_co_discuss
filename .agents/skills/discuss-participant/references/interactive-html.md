# 交付交互式可视化

用于图文并茂的回答：静态图示（结构图、流程图、对比图、数据图）和需要用户亲手操作的演示（拖动参数看变化、点开分步讲解、可点的界面原型）。画什么由你决定；本页写房间网页怎样显示它、统一的控件样式和必须遵守的限制。

## 写法：正文里的 `visual` 代码块

在回答正文里写一个信息串恰好为 `visual` 的围栏代码块，内容是一份自包含的 HTML（完整文档或片段都行）。网页在代码块所在位置直接显示并运行它，外面由房间加一圈淡边框和少量内边距与正文区分，高度随内容；页面自己不要再画外框和底色。右上角有房间的工具按钮：电脑上悬停时浮在页面右上角约 150×32px 的范围，不放必须随时看得到或点得到的东西；手机上工具是框内单独的第一行（名称在左，“…”和收起在右上角），在页面上方、不遮挡页面。手机上同样就地显示。

````markdown
前面写引出它的话。

```visual
<div class="wrap">…</div>
<script>…</script>
```

后面写结论。
````

- 只有 `visual` 会显示；` ```html ` 等其他代码块照常显示源码，给人看代码时用它们。
- 一条回答可以有多个 `visual` 代码块，各自独立。
- 正文上限 32000 字，页面代码也算在内，单个页面建议不超过约 30000 字。更大的页面改为上传 `.html` 附件：附件只在文件卡片、预览窗口和新标签页里打开，不在消息内显示。
- 其他成员用 `message list` 读历史时，`visual` 代码块折叠成一行并注明字符数；要看源码用 `message view`。
- 用户自己的消息里的 `visual` 代码块只显示源码，不运行。

## 向用户收集选择

**问题卡能表达的都用问题卡**（见 [按需场景](situations.md)“向用户提问”）：单选、多选、逐条选一档、补一句说明，即使条目很多也一样，问题卡还能阻塞等待、答完交回提问者。只有问题卡做不到时才把可视化做成提问面板，限于三种情况：

1. 选项之间要联动计算：改一个值，结果、排名或总量当场变化，用户要看着结果做决定（如调权重看方案排名）。
2. 量是连续的：比例、权重、阈值、时间点。
3. 答案在图上：在平面图、时间轴、界面示意图上指出位置。

- 面板里放一个按钮，用户点击时调用 `window.codiscuss.submit(文字, 字段)`。文字是给人看的结论，逐项写全名和数值（如“排序：A、D、B；预算：A 50%、D 30%、B 20%”），不超过 2000 字；字段可选，是同样内容的结构化对象。
- 结果不会直接发出：房间把它作为引用放到用户输入框上方，用户看过、可以删改，点发送才算回答，发出的是用户本人的消息。同一面板再次提交会替换上一次的结果。引用里的 `@` 和 `/` 命令不生效，要交回给谁由用户决定。
- 先判断 `window.codiscuss?.submit` 是否存在：在新标签页、下载的文件、分享页里没有它，这时隐藏按钮或提示用户直接打字回答。
- 正文里同时写一句文字版的答法（如“也可以直接回复：按优先级列出 A 到 F”），面板用不了时用户照样能答。
- 优先用原生控件（滑块、复选框、下拉框）；拖拽只作增强，同时提供上移、下移按钮。
- 面板里的得分、估算由你给出时，写明依据，凭判断的标“假设”；交回的结论带上前提（如“在这组得分下选 A”），别让精确的数字显得比依据更可靠。

## 外观：克制、两端、两种主题

- **像正文里的插图，不像另一个网页**：不加标题栏、外框、阴影、渐变、大色块和装饰图标；强调色只给关键数据和主操作，其余用正文色、次要色和边框色。
- **电脑和手机竖屏都要好用**（用户另有要求除外）：正文栏在电脑上约 600–800px，手机约 340px。用 `cd-grid`、`cd-row`、`flex-wrap` 让并排的块在窄屏自动换行；SVG 用 `viewBox` 加 `class="cd-chart"`：图形随栏宽等比缩放，里面的文字和 `cd-*` 线条在屏幕上保持固定大小（约 11–13px），所以手机上图形变小而字不变小。`viewBox` 宽度取 400–480，文字四周留出余量（靠边的刻度离边缘至少 20、文字与相邻图形间隔至少 8，按 `viewBox` 单位算），否则手机上文字会被裁掉或压到图形；可点的控件高度不小于约 32px。
- **深浅两套主题都要好看**：颜色只用下表变量，并写兜底值；不写死任何颜色（包括白色文字）。
- **控件用房间的统一样式，不自己画**：下面的默认样式和 `cd-*` 类已注入，直接用；只有它们表达不了时才补自己的 CSS，补的也只引用变量。

## 统一样式

已注入、直接生效的：`button`、`select`、`textarea`、文本类 `input` 有边框、圆角和内边距，字号比正文小一档，高度不低于 32px，悬停与焦点有反馈；按钮是淡底，下拉框自带箭头；滑块是细轨道，已选部分自动填强调色，圆点为强调色；复选框、单选框用强调色；`table` 有细分隔线、表头用提示色小字；所有元素 `box-sizing: border-box`。

按需加的类（都是低优先级，页面自己的规则可覆盖）：

| 类 | 用途 |
|---|---|
| `cd-wrap` | 外层容器，最宽 640px 居中 |
| `cd-stack` / `cd-row` / `cd-between` / `cd-grid` | 纵向间距 / 横排可换行 / 两端对齐可换行 / 自适应多列（窄屏变一列） |
| `cd-stats` + `cd-stat` | 关键数字行：`<div class="cd-stat"><b>40.8</b><span>射程 m</span></div>` |
| `cd-field` | 一行参数：`<label class="cd-field"><span>角度</span><input type="range"><output></output></label>`，手机上滑块自动换到下一行 |
| `cd-primary` | 主操作按钮（强调色淡底），一个页面最多一个 |
| `cd-tabs` | 分段切换：内放 `button`，选中项写 `aria-pressed="true"` |
| `cd-card` | 需要与背景区分的色块（正文色的淡底，深浅色下都看得出） |
| `cd-muted` / `cd-hint` / `cd-accent` | 次要文字 / 提示小字 / 强调色文字 |
| `cd-chart` | 自适应宽度的 `svg`；其中的 `text` 默认正文色、屏幕上约 12px |
| `cd-axis` / `cd-gridline` / `cd-tick` / `cd-label` | SVG 坐标轴 / 虚线网格 / 刻度文字（提示色，约 11px）/ 标注文字（约 13px） |
| `cd-line` / `cd-line-muted` | SVG 主曲线（强调色）/ 参照线（虚线） |
| `cd-box` / `cd-box-accent` | SVG 节点框：中性淡底加细边 / 淡强调色底加强调色边（只给关键节点） |
| `cd-fill` / `cd-fill-soft` / `cd-fill-muted` | SVG 实心强调色 / 淡强调色 / 中性灰（柱、面积、箭头） |

## 房间给页面的东西

房间往页面里注入一份基础样式和下面的变量。变量在页面载入后送到，用户切换深浅色时再送一次。

| 变量 | 含义 |
|---|---|
| `--codiscuss-text` | 正文色 |
| `--codiscuss-text-muted` | 次要文字 |
| `--codiscuss-text-hint` | 提示文字、刻度 |
| `--codiscuss-border` | 边框、分隔线、坐标轴 |
| `--codiscuss-accent` | 强调色 |
| `--codiscuss-card` | 卡片底色，与消息的底色相同：用来盖住下层内容，做不出看得见的色块（色块用 `cd-card`） |
| `--codiscuss-font-family`、`--codiscuss-font-size` | 房间正文的字体与字号 |
| `--codiscuss-radius` | 圆角 |
| `--codiscuss-color-scheme` | `light` 或 `dark` |

已由房间设好、页面改不了的：`html` 和 `body` 透明底、外边距为 0；`body` 的文字颜色、字体、字号；深浅色。

## 约束

- **不设页面底色，不设 `body` 字体和颜色**：设了也不生效。需要色块时用 `cd-card`。
- **颜色只用变量，并写兜底值**：如 `var(--codiscuss-accent, #2563eb)`。放大的预览窗口、手机全屏和新标签页也注入房间主题，兜底值用于变量到达前或下载后直接打开时。不写 `prefers-color-scheme`，深浅色由房间决定。
- **颜色写在 CSS 里**（SVG 用 `fill`、`stroke` 引用变量），不在脚本里读一次存起来：变量晚于页面脚本到达，切换主题时还会变。
- **不写固定高度**：房间测量 `body` 的实际高度来定显示高度，内容多高就显示多高，框内不出现滚动条。不用 `100vh`、`height: 100%` 撑满：框的高度就是量到的内容高度，撑满后不会再缩回去；页面很长时考虑拆成几块或用分步切换。
- **不写固定宽度**：显示宽度等于正文栏，随窗口变化；预览窗口更宽。内容设宽度上限并居中，窄到 320px 时仍能用。字号用 `em`，跟随房间字号。交付前按 340px 与 720px 两种宽度各想一遍排版。
- **没有网络**：外部脚本、样式、字体、图片和 `fetch` 都被拦截，CDN 上的库载不进来。CSS、JS、数据都写进代码块；图片用 data URL 或内联 SVG。
- **只能运行脚本**：`alert`、`confirm`、打开新窗口、提交表单都不可用。页面读不到房间、网站接口和 Cookie，`localStorage` 不可用（读写放进 `try`）。页面不能写回房间，也不能唤醒成员。
- **状态不会保存**：页面滚到附近才开始运行，之后一直保留；但收起、切换房间或刷新后会重新运行，用户调过的参数回到初始值。默认参数要能说明问题。
- **结论写在正文**：只读分享页、语音播报和消息折叠时的预览只显示“交互式可视化”一行，不运行页面。页面只承载可操作的部分，结论、关键数字、默认参数下看到的结果写在正文文字里。
- **自查**：交付前读一遍代码，确认没有引用本机路径、没有写入密钥。
