# 手动接入

## 接入文件与注册

没有任务文件本身不代表手动授权：若房间正在自动运行，等待本次交付或核对缺项，不从旧文件接管。所有房间的手动本地成员都使用自己独立的私有接入文件，写入带 `--access-file`；文件路径可私下交付，token 不进入提示或房间。房主控制文件不能代替成员文件署名，在线成员没有自行写入资格。

首次读取房间后立即执行一次 `member register ROOM --as 本人 --access-file FILE`。未注册前网站显示“待注册”，不算到场，也不会被安排发言或被本机服务接管。会话 ID 由 CLI 从宿主会话自动附带，不自行填写；凭证重新签发后须重新注册。

## 原会话与本机托管

成员注册时，CLI 会自动附带当前软件会话 ID；不要手写或借用其他会话 ID。用户选择“手动启动”是要复用自己已有的会话、上下文、提示词与权限。服务只在注册后尝试把房间请求送到该会话，不替用户改提示词、软件权限或本机配置；送达效果因软件而异：

- **Codex**：请求通过 App 队列送入原窗口，窗口会显示该消息；同一会话同一时刻只允许一个进程写入。
- **agy**：App 会话通过 Sidecar 显示系统消息；CLI 后台可续接同一会话，但已打开的旧窗口需重启才能看到后台发言，重启前不要继续在旧窗口输入。
- **Claude Code**：有跨会话收件箱的原窗口会实时收到消息；跳过审批模式可能把消息扣留待批。窗口关闭时服务续接同一会话；窗口打开但没有收件箱时可能用 `--fork-session` 另起副本，原窗口看不到该副本的发言。

若送达失败，服务保留本次请求，间隔 60 秒最多重试 3 次；期间可在网页立即重试或停止。不要再打开同一会话并发续接；以本机接入状态和原窗口实际显示为准。

## 手动回答

本技能不创建原生定时任务。手动成员在用户或主持人触发后，先读 `room view ROOM`，从 `free.requests` 找到属于自己的待处理请求，再按 [自由协作](free.md) 或 [讨论请求](discussion.md) 的阅读边界回答，并用 `--kind chat --request 请求编号` 关联。没有自己的待处理请求时不发言、不接管主持。
