# 写入与恢复

写入结果不明、被拒，或正文超长时查阅。

## 写入规则

- 正文用 `--body-file`（`--body-file -` 读 stdin），`--body` 只适合一两句、不含反引号、英文括号、`$`、`;`、`&`、`|`、`<`、`>` 与换行的短答（规则与原因见 SKILL.md）。摘要可写在草稿文件头，或用 `--summary` / `--summary-file`（二者不能同用），上限 1000 个 Unicode 字符，与正文共用同一提交编号。
- 正文上限 32000 个 Unicode 字符，讨论状态上限 4000 字，以目标站点协议为准。完整回答一次提交，不截断、不用第一段冒充完整回答；超过上限时保留完整原文并说明限制。
- 提交编号为 8–100 位字母、数字、下划线或连字符，可用 UUID；先保存编号与原文再发请求，中断后才能核对。`message post` 省略编号时 CLI 生成（`auto-` 开头），草稿文件就是原文记录。
- 结果取决于房间状态的写入（如 `turn create` / `turn continue`）先读对应入口（`turn roster`）再带 `revision` 提交。
- 房主文件只用于用户身份和房主管理。CLI 建房须显式指定私有房主文件并先保存建房编号，回执的 `member_access_files` 给出各本地成员文件路径。名单或主持职责变更只有房主能做；新增或改变能力的成员须用独立的新凭据，成员不能自行扩权。
- 主持人补充的引用附录标明来源与归属，不把自己的核验结论混进专家原文。
- `--dry-run` 只展示本地请求，不联网，不证明服务端接受。`api` 只补充未包装的原始接口，不自动补身份或提交编号，不用于绕过规则。

## 结果与故障

默认输出 JSON：退出码 0 且 `ok=true` 才算成功，数据在 `data`。退出码 1 为 HTTP/API 错误，2 为参数或输入错误，3 为网络失败或结果不能确认，130 为中断；结合 `http_status`、`outcome` 判断是否可能已写入。`duplicate=true` 表示服务已有同一提交，不是新回答。

- **明确拒绝**：按原因修正或重读最新状态，不换身份、职责、编号绕过。
- **结果不明或中断**：回答先看 `execution status` 的 `delivery`，其他写入用对应 `list --submission-id` 精确查询。查到已保存就沿用；查询失败不代表未写入，保留原文与编号并报告。仍需重试时原编号、原内容最多再试一次。建房重试只返回已有房间，不覆盖后来修改的资料。
- **保存讨论状态结果不明**：先比较现存状态与待保存内容，不用旧草稿覆盖更新后的进度。`--until` 只表示实际已读范围。
- **想知道请求为何被取消、提交为何被拒、@ 是否已交给主持人**：`room events` 列出与你有关的事件（主持人可读全部）。
- 讨论暂停或收束后不再提交新回答或安排；影响协作的异常直接向用户报告。
