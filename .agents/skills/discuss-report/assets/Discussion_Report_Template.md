# 讨论综合报告模板

让未参加讨论的人读懂问题、关键取舍、当前判断如何形成，以及仍不能确定什么，并能回到原文核对依据。

## 使用约定

- **必须覆盖**：下方“必要信息与事实边界”是内容要求，调整结构时仍须满足；验收按信息与依据，不按标题字面匹配。
- **默认沿用**：基本信息在前，随后交代问题、讨论概况、主题分析、结论与未决事项，来源索引在后，便于跨报告查阅。下方骨架是起点，可按内容合并、拆分、重命名或调整顺序；用户指定格式时优先沿用。
- **自主发挥**：主题划分、论证顺序、分析视角、篇幅及图表由材料与读者需要决定。可以提出有依据的新联系、解释或后续设想，明确标为报告作者分析并交代推导依据与不确定性，不冒充原有共识。例如，方案比较可关注收益与代价，创作讨论可关注人物动机与设定一致性；这些不是必设章节。

顶部 YAML 用于快速识别讨论、了解规模和判断成果状态，默认采用上方七项：日期、房间号与参与者说明身份；轮次和专家发言数合并为讨论规模；讨论状态与采纳状态分别说明进展和采用情况；报告更新标明整理时间。字段值保持简短，参与者尽量同行，本地文档省略不适用的字段，不为凑齐七项编造数据。

主题由标题表达。精确时间与时区、来源链接、消息和安排范围、报告作者、首次生成日期及版本依据放在文末来源说明；核验缺口在正文相关位置说明。必要但未知的信息如实标注；更新时保留首次生成日期，不将报告更新时间冒充讨论日期。成稿删除使用说明和占位符。

消息、发言、安排和完整轮次只统计声明范围，背景补读另列，不直接套用房间全量计数。讨论状态注明可确认的截止范围或读取时间，不用当前阶段反推历史阶段；跨日讨论写全起止日期，转换时间时标明所用时区。

## 必要信息与事实边界

| 信息 | 合格标准 |
| --- | --- |
| 报告身份与范围 | 主题、实际讨论时间、来源与截止范围、参与者及角色、报告作者与生成日期、用户采纳状态、材料覆盖与缺口可查。讨论时间与生成时间分开，作者、代发者、摘要作者不混淆。 |
| 背景与问题 | 说明讨论缘由、目标、约束和可调整的前提；每个核心问题有回答或明确列为未决，不补造材料没有的目标。 |
| 关键分析 | 解释实质性方案的理由、证据、反对意见及适用条件，保留影响判断的转折、修订、撤回及放弃替代方案的原因。不要求每条发言入正文，也不为凑章节重复结论。 |
| 当前结论与未决事项 | 区分共同方向、个人偏好、保留异议、作者分析与用户实际采纳。多数支持或未发现异议不等于全员认可；未确认不等于否决。撤回的主张不再作为当前依据，已解决的争议不继续列为未决。后续建议说明验证目的与判断依据，负责人、日期与承诺仅在来源明确时记录。 |
| 来源与归档 | 关键判断可定位到具体原文；来源索引对应实际副本，说明纳入/排除范围、背景补充、版本与重复材料。仅有摘要或无法访问的外部来源须注明，不因存在链接就称已核验或已归档。 |

必要信息缺失时写明“材料未提供”或“未核实”及其影响；不适用时简述原因，可合并说明，无需保留空章节。只有核对完整的选定范围后，才可写“在本次范围内未发现”。关键原文不足时，在开头标明“阶段报告”及缺口，禁止为补齐结构虚构事实、轮次、共识或决策。

## 默认报告骨架

先填写并保留顶部 YAML 元信息，再接以下正文。主题分析可展开为多个独立章节，简短讨论也可合并相关部分；标题应表达该报告的实际问题与洞察。

```markdown
# {{讨论主题}}讨论报告

## 背景与核心问题

{{为何讨论、目标与约束、需要回答的问题}}

## 讨论概览与关键转折

{{实际讨论方式及影响判断的变化}}

## {{体现核心洞察的分析主题}}

{{围绕实质问题解释方案、依据、取舍与条件；按需要展开更多主题}}

## 结论与未决方向

{{回应核心问题，说明结论边界、当前分歧、未决事项及后续建议}}

## 来源与归档说明

{{具体来源与本地副本的对应索引、范围及必要的版本说明}}
```
