# 通知渠道配置（notify-setup）

房间需要房主处理时（阻塞提问 3 分钟未答、Goal 待确认），本机服务经房主选定的渠道发提醒；房主在渠道里回复，即作答或作为发言发回对应房间。渠道列表里第一个启用的是“主要”渠道，发不出去再按顺序换下一个，每条提醒只发一次；所有已绑定渠道都保持收件。

## 边界

- **凭据只经本机**：Bot Token、App Secret、OneBot 令牌只填进本机网页“设置 → 通知”，或用户在自己窗口里给出后由你写入临时文件、调用命令、立即删除。不写进房间消息、仓库、草稿或日志，不在回答里复述。
- **不替用户操作平台账号**：注册、建机器人、开权限、扫码登录都由用户在平台上完成；你给出步骤、核对结果。
- **不改别人的服务**：要复用其他机器上已在运行的 OneBot（如服务器上的 SnowLuma），先说明会影响谁，停用其他程序对它的连接须用户明确同意。
- **只做通知**：渠道目前只处理房主的私聊；群聊与在渠道里操作房间属于后续的网关功能，不承诺。

## 命令

网页之外的统一入口是 `codiscuss launch notify --file FILE`（FILE 为 UTF-8 JSON；可经已配对电脑转交）：

| 目的 | JSON |
| --- | --- |
| 列出全部渠道的状态、顺序、需填字段 | `{}` |
| 看一个渠道 | `{"channel":"telegram"}` |
| 保存凭据并生成 10 分钟绑定码 | `{"channel":"telegram","action":"configure","values":{"token":"…"}}` |
| 发一条测试通知 | `{"channel":"telegram","action":"test"}` |
| 解除绑定 | `{"channel":"telegram","action":"unbind"}` |
| 设顺序与启用 | `{"action":"arrange","order":["onebot","weixin",…],"enabled":["onebot","weixin"]}` |

渠道编号：`weixin`、`telegram`、`discord`、`qq`（官方机器人）、`onebot`（QQ 个人号）、`feishu`。各渠道 `values` 的字段名以 `{}` 返回的 `fields` 为准。微信不走 `configure`，用网页扫码，或 `launch weixin` 的 `login` / `complete`。

## 流程

1. **读现状**：运行 `{}`，记下每个渠道的 `bound`（已存凭据）、`owner_bound`（已认出房主）、`ready`（能发送）、`enabled`、`primary`、`last_failure`。
2. **选渠道**：按用户常用的软件推荐，并讲清前提，让用户选：
   - 微信：个人微信扫码即可；iLink 要求房主隔一段时间给机器人发过消息才能主动推送，久未互动会被拒（-2），发一句即恢复。
   - Telegram：最省事，BotFather 建机器人即可，可随时主动推送。
   - Discord：要有一个自己管理的服务器来装机器人。
   - 飞书：要建企业自建应用（个人可免费建组织），开权限、选长连接。
   - QQ 官方机器人：个人账号能否主动推送取决于平台权限，以测试为准。
   - QQ 个人号（OneBot）：用一个 QQ 小号当机器人，能随时私聊你；要另外运行 NapCat 等程序，非官方协议，有登录失效与封号风险。选它时读 [references/onebot.md](references/onebot.md)。
3. **建机器人**：按 [references/channels.md](references/channels.md) 对应小节带用户在平台上操作，拿到凭据。
4. **填凭据**：优先请用户在“设置 → 通知”对应一栏填写并点“保存并验证”；用户在自己窗口里把凭据给你时，再用 `configure`（临时文件放草稿目录，调用后立即删除）。验证失败时按错误信息回到第 3 步，不反复重试同一凭据。
5. **绑定房主**：页面或命令结果给出 9 位绑定码（10 分钟有效）。请用户**用自己的账号**在该平台私聊机器人，只发这串数字。之后运行 `{"channel":…}` 确认 `owner_bound: true`；过期就重新 `configure`。第一个发对码的账号会被记为房主，提醒用户不要把码发到群里或转给别人。
6. **测试**：`test` 后请用户确认手机上真的收到。只看命令成功不算送达。
7. **排顺序**：问用户哪个当主要渠道、哪些作备用，用 `arrange` 保存（或请用户在设置的渠道列表里勾选、上下移动）。
8. **汇报**：每个渠道的状态、主要渠道与回退顺序、未完成项。不复述任何凭据。

## 排查

- 先看 `last_failure`（`message`、`code`、`detail` 是平台原始错误），再对照 [references/channels.md](references/channels.md) 该渠道的“常见失败”。
- `bound` 但 `ready` 为假：大多是还没发绑定码（机器人渠道）或久未给机器人发消息（微信）。
- 收不到回复：确认用户是在**私聊**里回复、用的是绑定时那个账号；引用某条通知回复会回到那条通知的房间，不引用则落到最近一条通知的房间。
- 保存凭据后渠道会自动开始收消息，不需要重启；`{}` 里没有某个渠道，说明本机服务还是旧版本，请用户更新后重启本机服务。
