# 房间图文分享素材

从用户给的侧重点做出一套可直接发布的**图文分享素材**（封面图 PNG + 配套社交文案）。示例：`$share-card 为 <房间链接> 做分享卡，重点展示最终产品。` 在目标房间内说“重点展示最终产品”即可。

1. **找到房间。** 优先用本次消息或上下文里明确指定的房间。链接取查询参数 `room`，ID 可直接用，只有房间名时用 `codiscuss room list` 匹配；重名且无法确定时再问。没有指定其他房间时用当前任务绑定的房间。跨房间只读同一站点的素材，保留当前任务凭据。
2. **按主题取材。** 运行 `codiscuss share-card materials [房间ID]`，同站点完整链接可用 `--site <链接的源站>` 核对。侧重产品就先看真实成品图、`materials.sites`（已上线产品/官网链接）和交付结果，侧重协作就看并发曲线和执行统计，侧重讨论就提炼分歧和结论；同时查看 `materials.share_link` 获取当前房间的公开分享链接。根据 `scope` 标明部分统计，省略无法核实的内容。数字、操作步骤、文件路径由你处理。
3. **制作并检查封面 PNG。** 在自己的草稿目录写 750 CSS 像素宽的静态 HTML，图片用本地素材，图表可用内联 SVG。运行 `codiscuss share-card render cover.html --out cover.png`，检查成图清晰且内容完整。二维码、域名和到期时间由分享面板追加。
4. **撰写小红书/社交平台级配套文案。** 按[制卡与文案参考](references/share-card.md)在回答正文里附上 ```` ```share-copy ```` 代码块：吸睛短标题（≤20 字）+ 有画面感与真实数据的分段正文 + 已上线产品链接（来自 `materials.sites`）+ 完整协作记录链接（`materials.share_link.url` 存在时直接填入，未发布时写 `{{share_url}}` 占位）+ 3–5 个话题标签。文案面向外部读者，不出现内部汇报口吻、密钥、联系方式或本机路径。
5. **同条消息图文交付。** 在房间任务中用 `codiscuss attachment upload --file <PNG路径>` 上传至接单房间，再用 `message post --attachment <返回的附件ID>` 提交包含 ```` ```share-copy ```` 代码块的回答。同房间用户在“已分享 → 查看分享卡 → 选择房间图片”里点选带“含文案”标记的封面图，分享面板会自动载入这段配套文案并将 `{{share_url}}` 替换为真实链接；跨房间时说明下载 PNG 到目标房间“上传封面”，并复制文案粘贴到“分享文案”框（`{{share_url}}` 同样会自动替换）。终端里直接交付可打开的文件路径与文案。

若本机安装版尚无 `share-card` 子命令，使用可访问的共议源码入口 `node "<仓库>/runner/codiscuss.mjs" share-card ...`。开发机可在 `~/.codiscuss/share-card-cli.txt` 指定该入口的绝对路径。普通房间和附件命令仍用任务指定的 CLI。
