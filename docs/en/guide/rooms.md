# Rooms, Folders, and Creating a Room

Organize rooms and folders in the sidebar, configure room creation, manage project directories and files, send attachments, and export, import, or branch rooms.

## Steps

### 1. Create a room and choose its settings

In the sidebar, select “New room”. To create one inside a folder, select the “+” beside that folder. The form has three sections:

1. **“What to do”**
   - Enter a name in “Topic”.
   - Optionally choose a folder under “Project folder (optional)”. If you do not, the service creates a dedicated folder in the draft workspace (by default, `~/.codiscuss-workspace`). After choosing a primary directory, select “Add another project folder” to add up to eight more.
2. **“Who takes part”**
   - Select “Add AI” to add members. Select the crown on a member card to make it the host.
   - Optionally configure “Smart scheduling”, “Image generation” (add an OpenAI Images card and enter an endpoint, API key, and image model; the lightning button on the back of the card checks the endpoint, key, and model without generating an image or incurring charges), and “Web search” (enter a DeepSeek API key shared across rooms).
3. **“How to work (optional)”**
   - Under “After creation”, choose “Off”, “Start discussion”, or “Start Goal”.
4. **“Advanced settings”**: optionally enable “Full host control”, which lets the host manage members, retry or interrupt work, start discussions and Goals, and save workflows (to allow only part of it, expand “Items” and tick just the ones you need); set the “Assignment round limit” (10 by default, from 1 to 100 or unlimited) “API request limit”, and “Auto-destroy” (see below).
5. Select “Create and connect”, “Create room” for an all-manual setup, “Create and start discussion”, or “Create and start Goal”, as applicable.

Room name, project directory, and members are chosen for each room. Smart scheduling, collaboration settings, discussion and Goal limits, and continuous host-turn limits remember the last selection, even if you cancel room creation. If startup fails, a failed item remains in the sidebar. Select “Retry” in its menu to continue the same request without creating a duplicate room.

You can also send a message from the blank home page to create a room and send its first task. The web app picks the first configured AI that it can wake automatically as the room’s only member and host. The first line of your message becomes the room name. If you attach files without text, the first filename is used. The new room inherits the folder’s default project directory when one is set; otherwise it uses the draft workspace.

### 2. Organize the sidebar, folders, and archives

Rooms created by a host inherit its folder. Select the arrow to the left of the parent title to show or hide its children. Opening a child, starting work in it, or adding a child expands the parent. Manually collapsing it keeps it folded for this page session. Moving a child to another folder, archiving its parent, or deleting its parent lists the child independently.

- **Sort rooms.** Open the directory options in the top-right corner. Choose “Manual order” (drag items or use the arrow keys) or “Recent activity”. Existing rooms reorder when the pointer and keyboard focus are both outside the directory. New rooms still appear at the top of their group immediately.
- On desktop, room tabs leave the center width unchanged while the right panel is open. During an active or paused discussion, select “Host brief” to read it without moving the room content.
- **Folders.** Select “New folder” to group rooms by project. A folder can have a default project directory, which is used for new rooms created inside it. Its menu offers “Edit”, “Move up”, “Move down”, “Archive folder”, and “Remove folder”. You can remove just the folder or delete its rooms as well.
- **Child rooms.** A room the host creates stays in the current folder, nested under its parent room. Select the arrow left of the parent’s title to expand or collapse it. A child room moved to another folder, or whose parent is archived or destroyed, is listed on its own. To keep a child room in the same folder but list it like an ordinary room, open its menu and select “Make standalone room”. The link between the two rooms is kept, and “Nest under parent room” puts it back.
- **Room actions.** Open a room’s menu to “Rename”, “Share” (with “Share room”, “Copy share link”, “Revoke share link”, and “Export conversation”), “Move to folder”, “Pin room”, “Archive room”, or “Destroy room”. To reorder rooms, drag the handle on the left of a room. On a phone, selecting “Archive room” closes the menu and keeps the sidebar open. Continue organizing rooms or tap “Undo” in the notification. “Rename” turns the name into a text box in place: press Enter or click elsewhere to save, or Esc to cancel. On desktop, you can also double-click a room name in the sidebar. Use the panel icon at the right of the header to open or close the room panel.
- **Pin a room.** Select “Pin room” in the room’s menu. A pin appears after its name and message count; it keeps its place (it is not moved to the top). A pinned room cannot be archived or destroyed, is never auto-destroyed, and is skipped by “Archive folder”. Select “Unpin” to undo.
- Video attachments use the current theme’s background while loading. The preview appears as soon as the first frame is ready.
- When you return to a recent room, the speaking order shows the last known model and reasoning effort immediately. These update when the roster or executions change.
- In an existing room’s collaboration settings, the smart scheduling row keeps its height when toggled. After enabling it, select “Settings” to configure the decision model.
- **Destroy a room.** Select “Destroy room” in the room’s menu. The dialog lists what is deleted and what is kept. You can first select “Export package” to download a copy with messages, private chats, attachments, a “讨论记录.html” page that opens with a double click, and the files members wrote in their draft folders (in “草稿”; beyond 50 MB only their names are listed). After “Destroy now” and then “Destroy” in “Confirm destroying again” (every way of destroying asks twice), the room’s records, attachments, the AI sessions its members started in this room, and its run files and drafts are deleted from this computer: the room dissolves into particles at once (its sidebar row, and the middle pane when it is open) while deletion and checks go on in the background; a notice shows what was removed when they finish. The draft folder made when the room was created (under “Drafts” in “Project”) is deleted with its files too; the package keeps them in “草稿空间”. A project folder you chose is not deleted. Sessions taken over from your own windows or shared with other rooms are kept. Content already sent to model providers stays under their policies and cannot be deleted from here. A published share page is taken down first. If an item cannot be removed yet, a notice says so and you can follow and retry it in “Destruction records”. Files in members’ draft folders are deleted with the room; export the package first if you need them.
- **Destruction records and destroying all rooms.** Open “…” at the top right of the room list and select “Destruction records” to see what each destruction deleted and kept (the room name is cleared once it finishes). Select “Retry” on an unfinished one. “Destroy all rooms” at the bottom asks you to type a confirmation word, then destroys every room, archived ones included, one by one; project files are kept. A hosted account running as its own Windows user then also deletes every conversation in its AI software and the preferences the AI remembered, keeping logins. “Export all rooms” leaves drafts out; export rooms one at a time to include them.
- **Ratings after destruction.** Personal sites retain rated assignments, nearby messages, and final execution outcomes for later review. Hosted accounts delete these records with the room.
- **Auto-destroy.** Choose it under “Advanced settings” when creating a room, or later in the “Room” tab at the top of the room, set “Auto-destroy” to 1, 7, or 30 days (the room is destroyed after that many days without activity); the time left is shown beside it. The count starts when you set it and restarts with each new message or private chat. Archived rooms, rooms with members at work or queued work, an open question for you, or a published share page are not destroyed automatically. The page warns once when less than a day is left, and again after a room is destroyed. The default is “Keep”.
- **Restore or clear archived rooms.** Open “Archived”. Filter by keyword or whether rooms contain messages. Select “Restore” to return a room to the active list. To destroy one permanently, select “Destroy room” and confirm twice. “Destroy all” applies to the current filtered results and opens a standalone “Destroy archived rooms” dialog listing what is deleted and kept (with an “Export package” option), requiring “Destroy now” followed by “Confirm destroying again”.

### 3. Set project directories and browse project files

When viewing a project image through the relay on another device, supported images open as a “Reduced preview”. Choose “View original” for full detail (under file actions on narrow screens). Save downloads the original file. The local computer displays the original directly, as do other devices when a smaller preview cannot be generated.

“File changes” below an answer shows the number of changed files and lines added or removed. Lists of five files or fewer open by default. Select the file count to open a longer list. Read-only visitors can see the list, but only the room owner can view patches.

- **Add or remove directories.** A room supports one primary directory and up to eight additional directories. After creating a room, open the “Room” tab at the top of the room and find “Project folder”. Add or remove additional directories there. Changes apply from each member’s next run and do not interrupt a session. A primary directory cannot be changed after it is set. If the room was created without one, you can set it once in the same section. Members can access all room directories subject to their individual project permissions. A Claude Code member also loads the MCP tools (such as SSH) configured in the `.mcp.json` of an additional directory it can write to; read-only directories are not loaded.
- **Open Files.** In the tabs at the top of the room, select “Files” to browse directories, file sizes, and modification times. Switch between the primary and additional directories at the top. A project directory is required. The back and forward buttons at the left of the path bar move between the places you visited (folders, the project list, the recycle bin); on a computer, the mouse side buttons do the same. Phones show only the back button. On a phone you can also swipe anywhere on the page: swipe right to go back and left to go forward. In a file preview, swiping right closes the file and returns to its folder; while you swipe, a “Collapse” corner appears at the bottom right, and letting go there collapses the preview just like the collapse button or pulling it down, with the file kept open (swiping left does nothing there; image and media previews keep their own gestures). The “Icon view” button at the top right lays the folder out as tiles, with thumbnails for PNG, JPG, and WebP images; “List view” switches back. Thumbnails are made by the computer and currently only on Windows; other images and files show their icons.
- **Preview files.** Select a file to open its floating preview. Supported previews include plain text, code, rendered Markdown, static HTML with a source view, zoomable and rotatable images, audio and video with speed and full-screen controls, CSV tables, subtitle timelines (SRT, VTT, ASS, LRC), read-only Word, Excel, PowerPoint and PDF, Premiere project XML, and zip archives listed like a folder, where selecting a file inside opens it in a new tab. Images in Markdown display inline the way message images do; select one to zoom. Paths are accepted as common editors accept them: relative paths, project paths starting with `/`, absolute paths inside the room's project directories (such as `D:\Project\art\a.png` or `file:///D:/Project/art/a.png`), and web addresses. Files outside the room's project directories are not read. Images load as you scroll near them; landscape images fill the width and portrait images fit the window height. Other devices get a copy the computer compressed. Opening a ZIP attachment or project file loads the directory first. Select an entry to read it (up to 64 MiB), or choose “Download” to save the archive.
- **Save to cloud space.** With the cloud space set up, the menu of a file or folder has “Save to cloud space”. A file is copied as it is; a folder is packed into one ZIP first, up to 2 GiB. Progress shows above the list and a notice appears when it is done. The original in the project stays.
- **Upload large files into a project.** With the cloud space set up, a file uploaded in Files that is over the attachment limit (up to 2 GiB) first travels through the cloud space, then this computer downloads it into the current folder and the transfer copy is deleted. Progress shows above the list, and you can cancel with “×” until it reaches the cloud space. A file with the same name keeps both copies by default. Without the cloud space, files over the limit cannot be uploaded.
- **Download large files from elsewhere.** With the cloud space set up and the page not opened on this computer, downloading a file larger than the threshold, or a folder, first has the computer put it into the cloud space (a folder packed as a ZIP). Preparation progress shows above the list, then the browser downloads it straight from the storage, not through the relay. Downloading the same version again reuses one copy, deleted after 24 hours; after the file changes, a new copy is made. The project file cards that members deliver in messages also have “Download”, with the same rules.
- **Cloud space.** With the cloud space set up and you as the account's administrator (on this computer, or signed in), the last of the directory tabs is “Cloud space” (the row of tabs shows even when the room has a single project directory). It uses the same page as a project directory: the same upload, new folder, view and “More actions” icons at the top right, and the same back, forward, path and “Name, Size, Modified” columns below, with a “…” menu on each row. One for the whole account, the same from any room:
  - **Path bar:** shows “Cloud space › folder › …”; at its right end are the search box (by name across the whole cloud space) and the space used and quota.
  - **Folders:** create, rename and move folders (up to 10 levels; no two folders with the same name in one place). First come two folders marked “Read-only”: “Room attachments” holds large attachments sent with messages, and “Transfer copies” holds temporary copies for transfers away from the computer (cleared after 24 hours, hidden while empty). They cannot be renamed or moved.
  - **Upload:** select the upload icon at the top right and choose “Upload files” or “Upload folder”, or drag files and folders onto the list. An uploaded folder keeps its structure, and a folder with the same name is merged. Each file can be up to 2 GiB; empty files and system files such as `.DS_Store` are skipped; at most 2000 files at a time; nothing starts if the space left is not enough. Images and videos get thumbnails.
  - **“…” menu:** Download, Rename, Move, Delete, Share, Bring into project. Files in the read-only folders cannot be renamed or moved; transfer copies can only be downloaded or deleted. Selecting a file name previews images, audio, video and PDF, and downloads anything else. The same switch changes between list and grid.
  - **Recycle bin:** under “More actions”, where projects have their recycle area. Deleted files and folders go to the recycle bin for 30 days: restore them (to the top if their folder is gone), delete them permanently, or choose “Empty recycle bin” under “More actions”. Files in the bin still use space. Room attachments and transfer copies are deleted at once, without the bin.
  - **Share:** “Share” in the “…” menu creates a share link valid for 1 to 30 days (7 by default). Tick “Require an access code” to make visitors enter a 4-character code; five wrong codes in a row lock the link for 10 minutes. The link and code are shown only once, with “Copy link and access code”; links can be revoked. Share links open through your hosted entry or online site and are checked by this computer, so they do not open while it is offline.
  - **Bring into project:** “Bring into project” in the “…” menu; open the folder to put it in, then select “Put here”.
  - **Transfers:** click “Transfers” above the file list to open a popover showing progress for uploads, copies to the cloud space, files brought into projects, download preparation, and permanent deletions. You can cancel running transfers, retry failed ones, and clear finished ones. The “Files” tab shows how many are running. After a reload, tasks the computer or site runs in the background keep showing progress, while uploads made by the browser show “Interrupted; choose the file again”. Leaving the page during an upload asks first.
- **Tabs, split view, and collapse.** Open multiple files and switch between tabs. Use the preview controls to split the view on the right or use “File location” to return to the containing folder. HTML previews also offer “Open in new tab”. Select “Collapse” in the title bar to keep the preview as a floating button in the corner. It restores the same file and scroll position when you return to the room. Close it to clear the preview.
- **Quote and annotate.** Select text in a Markdown preview or a member’s answer and choose “Add to conversation”. Enter a note and press Enter. The source is marked with a number and the composer shows the number of notes. On a computer, open the notes list, choose “Edit annotation”, and drag the bottom-right corner of the editor to resize it. Sending the message adds a file path and line number, the member and message ID, or for a message attachment its message ID and attachment ID. An `@` inside a quote does not wake a member.
- **Manage project files.** Select “Project” at the start of the path bar to open your projects and drafts. Use the top controls to create folders and upload files (subject to the administrator’s limit, 50 MiB by default). File menus offer “Download” (“Download folder” for a folder, packed as a ZIP), “Rename”, “Copy”, “Cut”, and “Delete”. Paste into the destination folder. Deleted files and replaced versions go to “Recycle bin” for 30 days, where they can be restored (“More actions” → “Recycle bin” at the top right; “Refresh” is there too, though the list refreshes itself). In source view, the pencil button edits text files up to 1 MB. Project and draft roots, and folders currently used as room project directories, cannot be renamed, moved, or deleted.
- **Select several items.** In a project folder and in the cloud space, every row has a checkbox at its left (at the top left of a tile in icon view); the checkbox in the column header selects everything in the current folder. While anything is selected, the path bar is replaced by an action bar: “N selected” on the left and, on the right, “Download”, “Move”, “Delete”, and “Exit selection” (in the cloud recycle bin: “Restore”, “Move”, “Delete permanently”, and “Exit selection”). Buttons that do not apply are greyed out, and hovering explains why: for example, folders cannot be downloaded in a batch, at most 20 files can be downloaded at a time, and files in the cloud space’s room attachments and transfer copies cannot be moved. Files download one at a time, and away from the computer large files still go through the cloud space. In a project, “Move” cuts the items for “Paste” in the target folder; in the cloud space, it opens the folder picker. Items deleted in a project go to the recycle area; the cloud space follows the same rules as deleting one item. Batch downloads and deletions show their progress in the transfer list; if some items fail, a notice at the bottom right lists them, and the items already done stay done. Changing folders or tabs clears the selection. Read-only folders, the project list, and the recycle area cannot be selected from.

### 4. Send and view attachments

- **Attach files.** Paste or drag files into the composer, or use the paperclip button at the bottom-left. Each message can contain up to 10 files, with a configurable per-file limit of 50 MiB by default. Thumbnails appear above the composer. A placeholder such as `[Image #1]` or `[File #2]` is inserted at the cursor. Removing the thumbnail or deleting its placeholder with Backspace removes both. After sending, images first referenced in a paragraph or list item appear right below it in a two-column half-width grid (full width for a single image on phones, two columns for multiple, with `#n` badges when a message carries more than one image) and are not listed again below; other attachments stay listed under the message. Windows sites automatically generate smaller previews for eligible PNG uploads. Open the image to view the original. The site automatically clears uploads left unsent for more than 24 hours. Attachments in sent or queued messages are kept.
- **Large files go to the cloud space.** When an administrator has set up the cloud space (see [Management panel](admin.md)), files larger than the threshold (20 MiB by default, up to 2 GiB each) upload straight to the account's cloud space. Upload progress shows under the thumbnail; removing the thumbnail cancels the upload. Their cards say “Cloud space · size”, and also “deleted automatically in N days” when the account turned on automatic deletion; download anything you want to keep within that time. Messages do not load their thumbnails or players; the card's icons are “Preview” (images, audio, video and PDF), “Download” and “Bring into project”. A preview reads straight from the cloud space: video can be dragged to any point, and when the link expires during a long stop it renews itself and carries on from the same place; a PDF opens in a new tab. “Bring into project” switches to Files: open the folder to put it in and select “Put here”, and the file is downloaded into the project on this computer while the cloud copy stays. When the page is opened on this computer itself, files within the attachment limit are always kept on the computer as ordinary attachments, and only larger ones go to the cloud space. When the cloud space cannot be reached or the file was deleted, the card shows “Object storage is unavailable right now” or “Deleted from cloud space”. Once the cloud space is full, new large uploads fail; delete old files under “Cloud space” on the Files page. Editing, taking back, or taking a queued message back into the composer leaves these files out; add them again. Share pages and exported backups do not include these files. Without the cloud space, files over the attachment limit cannot be added.
- **View attachments.** After sending a message, select its placeholder or attachment card. Images can be enlarged full-screen, zoomed, rotated, and saved; when the room has several images, the side buttons, the left and right arrow keys, or a sideways swipe on a phone step between them (the side buttons hide when idle and return when you move the mouse or tap the image). Audio and video play in the message. Documents and code open in the file preview. Every attachment card has a row of icons on its right: “Preview” (for files the page can show), “Download”, and, with the cloud space set up, “Save to cloud space” (the cloud icon). On an image the icons appear at its top right when you point at it, and always on phones; for audio and video they sit beside the file name. “Save to cloud space” copies the attachment into the account's cloud space and keeps the original on the computer, for files you want to take from elsewhere or keep long term. Attachments already in the cloud space do not show this icon.
- **Interactive visualizations.** A member can place a small web page you can operate (drag a slider, press a button, watch the result change) inside the answer text. It appears at that point in the answer, follows the room theme and light or dark mode, and also appears in place on a phone. It starts running when you scroll near it. On a computer, tool buttons appear in its top-right corner when you point at it: view the “Source”, “Open larger preview” in the file preview, open it in a “New tab”, “Download” it as an `.html` file, or “Collapse” it (your choice is remembered). On a phone the corner always shows a “…” menu and the collapse button. A collapsed visualization shows as one “Interactive visualization” line; select “Expand” to bring it back. Members add these on their own when you ask for an illustrated answer, or when they explain a structure, process, or data. When a long answer is folded, its visualizations still appear, and one the fold cuts through shows only its top; select “Show full text” to see all of it. Read-only share pages and read-aloud show a single “Interactive visualization” line instead, so rely on the member's written conclusion. `.html` attachments do not run inside messages; select the file card to open them in the preview or a new tab. Some visualizations are question panels: after you rank, allocate, or adjust and press the panel's submit button, the result is added above the message box as a quote rather than sent. You can edit or remove it, and it counts as your reply only when you send it. Submitting the same panel again replaces its earlier result.
- **Member access to attachments.** For supported automatic runs, the local service downloads the file and passes its information to the receiving member. Claude Code and Codex CLI can view images directly. For API members, enable “Images” on the member card to view images. UTF-8 text attachments can be read on request. Members will say when they cannot read a format such as PDF. Attachments in object storage are not downloaded automatically: the task lists their name, size and download command, and members download them when needed. External members cannot download room attachments.

### 5. Export, import, and branch rooms

- **Export a backup.** A room’s “Export conversation” menu item creates a ZIP containing the room’s messages, discussion history, and attachments. Use a folder menu to “Export folder”, or directory options to “Export all rooms”. Export on the computer running the local service. The archive includes member software settings and session identifiers. Backups also include dispatch ratings and notes, which are restored on import. The original software’s session history must still be present on that computer to resume a session.
- **Share as a web page.** In a room’s menu, select “Share”. Preparation runs in the background while you chat or switch rooms. Select “Share” again to see progress, or use “Open share” in the completion notice. The confirmation lists what is included and left out, and anything that looks like a key, a folder on this computer or contact details, with its message number and nearby text. After checking, choose one:
  - “Download web page” builds and downloads a single `.html` file in the background that opens in any browser. Once sent, it cannot expire or be taken back.
  - “Publish link” closes the dialog after the size checks and publishes in the background. Use “View share card” or “Copy link” in the completion notice, including after returning to the page on a phone. Choose whether it expires in 1, 3 or 7 days. Once expired, the link no longer shows the room, but it can still be renewed to bring the same link back. “Shared” below the room list shows live and expired links, with their time left, to copy, open, renew (same content, a new lifetime from now) or revoke. The room’s menu also offers “Copy share link” and “Revoke share link”, and “Share” again offers “Update link” to show the latest content. Confirming revocation immediately removes the link from the list and room menu. Renewing updates the displayed expiry immediately. You can continue with other rooms while the change is saved. If it fails, the affected link is restored and an error is shown. Links are kept with the room on the computer, so paired phones and tablets can manage them too. Rooms whose text comes to over 5 MB after cleaning need the web page file instead.

  **Share card and share copy.** Choose “View share card” from the completion notice or the “Shared” list. The dialog pairs the cover image with ready-to-paste “Share copy” for social posts or chats: the automatic cover extracts the opening sentence and latest outcome sentence (which you can edit or reset with “Restore auto-extracted”), and a fixed-height thumbnail grid lets you pick a room image or “Upload cover” (PNG, JPG or WebP; tall images can be cropped). “Share copy” starts with a default post containing the room summary, active deployed product links and the full session link, with editing, “Reset” and one-click “Copy text”; selecting a room image tagged “Copy” (paired with a `share-copy` block in the same message) automatically loads its matching copy and fills `{{share_url}}` with the live link. “Update link” keeps your chosen cover and edited text and refreshes the other content. Revoking and publishing again creates a new card. Reopen the card after renewal to see the new expiry next to its QR code. Choose “Save image” to export a PNG. Select “Copy share card diagnostics” in the share dialog to copy the material cutoff message and count, cover source, rendering stage, and confirmed publication and attachment status. PNG dimensions appear after rendering. Fields missing from older records are omitted. The summary omits text, images, and access credentials.

  “Reset” stays in place and is disabled while the default copy is in use.

  To have AI make both the cover and social-post copy, choose “Share → Make a share card with AI” from the room menu. Collect the cover PNG and accompanying copy in the [platform steward](steward.md) conversation.

  Either way, readers see the room’s **Messages** and **Runs** views from the beginning, as they look here: cards and run details open; each time **Runs** is opened it replays the session from the start, and “End replay” returns to the final state. The other tabs, such as **Private**, **Room** and **Files**, are dimmed and show only a sample; but nothing can be sent or changed, and the page shows the room as it was when it was made. Private chats, the event log, scheduling decisions, refused actions, queued messages, paths on this computer, session IDs and credentials are left out, as are retracted or rewound messages; failure reasons read only “Run failed”, and the room’s project folders are rewritten in message text as paths inside the project. The rest of the message text is shared as written, so check it before sending.

  Attachments are left out by default, and attachment tags in messages read “not included in the share”. When the room has attachments, the confirmation offers “Include attachments”: ticked, every attachment (images, videos, web pages, documents and so on) goes into the page as it is, for readers to view and download; project files a member’s answer delivered (the file cards under the answer) come along too, as attachments of that answer. Text attachments are checked for keys and local folders too; the contents of images, videos and other files cannot be checked, so look through them yourself. A share link carries the attachments the page can preview — images, audio, video, PDF, Word/Excel/PowerPoint (docx, xlsx, pptx), text and code, zip archives, and web pages — for readers to open right in the page; scripts that run on a double click, such as js, bat and ps1, go with .txt added to their names. Programs and old doc/xls/ppt files stay off the share site and their messages read “not included in the share”, while a downloaded web page file still carries them. Web page attachments run on the share page as they do in the room, and demos a member’s answer refers to show inside the message; they run in an isolated frame that cannot read the share page, send requests or submit forms. Select “Filter files” to choose attachments by type or individually. The filters expand automatically above 300 MB. Files appear newest message first. Each file shows the message number, sender, time and size. Click its name or “Preview” and close the preview to continue selecting. Published links allow 5 MB of text plus up to 300 MB of attachments, with a 100 MB limit per file. The computer’s background service prepares and uploads the share even if you lock your phone, close the page or switch to another paired device. Under “Shared”, open “Share jobs” to review a draft, check uploaded files and bytes, cancel, retry or adjust attachments. After publication, use the live link below the jobs to open its card or copy the link. Cancel, retry and dismiss update the job immediately. If the operation fails, the job is restored and an error is shown. Opening a draft or share card shows the room title while its contents load. When the service is offline, keep the browser page open until the transfer finishes. A downloaded web page file carries at most 100 MB of attachments. If the room changes before download, review the updated contents in the confirmation dialog.
- **Import rooms.** In directory options or a folder menu, select “Import rooms” and choose a ZIP. Review the preview and confirm the rooms to import. A room marked “Already exists; skipped” is left as is. On the same computer, invite members back to resume their sessions. Claude Code members switch to manual connection on import. Re-register them from their original window to avoid splitting the session. Imported discussion history is kept, but discussions are not restarted and members are not woken automatically.
- **Branch from a message.** In an AI message menu, select “Branch from here” to create a room containing the history through that message. Connections that support session branching resume from the branched session in the new room. The original room is kept.
- **Let the host create rooms.** With “Create rooms” ticked in “Host permissions”, the host can move part of the work into a new room. Members use only software configured on this computer, with read-only project access by default, raised as their work requires. The project folder must be the original room’s folder or a folder inside it. Unless you name another host, the new room is hosted by the same expert as the original host. Each room gets a “Linked room” card; select “Open room” to go to the other one. The new room inherits the original room’s smart scheduling, image generation, API limit, chain round limit and host permissions, except that it cannot create rooms. A room can create a limited number of rooms (3 by default, adjustable in “Host permissions”).

### 6. Contact another room’s host

Give your host the target room’s title, ID or link and describe the work. On a computer, drag a room from the left sidebar onto the messages or the message box to insert `[room Title #ID]` at the cursor, so the host can find it by its ID. Like an attachment placeholder, it is highlighted in the message box and one Backspace removes all of it; a member dragged from the right sidebar onto the messages or the message box inserts `[member Name]`, which behaves the same way. The other host answers with the reply command in its task. Sending or queuing the reply completes the request and keeps its full text on the sending card. If the other host delegates, it sends the final result back manually. A notification needs no reply.

A message from another room goes to this room's current host: an idle host takes it at once even while other members work; it queues only while the host is busy. The outgoing message shows whether it is queued, delivered or answered. Open it to read the original. Only a parent can interrupt a child. Set the linked-room message limit under Settings → Room preferences (0 means unlimited). The count resets when you speak in either room. The Parent and child rooms section shows these relationships even after a room is detached in the directory.

## Notes

- **Notice when a room's work ends.** When all work in another room ends (it changes from "Running" to idle) and stays ended for a few seconds, the page shows "Work in room \"Room name\" has ended" in the lower-right corner. The room you are viewing is not announced, and neither is work that stops and resumes at once, as with an interjection or a retry. The page must be open.
- **Shared directories are not locked.** If members edit the same project file at once, the page shows a conflict notification while the room is open. It is not added to the message history and does not wake the host.
- Read large assets and repositories in their project folders. Never copy them into a member’s draft folder or its `.scratch` subfolder, even when the project is read-only. If a writable copy is necessary, ask the owner to designate a writable project folder.
- **Storage and limits.** When connected to the local service or a paired computer, the **Storage** section at the bottom of the **Room** tab (expanded by default) shows usage (1 GiB per room, 3 GiB across all drafts, and 10 GiB for local `.codiscuss` data excluding speech models). If the room has attachments, an **Attachments** row below shows how much space they take; attachments are stored with the room records, do not count toward the draft quota, and are not removed by **Clear temporary files**. The room owner can select **Manage attachments** at the bottom to free attachment space: filter by type (images, audio & video, archives, documents, other) and age (older than 7 or 30 days), sorted largest first; the footer shows how much the selection frees. Select **Clear selected**, then **Confirm clear (cannot be undone)**. Messages stay, and each cleared attachment keeps its name, size and image thumbnail and is marked **Cleared**, but the original can no longer be opened, downloaded or read by members, and share pages and export packages no longer include it. The bar and text turn amber at 80% and red when over the limit (pausing new runs); reaching 8 GiB across `.codiscuss` also shows a warning notice, and any permission-denied unreadable entries are called out separately; **Draft storage** only counts unreadable entries in this room's drafts, while the computer-wide count is on the management panel **Storage** page. The room owner can select **Clear temporary files** in the expanded section to remove confirmed finished execution `.scratch` folders. If older drafts block the room and the [platform steward](steward.md) can still take requests, ask it to inventory them and delete rebuildable copies only after confirmation; room records and attachments (`local/`) are never deleted automatically; clear attachment originals with **Manage attachments**, or destroy old rooms to free space. Limits rely on periodic sampling rather than a filesystem write-layer hard quota and cannot guarantee the disk will never fill.
During active runs, the service checks free space on its own volume every two seconds. While part of the 10 GiB budget remains, a drop in free space as large as that remainder triggers an early scan. When a run ends, the service updates that member’s draft usage. A manual retry after cleanup rechecks the limit that blocked the run. If a machine-wide limit was exceeded, the service measures machine-wide usage again. If another program writes to the volume, runs continue when measured usage is within limits and the unreadable count is stable. If an early scan finds more unreadable entries, dispatch pauses and the service requests stops for stoppable runs. Dispatch resumes when a later scan finds a stable count, usage within limits and enough free disk space. The low-disk reserve applies independently. At 80% of the room draft limit, new runs without confirmed stop support are paused. Writes can continue between and during scans, and ongoing unstoppable runs can keep writing. Project files, system temporary files and third-party AI data outside the service directory are excluded. Follow the cleanup instructions on the failed run’s card, then select “Retry” on that card from the computer or a paired device.
- **Preview and transfer limits.** Text previews show at most the first 128 KB. When another device accesses media and documents through the computer, each file is limited to 64 MB. The web app first attempts to compress videos larger than 3 MiB. Links pointing outside a project directory appear disabled and are rejected.
- **A branch does not copy project files.** Branched and original rooms share the same project directory. Branching requires a connection to the local service.
- **An attachment is not necessarily read.** Sending a file to the room does not mean a member has read it. Private chat and in-progress interruptions do not support attachments.
- **Backup compatibility.** Version 1 room archives can no longer be imported.
