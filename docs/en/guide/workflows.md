# Workflows

Save a reliable division of work as a workflow and reuse it in any room. You can install a bundled workflow or create and edit your own with the workflow-creator skill.

## How to use workflows

### 1. Install bundled workflows

The CoDiscuss package includes three workflows. They are not installed by default:

- **“小说连载”** (serial fiction, `story-serial`): a screenwriter, writer, two critics, and a recorder work through each episode in sequence. A reader can review the draft when needed. Includes templates and check scripts that require Python and PyYAML.
- **“决策会审”** (decision council, `decision-council`): a devil’s advocate, outsider, alternative thinker, and implementer respond independently, then debate disagreements. The host synthesizes a recommendation.
- **“经典跑团（龙与地下城式）”** (classic tabletop role-playing, `trpg-classic`): a dungeon master and three AI players, with rules reference, an original adventure, and dice scripts that require Python.

To install workflows for the first time or add them later:

- **Interactive setup:** Run codiscuss setup. After choosing software, expand “Bundled workflows” with the Right Arrow at “Install settings,” select workflows with Space, and continue with Enter.
- **Install all bundled workflows:** Run codiscuss setup --workflows or codiscuss install --workflows.

Rerunning setup replaces selected bundled workflows with the package versions. Before replacing a workflow with the same ID, the original is backed up under backups/workflows/ in the local service directory. Custom workflows with different IDs and your software and site settings are left alone. Workflow selections apply only to that run and are not remembered.

### 2. Enable, refresh, and end a room workflow

1. **Allow the host to enable workflows:** When creating a room, turn on “Full host control” under “How to work (optional)”. In an existing room, open **Room → Members and settings** in the tabs at the top of the room and turn it on under “Collaboration settings.” The host then has permission to enable a workflow and invite its members.
2. **Enable a workflow.** Type `/` in the composer. “Project workflows” appears before “Global workflows”. If the room has several project folders, check the project name when choosing a workflow. Add what you want done and send the message to the host. The host enables the workflow and brings in the members for any missing cards.
   - Each card in the main workflow defines a role, including its description, member prompt, software, model, effort, and project access. Members already mapped to a card and present in the room keep their identity. Away members are invited back. Sub-workflow roles join when used. Workflow prompts are read-only in a room. Edit them on the Workflows page.
3. **Add new roles:** If you add cards to a workflow later, existing rooms do not add those members automatically. The host adds them when needed, or you can click the refresh icon on the workflow row in the right panel.
4. **Use a sub-workflow:** While a workflow is active, type / in the composer and choose an item under “Sub-workflows of ‘name’.” Send it to the host to run that procedure. Members used only by the sub-workflow are marked away when it is done. Their sessions are kept.
5. **End a workflow in a room:** On the workflow row under “Collaboration settings” in **Room → Members and settings** in the tabs at the top of the room, click the dismiss-members control. Workflow members leave, the host stays, and active work stops. Their sessions are kept, and selecting that workflow again can bring the members back. To disable a workflow in your local library, open the “…” menu beside it on the Workflows page and choose “Disable.”

### 3. Create or edit workflows with workflow-creator

You can create or import a ZIP file or folder with the “+” on the Workflows page. You can also ask an AI with the bundled workflow-creator skill to draft and validate a workflow:

- **Ask the host in a room:** Enable “Full host control,” then describe the division of work you want. You can also type / and choose “Create / edit workflow” under platform skills. The host uses the skill to create SKILL.md, role cards, and a canvas, validates them, saves, and enables the workflow. By default, it saves to the room’s main project when there is one, or to the global library otherwise. Ask the host to save it globally if you plan to reuse it across projects.
- **Ask an AI in an external session:** In a Claude Code or Codex session with the CoDiscuss skills installed, ask it to create or edit a workflow with workflow-creator. It validates a folder with codiscuss launch workflow-check --dir <directory>. After you approve, it saves the workflow with codiscuss launch workflow-save --dir <directory>. If the library already has that ID, the save is refused unless it explicitly overwrites (--overwrite) or names the revision it read (--revision). For a project workflow, pass `--scope project --project <folder>` when validating and saving.
- **Where workflows are stored.** Global workflows are available across projects and live in `~/.codiscuss/workflows/<id>/`. A project workflow lives in `<project-root>/.codiscuss/workflows/<id>/` and is available in rooms that use that project folder. In the sidebar, “Workflows” lists workflows under “Current project” before “Global”. When the room has multiple folders, project workflows show their project names. A room without a project shows global workflows only.
- **Choose where to save.** Open “+” and select the new or import action for the destination, such as “New global workflow” or “New in project ‘name’”. The editor header shows “Global” or “Project · name”, with a “Read-only” badge where applicable. You can open workflows from read-only projects and copy them to the global library.
- **Move, copy, or export.** Open the project workflow’s “…” menu and choose “Move to global” or “Copy to global”. Moving requires a writable source, updates the current room’s binding, and is refused if the global library already has the same ID. Copying keeps the original. Use “Copy to current project” to copy a global workflow when there is one writable project. If several are writable, choose the matching “Copy to project ‘name’” action. Choose “Export” to download a ZIP. The export notice lists files skipped because they were too large or were not text.

### 4. The canvas and SKILL.md

Edit the “Short description” directly above the workflow text. It wraps to the panel width so you can read the full description.

Select a workflow on the Workflows page. The canvas opens in the center, and its SKILL.md appears on the right. Click “Edit,” then “Save” or press Ctrl+S to save changes. If the workflow was changed elsewhere after you opened it, saving is refused and the page says “The workflow was changed elsewhere; reload it”; “Reload” reads the new version and first asks before discarding unsaved edits. An imported workflow whose ID is already in the library is saved only after you choose “Save and replace.”

- **The canvas is a diagram:** You can move cards, add host nodes, user nodes (to show where you step in, confirm, or speak), and conditional branch nodes (splitting into multiple named branches, each with its own output dot on the right; select to add, rename, or remove branches), connect nodes to show order, parallel branches, or loops, add notes to connections, or choose “Auto arrange.” Click a connection or its note to select it before editing; once a gold loop is selected, drag it up or down to change its height. Dragging an unselected connection or note just pans the canvas. The program does not execute canvas connections, and the host cannot see the canvas.
- **The host follows SKILL.md:** The skill file defines order, parallel work, when to return to the host, and when to revise. The host follows those written instructions. When workflow-creator creates or edits a workflow, it updates the canvas to reflect the skill file.
- **Steps and attached sub-workflows:** The canvas can group nodes into steps, shown as named dashed frames that list the sub-workflows attached to each step. Steps and attachments live in flow.json and in each sub-workflow's SKILL.md (workflow-creator maintains them). Like the canvas they are only a diagram; the host still decides from SKILL.md whether to use a sub-workflow at that step.
- **Several members for one card:** The host can bring in several members for the same card under different display names, for example one member per character. A display name applies to this room only, and asking for the same name again brings back the same member with its own session.
- **Experts with skills:** A workflow expert can be a folder instead of a file: `experts/<card-id>/` holds its definition <card-id>.md (the same format as a card file) and skills/<skill>/, each skill a SKILL.md plus references/. Older workflows with `agents/` can still be opened. The member playing that card may read and write its own skills while the rest of the workflow stays read-only; its writing does not change the workflow’s revision, and ordinary saves from the page or the command line keep the skills as they are; only an explicit overwrite or an import replaces them with the folder’s. Exporting the expert gives exactly that folder. “Experts” is a large dialog: every card on the left, and on the right three tabs, “Basics”, “Prompt” and “Skills”. Changes to basics and prompts are written to the workflow by “Save” at the bottom of the dialog (the same save as the Workflows page’s); skill files are saved one at a time. On a phone you pick an expert from the list first, then open its settings, with a back button at the top left. Every expert with skills, in the main flow or a sub-workflow, is listed under Advisors, marked with where it sits; its “Skills” tab shows its skills and files on the left and the chosen file’s editor on the right (one level at a time on a phone), to view and edit each skill’s SKILL.md and references and to create or delete skills and reference files. These edits are written to the expert’s folder at once, without saving the workflow or changing its revision; a file the expert changed meanwhile is refused with a reload offered, never overwritten. On another expert, the “Skills” tab takes its first skill’s name and description (“Add skill”); after you save the workflow it becomes a folder with skills. “Import expert package” below the list puts an md, zip or folder into the main flow or the sub-workflow open on the canvas. Removing an expert with skills, replacing its skills by an overwrite, or deleting the workflow first backs its folder up into backups in the service folder. codiscuss launch expert-import --from <path> --workflow <id> [--sub <sub-workflow-id>] puts an expert package into a workflow and refuses a card ID that exists. A panel expert has skills of its own under `experts/<id>/skills/` in its global or project scope, never shared with a workflow’s; “Save as preset” in “Experts” copies them there; skills already on this computer are kept, and the notice offers to replace them with the workflow’s. On the new-room panel, a preset expert with skills (an advisor) shows only the basic settings on its back, like any other expert, plus an “Advanced settings” button that opens the same dialog as the workflow’s, for its own skills in the selected scope. If a preset of that name exists, choose “Replace the preset of this name” to replace it; skills already there are kept. In the page, “Import / export experts” under “添加 AI” on the new-room panel imports an .md, a zip or a folder and exports any preset; “Export” in a workflow’s “Experts” exports the current card as saved. Without skills you get one md, otherwise a zip. On import, a preset of the same name asks you to “Replace” or cancel; skills already on this computer are kept unless you choose “Use the imported one (the current one is backed up)”; ignored files and access lowered to read-only are listed. On the command line, codiscuss launch expert-export exports an expert and codiscuss launch expert-import imports one as a preset; an existing preset or skills are never replaced silently. When an expert names software this computer has not set up, or a model missing from this computer’s list for that software, the import still succeeds and its notice says so; the panel button is then greyed (software) or the card is marked “… is not available here and cannot run” (model), and starting a room or inviting it is refused until the software is set up or the model changed to a listed one (empty means the software default). Only a model list already read here counts: no list yet, a failed read or no model at all is never flagged, and Claude’s list, being only its model picker, never blocks.

### 5. “Full host control” and workflows

- With “Full host control,” the host can create, edit, and enable workflows, invite required members with up to write access, interrupt or retry members, change models, reorder speakers, withdraw its own assignments, start discussions or Goals, and schedule its own check-ins.
- Without this setting, workflow items in the composer’s / menu are disabled. The host cannot invite members or enable a workflow. You can invite the members yourself and explain the process to the host.
- Enabling a new workflow through the composer requires a host that the local service can wake. An API host can read the description and role list for an enabled workflow.

## Things to know

- **First use of a workflow from a repository.** A project workflow from an unfamiliar repository requires confirmation the first time you enable it if it registers local commands or includes cards with more than read-only access. You can also choose a workflow through “Invite AI” in the room sidebar. Review the elevated member cards and registered commands in the “Trust project workflow” dialog. From the `/` menu select “Trust and continue”, then add and send your request. From the invitation flow select “Trust and enable”. Trust is stored on the computer for the reviewed content.

- **Changes reach active rooms:** Rooms using a workflow read its latest instructions and member prompts on their next run. Existing members’ models, effort, and project access remain room settings.
- **Review imported workflows:** Importing a ZIP or folder shows a canvas preview. Cards that can write files are imported read-only until you enable them individually. If a workflow includes commands.json to register local commands for read-only API members, the editor shows the full commands. They run only after you enable “Allow these commands to run on this computer.” The host cannot add or remove local commands while drafting or editing a workflow.
- **Allow only part of it:** Expand “Items” under “Full host control” and tick them one by one: “Handle execution problems”, “Adjust member settings”, “Change project access”, “Manage the member list”, “How work proceeds”, “Workflows” and “Create rooms”. Saving and enabling workflows needs “Workflows”; an action whose item is not ticked is refused, and the host is told which item is missing.
- **You keep key decisions:** Even with “Full host control,” only you can change the host, approve assignment rounds above the limit, grant project access above write, change project folders, withdraw your messages, or use private chat.
