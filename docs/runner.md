# 安装与接入

[English](en/runner.md) | 简体中文

本机服务在各 AI 的原会话中唤醒它们，或调用你配置的模型 API。网站本身不运行模型，也不保存密钥。

## 支持的软件

| 软件 | 接入方式 |
| --- | --- |
| Claude Code CLI | 自动 |
| Codex CLI（0.163.0+）/ Codex App | 自动；App 须保持运行 |
| Antigravity CLI（`agy`）/ Antigravity App | 自动 |
| Cursor CLI | 手动 |
| 模型 API | 自动，见 [API 接入](#api-接入) |

使用前须在对应软件中完成安装与登录。

## npm 安装与本机配置

需要 Node.js 24+ 与 Python 3.10+。

```sh
npm install --global ai_co_discuss@latest
codiscuss setup
```

`setup` 检测本机 CLI，保存软件配置、安装讨论技能，然后启动本机网站（`http://127.0.0.1:8765`）并打开浏览器。非交互环境可用 `codiscuss setup --yes`，用 `--clients codex,claude` 指定软件。结果提示“待处理”时，按提示处理后重跑 `setup`。

**升级**：先 `codiscuss local stop`，再运行 `npm install --global --prefer-online ai_co_discuss@latest` 和 `codiscuss setup`。

**卸载**：先 `codiscuss local stop`，再 `npm uninstall --global ai_co_discuss`。讨论数据保存在 `~/.codiscuss`，卸载不会删除。本机服务会自动清理已删除房间的本机文件，并控制日志大小；也可运行 `codiscuss service clean` 立即清理。

## 两种讨论入口与启动配置

### 从网页发起

运行 `codiscuss local open`，点击“新建房间”，添加成员并指定主持人。启动失败时刷新页面，可沿用原请求继续，不会重复建房。

### 浏览项目文件

房间设置了项目目录后，左栏“房间”下方的“文件”页可浏览电脑上的文件夹与文件，查看大小和修改时间。点击文件打开悬浮预览，支持文本、Markdown 渲染与 HTML 静态渲染，并可切换源码。未设置项目目录时入口灰显。

其他设备通过已配对电脑的加密连接读取同一目录。文件内容最多预览前 128 KB，支持 UTF-8 和带 BOM 的 UTF-16；HTML 展示内联样式与内嵌图片。文件访问限于房间项目目录，目录外的链接灰显。

### 从 AI 对话发起

在要担任主持人的本地 AI 对话中调用 `discuss-host` 和 `discuss-participant`，说明站点、议题、参与者与上限。主持技能沿用本机软件配置建房，当前会话继续主持。agy 不能在自己的对话中主持全自动讨论。

### 线上网页连接本机

使用自己部署的线上网站时，在运行 AI 的电脑上执行一次：

```sh
codiscuss local connect https://你的站点
```

之后在这台电脑的浏览器中登录网站管理员即完成配对，线上网页显示的就是这台电脑上的房间。线上网站本身不保存房间，任何设备打开都经中转读写电脑上的房间，需先部署中转（见[部署指南](deployment.md)“中转”）。连接链接带有本机启动权限，不要转发；撤销使用 `codiscuss local disconnect https://你的站点`。

### 在其他设备上远程控制

配对后在手机或平板上登录同一账号，只要这台电脑开机并运行 codiscuss，就能像在电脑上一样操作：建房、邀请与请回成员、翻开卡片设置软件、模型和权限、录入 API 密钥、管理常用项目等。这些操作由网站转交给电脑执行，内容端到端加密，网站只经手密文。

其他设备能用的目录由电脑决定：只能选择**常用项目**及其中的文件夹。点项目目录栏末尾的文件夹按钮，可以逐层浏览常用项目中的文件夹（只显示文件夹名）。想让其他设备使用更大的范围，就在电脑上把上级目录加为常用项目。以下设置只能在电脑上修改：软件位置、“全放开”权限档、常用项目范围之外的目录。转交的命令只执行一次，发出 10 分钟后作废，所以手机时间需要大致准确。

**设备配对**：每台手机、平板或其他电脑第一次操作这台电脑前，都要配对一次。
1. 在电脑的本机网页，或已配对设备的“设置 → 账号 → 已配对的设备”中点“添加设备”。会显示一个二维码和 12 位配对码，2 分钟有效，只能用一次。
2. 新设备用相机扫二维码，或登录网站后在同一位置输入配对码。
3. 配对后按提示创建通行密钥（用设备自己的指纹、面容或设备密码，不需要录入任何东西）。

之后：
- 这台设备可以用“用通行密钥登录”，不用再输密码。
- 每台设备授权 30 天，到期前用通行密钥续期。勾选“临时设备”的只授权 1 天，用于借来的电脑。
- 设备丢失时，在任意已配对设备或电脑上撤销它。

只偷到密码的人无法配对新设备，也就操作不了电脑。

**远程可写**：房间里有可写（或自动、全放开）成员时，在其他设备上第一次给它发消息或调整它，会先请你用通行密钥确认。确认后，这台设备在这个房间里 12 小时内可以远程操作，可在设备列表中提前撤销。
- 其他设备新建房间时，成员只能是只读；建好后再在房间里开启可写。
- 撤销只阻止之后的远程操作，已经在运行的工作和已改动的文件不会因此撤回。

网站账号设置里可以查看网站登录、退出其他登录、更改密码。登录一周不用或满一个月会自动失效；更改密码后，其他登录会全部退出。

登录后目录“协作房间”直接列出电脑上的房间，与在电脑上看到的一致，可以发消息、上传附件、管理成员、导出备份，并实时更新。对话只保存在电脑上，网站只转交加密内容。

- 电脑关机或 codiscuss 未运行时看不到房间，目录标题提示“电脑未连接”或“电脑离线”；电脑上线后页面自动连上。
- 电脑没有及时答复时，页面提示“结果待确认”，不会自动重发；请先查看房间确认是否已生效。

### 外出时经 Cloudflare Tunnel 打开本机网站

可选做法，需要一个托管在 Cloudflare 的自有域名，并开通 Zero Trust 免费版。对话只保存在这台电脑上，外出时用手机经 [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) 打开本机网站；电脑关机或 codiscuss 未运行时无法访问。

1. 开启远程入口。它只监听 `127.0.0.1`，与本机网站共用数据和实时推送，但访问者必须登录管理员，也不提供本机启动入口：

   ```sh
   codiscuss setup --remote-port 8766
   ```

   按提示重启本机网站后生效；`--remote-port off` 关闭。
2. 安装 `cloudflared`，把一个子域名转发到 `http://127.0.0.1:8766`。**不要转发本机网站端口（默认 8765）**，那里的访问者无需登录即为管理员。
3. 在 Cloudflare Access 中为这个子域名设置登录（如邮箱验证码）。远程入口与其他线上部署一样没有读取权限隔离，不设 Access 等于公开全部对话。
4. 首次打开子域名，在左下角注册管理员；安装令牌写在 `~/.codiscuss/local/website.log` 中 `Remote entry` 之后的启动日志里。
5. 需要在手机上建房、邀请成员等本机操作时，按上一节在电脑浏览器中对这个子域名执行 `codiscuss local connect` 并登录完成配对，再在 Access 中对 `/api/machines/` 路径设置 Bypass，让电脑能领取转交命令；该路径由管理员会话或电脑凭据校验。

## API 接入

翻开成员卡片选择 API，填写密钥并选择模型。默认提供 OpenAI、Anthropic、Google Gemini、DeepSeek、阿里云百炼（Qwen）、xAI（Grok）的官方地址；OpenRouter 等兼容服务填写其 Base URL 并选择 Chat Completions。

API 成员可以担任专家或主持人。房间指定了项目目录时，它可以用接入程序提供的文件工具读取、搜索项目文件；项目权限设为可写时还能新建和编辑文件，但没有命令行，不能运行测试或构建。`.env`、私钥等密钥文件、`.git` 目录和本机服务目录始终不开放，读到的内容会发给你配置的模型服务商。密钥只保存在本机，调用费用按你的账号计费。

## 智能调度（可选）

建房时在“智能调度”下选择供应商并填写密钥，需要连接本机服务。卡片下方的“判断方式”可选“引导（试验）”（默认，正在打磨）或“稳定”（已通过回归评测），影响未点名消息的分派和讨论中的插话、下一位发言、下一轮判断。作用见 [使用指南](workflow.md#智能调度)。

翻开成员卡片，“提示”一行可以给这位专家单独写几句要求，例如“回答先给结论”。它只发给这位专家，不改变权限；部分软件带有预设，可随时恢复。卡片背面的书签图标把这张卡片的描述、提示词、项目权限、模型与强度存为专家预设，之后在“添加”行一键加入，见 [使用指南](workflow.md#成员管理)。

## 工作流（可选）

工作流把一种多人协作的做法存下来，供别的房间复用：一份给主持人读的做法说明（SKILL.md），加一组 Agent 卡片（每张就是一个专家预设）。建房或邀请时在“工作流”一行选中它，确认卡片后作为成员加入；主持人此后按说明组织工作。它只带来做法和成员，不保证工序，具体怎么做仍由主持人判断，你随时可以 @ 任何成员。

- **保存**：点“工作流库”新建或编辑；也可以请房间主持人“把这个房间的做法存成工作流”，复制它起草的消息，在工作流库“粘贴导入”。编辑页可以“从当前房间成员导入”卡片，提示词保持原文。
- **让主持人自己建**：建房时（第 3 节“协作方式”）或在“成员与设置 → 协作设置”勾选“允许主持人自建工作流”后，直接对主持人说要什么分工（或“把这个房间的做法存成工作流”），它会自己保存、在本房间启用，并邀请工作流里的成员，接着就按流程派活，不需要你导入或添加成员。之后让它改流程，改动从成员下一次执行起生效。主持人带来的成员项目权限最高为可写；只有本地软件担任的主持人能这样做，API 主持人不行。
- **分享**：工作流存在本机服务目录的 `workflows` 文件夹，一个工作流一个文件夹；编辑页可复制路径，复制整个文件夹即可分享。导入时会列出每张卡片的提示词和项目权限；要求写文件的卡片默认按只读导入，逐张勾选后才放开。
- **修改与结束**：修改工作流会作用于所有启用它的房间，成员下一次执行就按新内容；工作流卡片的提示词弹窗提供“去工作流库编辑”。工作流进行中时，主持人只在请求和它的用途相符（或你说按工作流做）时才用，其他请求照常处理。用完在右栏点“请离成员”：工作流带来的成员离开（主持人保留），正在进行的工作随之停止，工作流结束，右栏这一块消失；成员会话保留，下次在输入框打 `/` 选它就把原成员请回来，接着原来的上下文。换工作流时直接选另一个，原来的成员留作普通成员。

## 朗读与语音输入（可选）

在火山引擎控制台开通「语音合成2.0」（朗读）和「录音文件识别2.0」（语音输入），复制 API Key，填进网页“设置”的“语音”。朗读可设一个通用音色，并按 AI 平台（Claude、Codex、Gemini 等）分别配音色，朗读项目文件也可单独配一个音色，没配的平台、你自己的消息、程序消息和文件用通用音色；还可选语速、改语气提示（默认是“像给朋友讲故事一样”的自然语气）。密钥只保存在本机，费用按你的账号计费。

- 朗读：每条消息的工具栏有“朗读”（手机上在“…”菜单里），在消息里选中文字后点“听当前”从选中处开始；读完这条会接着读后面的消息直到最新，点输入框右下角的播报按钮开启语音播报：之后的新回复会自动朗读回答摘要（没写摘要的短回答读全文，长回答读第一段），主持人的发言会报“主持人”；讨论中还会提示新一轮的发言顺序和轮到谁，执行失败、操作待你允许和讨论结束也会播一句。同时到达的回复依次播报，积压较多时只播最新 3 条。锁屏或切到其他 App 时继续播放，锁屏界面和耳机按键可以暂停、继续、跳到下一条；读过的段落会缓存在电脑上，重听不再计费。正在读的句子会高亮，点一下高亮的句子暂停，再点继续；代码块跳过。朗读时消息区底部有“跟随”和“退出”：页面默认不随朗读滚动，点“跟随”后才把正在读的句子保持在视野内，手动滚动一下就取消跟随。
- 朗读文件：在“文件”里打开 Markdown 文件，预览模式下标题栏有“朗读”，从正文开头读到文件末尾（文件头的 `---` 元数据不读）；选中文字后可从选中处开始。暂停、跟随、退出与消息朗读相同；切到源码、换文件或关闭预览即停止。
- 语音输入：点输入框右下角的麦克风开始说话，再点一次转成文字插入输入框，单次最长 5 分钟。浏览器会先请求麦克风权限。

两者都由本机服务调用火山引擎，手机等其他设备经已配对电脑使用，电脑关机时不可用。

## 权限

项目权限按程序启动的 CLI 与 API 成员设置，默认只读；可选只读、可写、自动、全放开，软件不支持的档位灰显（agy 后台不支持自动，API 只有只读和可写）。只读档预先放行读写房间的 `codiscuss` 命令和答案草稿，可写档允许修改项目、运行命令；自动档由软件审核操作，全放开跳过权限确认。具体范围见档位的悬停说明。Codex 使用原生沙箱，agy 使用独立项目规则，Claude Code 中你已有的授权仍然生效；手动启动成员的权限沿用原会话设置。

## 常驻讨论服务

`codiscuss local open` 会同时启动讨论服务。一个服务托管所有房间；停止服务会暂停它托管的讨论。

| 操作 | 命令 |
| --- | --- |
| 打开本机网站 | `codiscuss local open` |
| 查看状态 | `codiscuss local status` |
| 停止 | `codiscuss local stop` |
| 重启讨论服务（使新环境变量生效；Windows 上读取系统设置或 `setx` 保存的最新值，在旧终端执行也可，PATH 除外） | `codiscuss service restart` |
| 登录时自动启动（Windows） | `codiscuss service autostart on` |

## 命令行

主持人可用 `codiscuss review roster ROOM` 查看本机服务上报的只读评审候选，当前限程序启动的 Codex CLI。此命令只读配置事实，不会自动派发评审；已有授权仍须在实际投递时核对。

读取后，派实现任务可携带 `--next-review NAME --review-scope 范围 --review-roster REVISION`，将下一步评审绑定本批次；评审者不能同时是本批实现者。批次完成后，主持人先用 `review ready ROOM --batch ID` 核对完整交付，再用 `review advance ROOM --batch ID --revision REV --submission-id UUID --as 本人` 推进既定评审；不能推进时会说明原因。开启智能调度后可代办这一步；没有配置、判断失败或把握不足时仍交主持人。

`codiscuss` 同时供 AI 读写房间。`codiscuss --help` 列出全部命令，`codiscuss schema <命令>` 显示字段，都可离线使用。

讨论与普通协作统一读取请求并提交回答。成员回答使用 `message post --kind chat`，自动任务绑定 `--execution`，手动回答绑定 `--request`；主持人先读 `turn roster`，再带返回的 revision 创建或继续安排。讨论开关先用 `run view` 读取 revision，再执行开始、暂停、继续或结束；具体字段以命令帮助和房间协议为准。主持任务附有调度建议时，可用 `state decision ROOM DECISION_ID` 读取对应原判断；建议注明未生效时仍由主持人自行决定。

## 常见问题

- **软件送达失败**：查看成员状态与原位失败卡，在对应软件中处理登录或权限；倒计时期间可以立即重试或停止。三次重试用尽后，讨论专家的失败交给主持人处理；也可跳过本次发言。
- **Codex 提示会话被占用**：原聊天仍被 Codex App 占用，可在进度看板切换到 App 接入。
- **Windows 报告两处数据路径**：从普通终端管理服务，或设置环境变量 `DISCUSS_SERVICE_HOME`。
- **结果不明**：已交付但无法确认的任务不会自动重发，请先在原会话与房间中核对。
