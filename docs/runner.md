# 安装与接入

[English](en/runner.md) | 简体中文

本机服务在各 AI 的原会话中唤醒它们，或调用你配置的模型 API。网站本身不运行模型，也不保存密钥。

## 支持的软件

| 软件 | 接入方式 |
| --- | --- |
| Claude Code CLI | 自动 |
| Codex CLI（0.163.0+）/ Codex App | 自动；App 须保持运行 |
| Antigravity CLI（`agy`）/ Antigravity App | 自动 |
| Cursor CLI | 手动 |
| 模型 API | 自动，见 [API 接入](#api-接入) |

使用前须在对应软件中完成安装与登录。

## npm 安装与本机配置

需要 Node.js 24+ 与 Python 3.10+。

```sh
npm install --global ai_co_discuss@latest
codiscuss setup
```

`setup` 检测本机 CLI，保存软件配置、安装讨论技能，然后启动本机网站（`http://127.0.0.1:8765`）并打开浏览器。非交互环境可用 `codiscuss setup --yes`，用 `--clients codex,claude` 指定软件。结果提示“待处理”时，按提示处理后重跑 `setup`。

**升级**：先 `codiscuss local stop`，再运行 `npm install --global --prefer-online ai_co_discuss@latest` 和 `codiscuss setup`。

**卸载**：先 `codiscuss local stop`，再 `npm uninstall --global ai_co_discuss`。讨论数据保存在 `~/.codiscuss`，卸载不会删除。本机服务会自动清理已删除房间的本机文件，并控制日志大小；也可运行 `codiscuss service clean` 立即清理。

## 两种讨论入口与启动配置

### 从网页发起

运行 `codiscuss local open`，点击“新建房间”，添加成员并指定主持人。启动失败时刷新页面，可沿用原请求继续，不会重复建房。

话题名称、项目目录和本次成员每次重新填写；智能调度、协作方式、讨论与 Goal 上限、连续派活轮数等选项自动记住上一次选择，取消建房也保留。偏好保存在运行服务的电脑上，其他已配对设备使用同一份；讨论与 Goal 的目标仍需每次填写。工作流只记住浏览选中项，不会因此启动。

### 浏览项目文件

房间设置了项目目录后，左栏“房间”下方的“文件”页可浏览电脑上的文件夹与文件，查看大小和修改时间。点击文件打开悬浮预览，支持文本、Markdown 渲染与 HTML 静态渲染，并可切换源码。可同时打开多个文件，以标签切换；标题栏的“收起”（手机上也可按住标签栏下拉，或正文在顶部时下拉）把预览缩成内容区左上角的悬浮按钮，悬浮按钮可拖到左侧或右侧；切到其他频道或其他房间后点它回到原处（打开的文件、模式和滚动位置都保留），关闭才清空。未设置项目目录时入口灰显。

在 Markdown 预览或成员回答正文中选中文字后点“添加到对话”，选中处上方出现批注框（可留空），回车后这段文字成为一条摘录，原文末尾标上编号；文件摘录随即收起预览、回到“消息”页。输入框上方显示“N 条摘录”，点开可逐条查看、修改批注或删除，悬停时的 × 一次移除全部；点原文上的编号也能重新编辑批注或删除该条。发送时每段摘录以“文件路径 + 行号”或“成员名 + 消息编号”加引用原文与批注附在正文之后，引用中的 @ 不会唤醒成员。

其他设备通过已配对电脑的加密连接读取同一目录。文件内容最多预览前 128 KB，支持 UTF-8 和带 BOM 的 UTF-16；HTML 展示内联样式与内嵌图片。文件访问限于房间项目目录，目录外的链接灰显。

### 多个项目目录

一个房间可以有一个主项目目录和最多 8 个其他项目目录。新建房间选好项目目录后，点下方“添加其他项目目录”；建房后在“成员与设置 → 协作设置”的“项目目录”一行增删，保存后从各成员下一次执行起生效，会话不中断。主项目目录设置后不能更改；建房时没选的，可在同一行补设一次，已在房间的成员保留原会话、按自己的项目权限读写它。

- 成员按自己的项目权限读写这些目录：只读成员全部只读，可写成员全部可写。
- “文件”页上方可切换目录；输入框里 `@` 搜索文件时会一起搜其他目录，选中后按完整路径引用。
- Claude Code、Codex CLI、agy 和 API 成员由程序限制读写；Codex App、Antigravity App 与在原窗口工作的手动成员只在任务里写明，实际权限以软件自身设置为准。

工作目录不在房间任何项目目录里的成员（例如手动接入时它的 Claude 会话属于别的文件夹，或在启动配置里给它设了别的工作目录）也可以加入：它在自己的目录工作，对房间的目录只读，它自己目录里的改动不参与冲突提示。它加入或换目录时，网页右下角会提示一次，成员卡上也会标出它的工作目录。Codex CLI、API 成员，以及只读档的 Claude Code、agy 由程序保证改不了房间目录；其他情况（App、手动成员、可写档的 Claude Code 与 agy、自动与全放开）只在任务里要求，成员卡会注明“程序拦不住”。

### 从 AI 对话发起

在要担任主持人的本地 AI 对话中调用 `discuss-host` 和 `discuss-participant`，说明站点、议题、参与者与上限。主持技能沿用本机软件配置建房，当前会话继续主持。agy 不能在自己的对话中主持全自动讨论。

### 线上网页连接本机

使用自己部署的线上网站时，在运行 AI 的电脑上执行一次：

```sh
codiscuss local connect https://你的站点
```

它用一次性绑定令牌把这台电脑绑定到网站：在部署网站的电脑上（已 `wrangler login`）自动生成，否则先在部署网站的电脑上运行 `codiscuss token`，再加 `--setup-key 令牌`。每个令牌只能用一次。线上网站没有账号和密码，也不保存房间；任何设备都要先与这台电脑配对，再经中转读写电脑上的房间，需先部署中转（见[部署指南](deployment.md)“中转”）。撤销使用 `codiscuss local disconnect https://你的站点`。

### 在其他设备上远程控制

手机或平板与电脑配对后，只要这台电脑开机并运行 codiscuss，就能像在电脑上一样操作：建房、邀请与请回成员、翻开卡片设置软件、模型和权限、录入 API 密钥、管理常用项目等。这些操作由网站转交给电脑执行，内容端到端加密，网站只经手密文。

其他设备能用的目录由电脑决定：只能选择**常用项目**及其中的文件夹。点项目目录栏末尾的文件夹按钮，可以逐层浏览常用项目中的文件夹（只显示文件夹名）。想让其他设备使用更大的范围，就在电脑上把上级目录加为常用项目。以下设置只能在电脑上修改：软件位置、常用项目范围之外的目录。转交的命令只执行一次，发出 10 分钟后作废，所以手机时间需要大致准确。

**设备配对**：每台手机、平板或其他电脑第一次使用前，都要在这台电脑前配对一次，不需要注册账号或记住密码。
1. 在电脑的本机网页“设置 → 账号 → 已配对的设备”中点“添加设备”，显示一个二维码和 12 位配对码，2 分钟有效，只能用一次。
2. 新设备用相机扫二维码；不方便扫码时，打开线上网站，在设置页输入配对码。扫码时页面会核对电脑密钥指纹，防止被换成别的电脑。
3. 按提示用设备自己的面容、指纹或设备密码确认一次，同时创建这台设备的通行密钥。

之后：
- 设备在浏览器里保存一把不可导出的设备密钥，之后打开网站直接可用。网站只认电脑签过名的设备名单，没有能被盗用的账号密码。
- 每台设备授权 30 天。到期前或到期后 30 天内打开网页，用通行密钥确认一次即续期 30 天，不用回到电脑前；超过这段时间须重新配对。勾选“临时设备”的只授权 1 天，用于借来的电脑，不能续期。
- 新设备的浏览器不支持通行密钥时（例如没有 Google Play 服务的安卓平板），在电脑上添加设备前勾选“允许不用通行密钥”再生成二维码。这样的设备不需要每日确认，也不能续期，到期须回电脑前重新配对；它在解锁状态下被别人拿到就能操作电脑，只在确实需要时勾选。
- 新设备只能在电脑前添加，已配对设备不能远程添加。设备丢失时，在其他已配对设备或电脑上解绑它；只有一台外出设备时，回到电脑前解绑并重新配对。
- 每台设备的记录按钮（时钟图标）列出电脑为它记下的配对、解绑、每日确认和远程操作（不含内容）；已解绑设备的记录汇总在列表末尾。看到不是你做的操作，立即解绑对应设备。
- 清除浏览器数据会删掉设备密钥，需要回到电脑前重新配对。

**每日确认**：每台设备每天第一次打开网页时，用面容、指纹或设备密码确认一次，之后 24 小时内建房、发消息、设置任意权限档（含可写、全放开）都不再询问。配对和续期本身也算一次确认。解绑设备只阻止之后的远程操作，已经在运行的工作和已改动的文件不会因此撤回。

配对后目录“协作房间”直接列出电脑上的房间，与在电脑上看到的一致，可以发消息、上传附件、管理成员、导出备份，并实时更新。对话只保存在电脑上，网站只转交加密内容。

- 电脑关机或 codiscuss 未运行时看不到房间，目录标题提示“电脑未连接”或“电脑离线”；电脑上线后页面自动连上。
- 电脑没有及时答复时，页面提示“结果待确认”，不会自动重发；请先查看房间确认是否已生效。

## API 接入

在“添加”行选择 **OpenAI**，翻开卡片填写 OpenAI 官方 API Key 并选择模型；已预填官方地址 `https://api.openai.com/v1` 和 Responses 协议。原有 Codex 卡片仍可选择 API 接入。

选择 **自定义 API** 可接入其他服务：翻开卡片填写 Base URL、API Key 和完整模型 ID，默认使用 Chat Completions，也可选择 Responses、Anthropic Messages 或 Gemini generateContent。卡片背面的“名称与描述”按钮可修改显示名称；重复点击添加可配置多个不同的 API 成员。Anthropic、Google Gemini、DeepSeek、阿里云百炼（Qwen）、xAI（Grok）也保留官方地址预设。

API 成员可以担任专家或主持人。房间指定了项目目录时，它可以用接入程序提供的文件工具读取、搜索项目文件；项目权限设为可写时还能新建和编辑文件，但没有命令行，不能运行测试或构建。`.env`、私钥等密钥文件、`.git` 目录和本机服务目录始终不开放，读到的内容会发给你配置的模型服务商。密钥只保存在本机，调用费用按你的账号计费。

## 智能调度（可选）

建房时在“智能调度”下选择供应商并填写密钥，需要连接本机服务。卡片下方的“判断方式”可选“引导（试验）”（默认，正在打磨）或“稳定”（已通过回归评测），影响未点名消息的分派和讨论中的插话、下一位发言、下一轮判断。作用见 [使用指南](workflow.md#智能调度)。

翻开成员卡片，“提示”一行可以给这位专家单独写几句要求，例如“回答先给结论”。它只发给这位专家，不改变权限；部分软件带有预设，可随时恢复。卡片背面的书签图标把这张卡片的描述、提示词、项目权限、模型与强度存为专家预设，之后在“添加”行一键加入，见 [使用指南](workflow.md#成员管理)。

## 工作流（可选）

工作流把一种多人协作的做法存下来，供别的房间复用：一份给主持人读的做法说明（SKILL.md），加一组 Agent 卡片（每张就是一个专家预设）。工作流在左侧“频道工具 → 工作流”页管理（没打开房间时也能用）：查看说明、接力顺序和成员卡片，新建、导入、编辑、删除都在这里。要在房间里用时，在输入框要求主持人启动（打 `/` 选工作流可以直接写好这句请求，权限见下文）；主持人此后按说明组织工作。它只带来做法和成员；没画流程时不保证工序，具体怎么做由主持人判断。你随时可以 @ 任何成员。

- **内置工作流**：安装包自带“小说剧本连载”（`story-serial`：编剧、写手、两位批评家与记录员逐集接力，附项目模板与状态检查脚本，脚本需要 Python 的 PyYAML）。默认不安装。在终端里运行 `codiscuss setup` 时，选完软件后有一步“安装配置”：先显示概览，按 → 展开，用空格勾选要装的工作流，回车继续；不勾就不装。也可以直接加 `--workflows` 安装全部（`install` 同样适用，非交互运行只认这个选项）。装的时候，已有同名的会覆盖为包里的最新版，原来那份先备份到服务目录的 `backups/workflows/`。选择只对这一次有效，不会记住，不选就不动工作流库。
- **保存**：在“工作流”页点列表上方的 +，选“新建”，或导入别人分享的 zip 或文件夹（手机、平板上同样可用）。导入的内容先放上画布预览，点“保存”才写入。复制文件夹路径和删除工作流在说明抽屉底部。编辑页可以“从当前房间成员导入”卡片，提示词保持原文。想让主持人起草，打开下面的“主持人完整权限”。
- **流程画布**：“工作流”页左边是工作流列表，其余整块就是选中工作流的画布。每位成员是一张小卡（序号、头像、名称、模型与权限），拖动即可移动；单击打开右侧的专家卡片，翻面设置或 × 删除。左上“成员”添加卡片（平台、预设，或当前房间的成员），“检查点”添加主持人检查点；也可以从卡片右侧的圆点拖线到空白处，就地选要加的成员并自动连上。名称在右上角直接改，Ctrl+S 保存。从「开始」右侧的圆点拖线连到卡片，排出谁先谁后；同一列并排的几张（由同一张交来、交给同一张）同时做；检查点放在两棒之间，前一棒做完先交回主持人把关；从后面连回前面的卡片就是循环（金色虚线），走到这里交回主持人，要返工就从连回的那张再来一圈，通过就往下走。底部的胶囊实时显示排出的顺序，排不成接力时变红说明原因。描述和做法说明在右上的说明图标里。主持人按这个工作流派活时照画布交接，程序负责一棒接一棒、检查点和循环；没连线时仍由主持人按做法说明组织。暂不支持按条件分支，需要判断的地方放检查点。
- **让主持人自己建**：建房时（第 3 节“协作方式”）或在“成员与设置 → 协作设置”勾选“主持人完整权限”后，直接对主持人说要什么分工（或“把这个房间的做法存成工作流”），它会自己保存、在本房间启用，并邀请工作流里的成员，接着就按流程派活，不需要你导入或添加成员。之后让它改流程，改动从成员下一次执行起生效。打开这个开关后，也可以在输入框输入 `/` 选一个已保存的工作流，输入框里会写好“启用工作流「名称」（ID），”，补上要做的事发给主持人，它就启用这个工作流并带来成员（没打开时该项灰显）。主持人带来的成员项目权限最高为可写；只有本地软件担任的主持人能这样做，API 主持人不行。
- **主持人完整权限的其他控制**：同一个开关打开后，主持人会自己处理房间里的问题、持续推进：成员跑偏时插话、卡住时打断或重试、模型不可用时换模型、无法恢复时换人；你也可以直接说“停下写手”“全部停下”“下一个让批评家先说”“请一位 Codex 进来只读评审”“把记录员请出去”“开个 Goal 把剩下几集写完”“暂停讨论”。邀请只用本机已配置的软件，项目权限最高可写；它自己开的 Goal 用你的默认预算（不限时为 8 次续跑、90 分钟）。成员连续 10 分钟没有新输出时，系统会提醒主持人检查；主持人派出长任务时还可以给自己设定时检查（每 5–120 分钟一次，房间空闲后自动结束）。它也能撤回自己派出的活，正在循环的接力会立即停下。以下仍由你决定：对主持人自己操作或更换主持人、批准超出上限的轮数、高于可写的权限或放行工具、改项目目录、撤回你的消息、私聊。API 主持人没有命令行，不能这样做。
- **分享**：工作流存在本机服务目录的 `workflows` 文件夹，一个工作流一个文件夹；编辑页可复制路径，把整个文件夹（或打成 zip）发给对方即可分享。导入时会列出每张卡片的提示词和项目权限；要求写文件的卡片默认按只读导入，逐张勾选后才放开。
- **给 API 成员登记命令**：以 API 方式加入的成员没有命令行。工作流文件夹里放一个 `commands.json`（写法见 `workflow-creator` 技能），登记它们能运行的命令（例如检查脚本，脚本也放在工作流文件夹里），随工作流一起分享；启用后 API 成员只能按名字运行这些命令，改不了命令行，只读成员只能运行标为只读的命令。命令以你的身份在本机运行，所以导入别人的工作流时，编辑页会列出每条完整命令，勾选“允许这些命令在本机运行”才会带上；主持人起草或修改工作流时不能增删命令。
- **修改与结束**：修改工作流会作用于所有启用它的房间，成员下一次执行就按新内容；新增的卡片不会自动进入房间，主持人用到时会自己补上，也可以在右栏工作流一行点刷新图标立即补齐（删掉的卡片，其成员留作普通成员；与库一致时不显示该图标）；工作流卡片的提示词只读，在“工作流”页的画布上修改。工作流进行中时，主持人只在请求和它的用途相符（或你说按工作流做）时才用，其他请求照常处理。用完在“成员与设置 → 协作设置”的工作流一行点请离成员图标（或逐个让成员离开）：工作流带来的成员离开（主持人保留），正在进行的工作随之停止，工作流结束，右栏这一块消失；成员会话保留，下次在输入框打 `/` 选它就把原成员请回来，接着原来的上下文。换工作流时直接选另一个，原来的成员留作普通成员。

## 朗读与语音输入（可选）

朗读可在网页“设置”的“语音”里切换服务：火山引擎（豆包语音合成 2.0）、阿里云百炼（CosyVoice）或 Azure（神经语音，另填语音资源所在区域）。在所选服务的控制台获取 API Key 填进去；每个服务的 Key 与音色分开保存，切回时仍在。语音输入固定用火山引擎「录音文件识别2.0」，朗读用其他服务时需另填火山引擎的 Key。朗读可设一个通用音色，并按 AI 平台（Claude、Codex、Gemini 等）分别配音色，朗读项目文件也可单独配一个音色，没配的平台、你自己的消息、程序消息和文件用通用音色；还可选语速；火山引擎还可改语气提示（默认是“像给朋友讲故事一样”的自然语气）。密钥只保存在本机，费用按你的账号计费。

- 朗读：每条消息的工具栏有“朗读”（手机上在“…”菜单里），在消息里选中文字后点“听当前”从选中处开始；读完这条会接着读后面的消息直到最新，点输入框右下角的播报按钮开启语音播报：之后的新回复会自动朗读回答摘要（没写摘要的短回答读全文，长回答读第一段），主持人的发言会报“主持人”；讨论中还会提示新一轮的发言顺序和轮到谁，执行失败、操作待你允许和讨论结束也会播一句。同时到达的回复依次播报，积压较多时只播最新 3 条。锁屏或切到其他 App 时继续播放，锁屏界面和耳机按键可以暂停、继续、跳到下一条；读过的段落会缓存在电脑上，重听不再计费。正在读的句子会高亮，点一下高亮的句子暂停，再点继续；代码块跳过。朗读时消息区底部有“跟随”和“退出”：页面默认不随朗读滚动，点“跟随”后才把正在读的句子保持在视野内，手动滚动一下就取消跟随。
- 朗读文件：在“文件”里打开 Markdown 文件，预览模式下标题栏有“朗读”，从正文开头读到文件末尾（文件头的 `---` 元数据不读）；选中文字后可从选中处开始。暂停、跟随、退出与消息朗读相同；收起为悬浮窗时继续朗读，切到源码、换文件或关闭预览（含悬浮窗上的关闭）即停止。
- 语音输入：点输入框右下角的麦克风开始说话，再点一次转成文字插入输入框，单次最长 5 分钟。浏览器会先请求麦克风权限。

两者都由本机服务调用语音服务，手机等其他设备经已配对电脑使用，电脑关机时不可用。

## 权限

项目权限按程序启动的 CLI 与 API 成员设置，默认只读；可选只读、可写、自动、全放开，软件不支持的档位灰显（agy 后台不支持自动，API 只有只读和可写）。只读档预先放行读写房间的 `codiscuss` 命令和答案草稿，可写档允许修改项目、运行命令；自动档由软件审核操作，全放开跳过权限确认。具体范围见档位的悬停说明。Codex 使用原生沙箱，agy 使用独立项目规则，Claude Code 中你已有的授权仍然生效；手动启动成员的权限沿用原会话设置。

## 常驻讨论服务

`codiscuss local open` 会同时启动讨论服务。一个服务托管所有房间；停止服务会暂停它托管的讨论。

| 操作 | 命令 |
| --- | --- |
| 打开本机网站 | `codiscuss local open` |
| 查看状态 | `codiscuss local status` |
| 停止 | `codiscuss local stop` |
| 重启讨论服务（使新环境变量生效；Windows 上读取系统设置或 `setx` 保存的最新值，在旧终端执行也可，PATH 除外） | `codiscuss service restart` |
| 登录时自动启动（Windows） | `codiscuss service autostart on` |

## 命令行

主持人可用 `codiscuss review roster ROOM` 查看本机服务上报的只读评审候选，当前限程序启动的 Codex CLI。此命令只读配置事实，不会自动派发评审；已有授权仍须在实际投递时核对。

读取后，派实现任务可携带 `--next-review NAME --review-scope 范围 --review-roster REVISION`，将下一步评审绑定本批次；评审者不能同时是本批实现者。批次完成后，主持人先用 `review ready ROOM --batch ID` 核对完整交付，再用 `review advance ROOM --batch ID --revision REV --submission-id UUID --as 本人` 推进既定评审；不能推进时会说明原因。开启智能调度后可代办这一步；没有配置、判断失败或把握不足时仍交主持人。

`codiscuss` 同时供 AI 读写房间。`codiscuss --help` 列出全部命令，`codiscuss schema <命令>` 显示字段，都可离线使用。

讨论与普通协作统一读取请求并提交回答。成员回答使用 `message post --kind chat`，自动任务绑定 `--execution`，手动回答绑定 `--request`；主持人先读 `turn roster`，再带返回的 revision 创建或继续安排。讨论开关先用 `run view` 读取 revision，再执行开始、暂停、继续或结束；具体字段以命令帮助和房间协议为准。主持任务附有调度建议时，可用 `state decision ROOM DECISION_ID` 读取对应原判断；建议注明未生效时仍由主持人自行决定。

## 常见问题

- **软件送达失败**：查看成员状态与原位失败卡，在对应软件中处理登录或权限；倒计时期间可以立即重试或停止。本机接入程序重启或异常退出、导致进行中的软件进程随之结束时，同样自动重新投递同一执行，间隔缩短为 5 秒。三次重试用尽后，讨论专家的失败交给主持人处理；也可跳过本次发言。
- **Codex 提示会话被占用**：原聊天仍被 Codex App 占用，可在进度看板切换到 App 接入。
- **Windows 报告两处数据路径**：从普通终端管理服务，或设置环境变量 `DISCUSS_SERVICE_HOME`。
- **结果不明**：已交付但无法确认的任务不会自动重发，请先在原会话与房间中核对。
