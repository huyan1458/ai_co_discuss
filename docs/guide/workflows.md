# 工作流

把一套稳定的多人分工保存为工作流，在任意房间一键复用；既可以用安装包自带的内置工作流，也可以用 `workflow-creator` 技能新建或修改自己的流程。

## 怎么操作

### 1. 安装与补装内置工作流

共议（AI CoDiscuss）安装包自带三套内置工作流，默认不安装：

- **小说连载**（`story-serial`）：编剧、写手、两位批评家与记录员逐集接力，另有一位读者按需读正文（附模板与检查脚本，脚本需 Python 的 PyYAML）。
- **决策会审**（`decision-council`）：反方、局外人、另辟选项、执行者先各自独立作答，再围绕分歧交锋，最后由主持人综合建议。
- **经典跑团（龙与地下城式）**（`trpg-classic`）：一位地下城主加三位 AI 玩家，附规则速查、原创冒险与掷骰脚本（脚本需 Python）。

**首次安装或事后补装**：

- 交互式安装：运行 `codiscuss setup`，选完软件后在“安装配置”一步按 `→` 展开“随包工作流”，用空格勾选要装的工作流，回车继续。
- 命令行一次补装全部：运行 `codiscuss setup --workflows`（或 `codiscuss install --workflows`）。

**重跑会不会覆盖已有工作流**：会覆盖**同名**内置工作流为包里的最新版，但覆盖前会先把你原来的那份备份到本机服务目录的 `backups/workflows/` 下；你自建的不同名工作流不会被改动，其他软件与站点配置也不会被清空。工作流勾选只在当次生效，不会记住。

### 2. 在房间里启用、刷新与停用工作流

1. **授权主持人启用工作流**：建房时在“协作方式（可选）”，或建房后在顶部“房间”页 → “成员与设置” → “协作设置”勾选“主持人完整权限”。打开后，主持人才能直接帮你启用工作流并把工作流里的成员请进房间。
2. **启用工作流**：在房间输入框输入 `/`，从菜单选择已保存的工作流（输入框会填入 `/工作流ID`），补上这次要做的事发送给主持人。主持人会启用工作流，并按工作流里的角色卡片把对应成员请进房间，然后按流程派活。
   - **成员卡片与角色对应**：主工作流里的每张卡片对应一个角色（含分工描述、专属提示词、软件、模型、强度和项目权限），启用时主持人按卡片加入缺少的成员，已绑定且在场的成员沿用原身份，已离开的请回。子工作流的角色在用到时加入。工作流卡片的提示词在房间里只读，需要改时在左栏“工作流”页修改。
3. **补齐新增角色**：如果后来在工作流里加了新卡片，已启用它的房间不会自动加人；主持人用到时会自己补上，你也可以在右栏工作流一行点刷新图标立即补齐。
4. **使用子工作流**：工作流运行中，在输入框打 `/` 会多出“工作流「名称」的子工作流”分组，选一项发给主持人即按子流程处理；用完相关成员会被设为离开，会话保留。
5. **停用与请离**：在顶部“房间”页 → “成员与设置” → “协作设置”的工作流一行点请离成员图标，工作流带来的成员会离开（主持人保留），进行中的工作随之停止，工作流结束。成员会话仍保留，下次再选该工作流会把原成员请回。若要在库里全局停用某个工作流，点左栏“工作流”列表项右侧“…” → “停用”。

### 3. 用 `workflow-creator` 新建或修改工作流

你既可以在左栏“工作流”点“+”手动新建或导入 `.zip`/文件夹，也可以直接让 AI 用随包安装的 `workflow-creator` 技能帮你起草和校验：

- **在房间里让主持人建**：打开“主持人完整权限”后，直接对主持人说你要什么分工（或说“把这个房间的做法存成工作流”），也可以在输入框打 `/` 选平台技能里的“新建 / 修改工作流”。主持人会调用 `workflow-creator` 生成 `SKILL.md`、角色卡片与画布，校验通过后保存并启用。
- **在外部 AI 对话里建**：在任意已装好共议技能的 Claude Code / Codex 窗口，请它按 `workflow-creator` 技能为你新建或修改工作流。它先用 `codiscuss launch workflow-check --dir <目录>` 校验，待你确认后用 `codiscuss launch workflow-save --dir <目录>` 保存。库里已有同 ID 的工作流时，须明确选择覆盖（`--overwrite`）或带上读取时的修订号（`--revision`），否则不会保存。
- **存在哪里**：所有工作流都保存在本机服务目录的 `workflows/` 文件夹下（默认 `~/.codiscuss/workflows/<工作流ID>/`），一个工作流一个文件夹。在左栏工作流列表点“…” → “导出”，把这个工作流下载成一个压缩包（`<工作流ID>.zip`，里面是整个文件夹），可以分享给别人，对方在工作流页“+”里导入；不是文本或太大的文件不会放进去，导出后会提示。

### 4. 画布与 `SKILL.md` 的分工

在左栏“工作流”列表点一项，中间打开流程画布，右侧显示它的 `SKILL.md`（点“编辑”可修改，点“保存”或 `Ctrl+S` 保存。工作流在你打开之后被别处改过时，保存会被拒绝，页面提示“工作流已被修改，请重新载入”，点“重新载入”读取新版，未保存的修改会先询问是否放弃；导入的工作流和库里已有的同 ID 时，要点“覆盖保存”才会整份替换）：

- **画布只帮你看懂**：你可以拖动卡片、添加主持人节点、用户节点（示意需要你介入、确认或发言的位置）和条件分支节点（按条件分成多条执行分支，每个分支各有独立的右侧连线圆点，选中后可增删和重命名分支）、从节点右侧圆点拖线表示先后、并行多路或循环（金色虚线表示循环）、写连线说明，或点“自动整理”。连线和说明要先单击选中才能编辑；选中金色循环线后，按住它上下拖动可调整高度。没选中时，在连线或说明上拖动只会平移画布。**程序不执行画布连线，主持人也看不到画布。**
- **主持人按 `SKILL.md` 派活**：谁先谁后、哪些成员并行、什么时候交回主持人把关、什么条件返工，都由 `SKILL.md` 写明并由主持人照做。用 `workflow-creator` 生成或修改工作流时，AI 会按 `SKILL.md` 同步更新画布。
- **步骤分组与挂靠**：画布可以把节点分成几个步骤，显示为带名字的虚线框，框上标出挂在这一步的子工作流。步骤和挂靠写在 `flow.json` 与子工作流的 `SKILL.md` 里（由 `workflow-creator` 维护），和画布一样只是示意，主持人仍按 `SKILL.md` 判断这一步用不用。
- **一张卡片请多位成员**：同一张卡片可以由主持人按不同显示名请进多位成员，例如每位人物一位成员；显示名只在本房间有效，同一个名字请回的是原来那位成员和它的会话。
- **带技能的专家**：工作流里的专家可以是一个文件夹而不是一个文件：`agents/<卡片ID>/` 里放定义 `<卡片ID>.md`（和普通卡片文件同一格式）和 `skills/<技能名>/`，每条技能一份 `SKILL.md` 加 `references/`。担任这张卡片的成员可以读写自己的 skills，工作流的其他部分照旧只读；他写技能不改变工作流的修订号，网页和命令行的普通保存都原样保留这些技能，只有整份覆盖和导入会用文件夹里带的替换。导出这位专家得到的就是这个文件夹。“专家配置”是一个大弹窗：左边列出所有卡片，右边分“基础”“提示词”“技能”三个标签页；基础和提示词改完点弹窗底部的“保存”写入工作流（和工作流页的“保存”是同一次保存），技能文件逐个保存。手机上先在列表里选专家，再进入他的配置，左上角返回。带技能的专家不论在主线还是子工作流，都归在“顾问”一组，条目上标着他属于哪里；选中后切到“技能”，左边是技能和文件，右边编辑选中的文件（手机上逐层进入），可以查看和修改每条技能的 SKILL.md 和资料，新建、删除技能和资料文件。这些修改直接写进专家的文件夹，不用保存工作流，也不改工作流的修订号；专家同时改过的文件会拒绝保存并提示重新载入，不会被覆盖。普通专家在“技能”标签页写下第一条技能的名字和描述，点“添加技能”，保存工作流后它就变成带技能的文件夹。列表下方的“导入专家包”把一个 md、压缩包或文件夹放进主线或画布当前所在的子工作流。删掉一位带技能的专家、整份覆盖替换了技能、删除整个工作流时，原来的文件夹会先备份到服务目录的 backups 下。命令行 `codiscuss launch expert-import --from <路径> --workflow <ID> [--sub <子工作流ID>]` 把专家包放进工作流，卡片 ID 已存在时拒绝。面板上的专家各有一份技能，在本机服务目录 `experts/<ID>/skills/`，和工作流里的不共用；在“专家配置”里把卡片“存为面板预设”时会复制过去，同名预设已存在时要点“覆盖同名预设”才会替换；本机已有这位专家的技能时默认保留，提示后可点“用工作流里的技能替换本机的”。新建房间面板上，带技能的预设专家（顾问）卡片背面和其他专家一样只放基础配置，另有一个“高级配置”按钮，打开和工作流同一个配置弹窗，查看和修改的是本机服务目录里的那份技能。网页上，新建房间面板“添加 AI”下方的“导入导出专家”可以导入 .md、压缩包或文件夹，也可以导出任一预设；工作流“专家配置”里的“导出”导出当前卡片（已保存的版本）。没有技能下载一个 md，有技能下载一个压缩包。导入时同名预设会让你选“覆盖”或“取消”；本机已有这位专家的技能时默认保留本机的，可选“用导入的替换（原来的会备份）”；被忽略的文件和被降为只读的权限会在提示里列出。命令行同样可以：`codiscuss launch expert-export` 导出，`codiscuss launch expert-import` 导入成面板预设；同名预设和已有的技能都不会被静默替换。专家带着的软件本机没有配置，或者本机这个软件的模型列表里没有他写的模型时，导入照样成功，提示里会说明；这时面板上的按钮变灰（软件）或卡片上标出“本机没有……，不能调用”（模型），建房和请进都会被拒，配好软件、或把模型改成列表里的（留空即用软件默认）之后恢复。是否“没有”只看本机已经读到的模型列表：还没读过列表、读取失败或没写模型都不算；Claude 的列表只是它的模型选单，不据此拦。

### 5. “主持人完整权限”与工作流的关系

- 打开“主持人完整权限”后，主持人不仅能自己保存、修改和启用工作流、邀请工作流所需成员（项目权限最高可写），还能在推进中自行插话、打断或重试成员、换模型、调发言顺序、撤回自己派出的活、开启讨论或 Goal，以及给自己设定时检查。
- 没有打开该开关时，输入框 `/` 菜单里的工作流项灰显，主持人不能自行邀请成员或启用工作流；你只能自己把成员请进房间，再把做法告诉主持人。
- 通过输入框启用新工作流，需要一位由本机服务唤醒的主持人。API 主持人能够读取已启用工作流的说明和角色名单。

## 要注意什么

- **改一次作用于全部房间**：修改并保存工作流后，已启用它的房间在下一次执行时读取最新流程说明与角色提示词。已有成员的模型、强度和权限仍取房间设置。
- **导入别人工作流时的安全检查**：导入 `.zip` 或文件夹时会先上画布预览，要求写文件的卡片默认按只读导入，需你逐张勾选才放开；若工作流包含给只读 API 成员登记本机命令的 `commands.json`，编辑页会列出完整命令，勾选“允许这些命令在本机运行”才会生效。主持人起草或修改工作流时不能增删本机命令。
- **只放开一部分**：展开“主持人完整权限”下的“具体权限”，按项勾选：“处理执行问题”“调整成员配置”“改项目权限”“管理成员名单”“推进方式”“工作流”“新建房间”。主持人保存和启用工作流需要其中的“工作流”；没勾选的操作会被拒绝，并告诉主持人缺哪一项。
- **仍由你掌控的边界**：即使开了“主持人完整权限”，更换主持人、批准超出上限的轮数、高于可写的权限档、改项目目录、撤回你的消息和私聊仍只由你决定。
