# 工作流

把一套稳定的多人分工保存为工作流，在任意房间一键复用；既可以用安装包自带的内置工作流，也可以用 `workflow-creator` 技能新建或修改自己的流程。

## 怎么操作

### 1. 安装与补装内置工作流

共议（AI CoDiscuss）安装包自带三套内置工作流，默认不安装：

- **小说连载**（`story-serial`）：编剧、写手、两位批评家与记录员逐集接力，另有一位读者按需读正文（附模板与检查脚本，脚本需 Python 的 PyYAML）。
- **决策会审**（`decision-council`）：反方、局外人、另辟选项、执行者先各自独立作答，再围绕分歧交锋，最后由主持人综合建议。
- **经典跑团（龙与地下城式）**（`trpg-classic`）：一位地下城主加三位 AI 玩家，附规则速查、原创冒险与掷骰脚本（脚本需 Python）。

**首次安装或事后补装**：

- 交互式安装：运行 `codiscuss setup`，选完软件后在“安装配置”一步按 `→` 展开“随包工作流”，用空格勾选要装的工作流，回车继续。
- 命令行一次补装全部：运行 `codiscuss setup --workflows`（或 `codiscuss install --workflows`）。

**重跑会不会覆盖已有工作流**：会覆盖**同名**内置工作流为包里的最新版，但覆盖前会先把你原来的那份备份到本机服务目录的 `backups/workflows/` 下；你自建的不同名工作流不会被改动，其他软件与站点配置也不会被清空。工作流勾选只在当次生效，不会记住。

### 2. 在房间里启用、刷新与停用工作流

1. **授权主持人启用工作流**：建房时在“协作方式（可选）”，或建房后在左栏“房间”页 → “成员与设置” → “协作设置”勾选“主持人完整权限”。打开后，主持人才能直接帮你启用工作流并把工作流里的成员请进房间。
2. **启用工作流**：在房间输入框输入 `/`，从菜单选择已保存的工作流（输入框会填入 `/工作流ID`），补上这次要做的事发送给主持人。主持人会启用工作流，并按工作流里的角色卡片把对应成员请进房间，然后按流程派活。
   - **成员卡片与角色对应**：主工作流里的每张卡片对应一个角色（含分工描述、专属提示词、软件、模型、强度和项目权限），启用时主持人按卡片加入缺少的成员，已绑定且在场的成员沿用原身份，已离开的请回。子工作流的角色在用到时加入。工作流卡片的提示词在房间里只读，需要改时在左栏“工作流”页修改。
3. **补齐新增角色**：如果后来在工作流里加了新卡片，已启用它的房间不会自动加人；主持人用到时会自己补上，你也可以在右栏工作流一行点刷新图标立即补齐。
4. **使用子工作流**：工作流运行中，在输入框打 `/` 会多出“工作流「名称」的子工作流”分组，选一项发给主持人即按子流程处理；用完相关成员会被设为离开，会话保留。
5. **停用与请离**：在左栏“房间”页 → “成员与设置” → “协作设置”的工作流一行点请离成员图标，工作流带来的成员会离开（主持人保留），进行中的工作随之停止，工作流结束。成员会话仍保留，下次再选该工作流会把原成员请回。若要在库里全局停用某个工作流，点左栏“工作流”列表项右侧“…” → “停用”。

### 3. 用 `workflow-creator` 新建或修改工作流

你既可以在左栏“工作流”点“+”手动新建或导入 `.zip`/文件夹，也可以直接让 AI 用随包安装的 `workflow-creator` 技能帮你起草和校验：

- **在房间里让主持人建**：打开“主持人完整权限”后，直接对主持人说你要什么分工（或说“把这个房间的做法存成工作流”），也可以在输入框打 `/` 选平台技能里的“新建 / 修改工作流”。主持人会调用 `workflow-creator` 生成 `SKILL.md`、角色卡片与画布，校验通过后保存并启用。
- **在外部 AI 对话里建**：在任意已装好共议技能的 Claude Code / Codex 窗口，请它按 `workflow-creator` 技能为你新建或修改工作流。它先用 `codiscuss launch workflow-check --dir <目录>` 校验，待你确认后用 `codiscuss launch workflow-save --dir <目录>` 保存。同 ID 会覆盖已有工作流。
- **存在哪里**：所有工作流都保存在本机服务目录的 `workflows/` 文件夹下（默认 `~/.codiscuss/workflows/<工作流ID>/`），一个工作流一个文件夹。在左栏工作流列表点“…” → “复制文件夹路径”可直接定位文件夹并打包分享给别人。

### 4. 画布与 `SKILL.md` 的分工

在左栏“工作流”列表点一项，中间打开流程画布，右侧显示它的 `SKILL.md`（点“编辑”可修改，点“保存”或 `Ctrl+S` 保存）：

- **画布只帮你看懂**：你可以拖动卡片、添加主持人节点、从节点右侧圆点拖线表示先后或循环（金色虚线表示循环）、写连线说明，或点“自动整理”。**程序不执行画布连线，主持人也看不到画布。**
- **主持人按 `SKILL.md` 派活**：谁先谁后、哪些成员并行、什么时候交回主持人把关、什么条件返工，都由 `SKILL.md` 写明并由主持人照做。用 `workflow-creator` 生成或修改工作流时，AI 会按 `SKILL.md` 同步更新画布。

### 5. “主持人完整权限”与工作流的关系

- 打开“主持人完整权限”后，主持人不仅能自己保存、修改和启用工作流、邀请工作流所需成员（项目权限最高可写），还能在推进中自行插话、打断或重试成员、换模型、调发言顺序、撤回自己派出的活、开启讨论或 Goal，以及给自己设定时检查。
- 没有打开该开关时，输入框 `/` 菜单里的工作流项灰显，主持人不能自行邀请成员或启用工作流；你只能自己把成员请进房间，再把做法告诉主持人。
- 通过输入框启用新工作流，需要一位由本机服务唤醒的主持人。API 主持人能够读取已启用工作流的说明和角色名单。

## 要注意什么

- **改一次作用于全部房间**：修改并保存工作流后，已启用它的房间在下一次执行时读取最新流程说明与角色提示词。已有成员的模型、强度和权限仍取房间设置。
- **导入别人工作流时的安全检查**：导入 `.zip` 或文件夹时会先上画布预览，要求写文件的卡片默认按只读导入，需你逐张勾选才放开；若工作流包含给只读 API 成员登记本机命令的 `commands.json`，编辑页会列出完整命令，勾选“允许这些命令在本机运行”才会生效。主持人起草或修改工作流时不能增删本机命令。
- **仍由你掌控的边界**：即使开了“主持人完整权限”，更换主持人、批准超出上限的轮数、高于可写的权限档、改项目目录、撤回你的消息和私聊仍只由你决定。
