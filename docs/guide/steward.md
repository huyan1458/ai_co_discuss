# 平台主理人

平台主理人是处理平台事务的本机 AI。它的专用对话保留历次请求和回答，不绑定任何项目房间。它不会加入项目房间或代替主持人派活，专用对话也不出现在项目房间目录里或计入房间统计。

## 怎么操作

1. 首次使用前，须在“设置 → 平台主理人”选择要使用的 AI 软件，系统不会代选。也可在这里设置模型、强度、项目权限、工作目录和允许使用的技能。
2. 点左侧栏底部的“平台主理人”打开对话，直接打字提需求，例如“帮我安装本机朗读”。不必填写技能名，主理人会按需读取已获准且可用的技能。要处理某个房间的事务，可以在消息里写明房间链接或编号。也可以从对应页面发起请求。
   - **分析派活**：在“统计”的“主持人调度得怎样”一节点“AI 分析”。只有 `dispatch-analysis` 技能可用且获准使用时才显示。分析仅手动触发，结果单独呈现，不会改写统计数字。
   - **制作房间分享卡**：在目标房间的菜单选择“分享 → AI 制作分享卡”。请求会附上目标房间，供主理人取材。
   - **安装本机语音**：在“设置 → 语音”，从尚未安装的本机朗读或本机语音输入一项点“让平台主理人安装”。安装会改动运行本机服务的电脑，每次都要先确认。
   - **配置通知**：在“设置 → 通知”点“让平台主理人配置”并确认。主理人可能更改本机通知设置，渠道凭据由你在通知设置里填写。
   - **部署或更新自己的线上站点**：在设置的设备配对区域点“让平台主理人部署”。没有源码时，主理人会先问你是否克隆与本机版本对应的源码。它会在每次写入 Cloudflare 前列出资源和命令，等你确认。见[部署指南](../deployment.md)。
   - **盘点共议占用**：在管理面板“存储”点“让平台主理人分析占用”，或运行 `codiscuss admin storage analyze`。范围是成员草稿、运行日志、工作流备份、房间附件和本机语音模型，不包括整个磁盘。默认只盘点，清理前须逐项确认。
3. 发出请求后，点右下角提示里的“打开平台主理人”，或从侧栏进入，查看进度和结果。可在对话里查看执行详情、停止或重试。

## 要注意什么

- 主理人技能随包提供，由平台主理人按请求加载，不安装到你的 AI 软件。除了网页上的入口，也可以通过命令行请求整理讨论报告或盘点草稿。项目目录、权限和允许的技能由你设置。
- 更换主理人软件后，旧对话随旧房间存档，下次打开主理人或发起请求时会新建对话。在“设置 → 平台主理人”的“旧对话”可点“打开”只读查看，或点“删除”并确认后永久删除。也可运行 `codiscuss steward history` 列出，或用 `codiscuss steward delete ROOM --confirm` 删除指定旧对话。
- 保存过允许的技能清单后，升级新增的主理人技能不会自动获准。需要使用时，在“设置 → 平台主理人”手动勾选。
- 在线上站点或已配对的手机、平板上操作时，请求仍由已配对电脑执行。电脑上的本机服务需要保持运行。
- 使用命令行时，见[命令行](cli.md#平台主理人)。
