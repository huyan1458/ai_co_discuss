# MOSS

MOSS（原“平台主理人”）是处理平台事务的本机 AI。它能回答共议用法和各项目房间的状态。专用对话保留历次请求和回答，不绑定项目房间。

## 怎么操作

1. 侧栏顶部依次是“新建房间”“MOSS”“工作流”“统计”。点“MOSS”，首次使用时选一个 AI 软件，再点“开始对话”。首次创建对话后，如果允许“房间总览”技能，MOSS 会先概述项目房间、需要你处理的事项和可核实的配置缺项。
2. 在对话里直接打字。你可以问“哪些房间等我处理”或“这个执行为什么失败”。房间概览附房间链接和对应编号，排障只读取手册、事件记录、执行详情和相关日志。要处理某个房间的事务，可以写明房间链接或编号，也可以从对应页面发起请求。
   - **分析派活**：在“统计”的“主持人调度得怎样”一节点“AI 分析”。只有 `dispatch-analysis` 技能可用且获准使用时才显示。分析仅手动触发，结果单独呈现，不会改写统计数字。
   - **制作房间分享卡**：在目标房间的菜单选择“分享 → AI 制作分享卡”。请求会附上目标房间，供主理人取材。
   - **安装本机语音**：在“设置 → 语音”，从尚未安装的本机朗读或本机语音输入一项点“让 MOSS 安装”。安装会改动运行本机服务的电脑，每次都要先确认。
   - **配置通知**：在“设置 → 通知”点“让 MOSS 配置”并确认。MOSS 可能更改本机通知设置，渠道凭据由你在通知设置里填写。
   - **部署或更新自己的线上站点**：在设置的设备配对区域点“让 MOSS 部署”。没有源码时，MOSS 会先问你是否克隆与本机版本对应的源码。它会在每次写入 Cloudflare 前列出资源和命令，等你确认。见[部署指南](../deployment.md)。
   - **盘点共议占用**：在管理面板“存储”点“让 MOSS 分析占用”，或运行 `codiscuss admin storage analyze`。范围是成员草稿、运行日志、工作流备份、房间附件和本机语音模型，不包括整个磁盘。默认只盘点，清理前须逐项确认。
3. 发出请求后，从右下角通知的“打开 MOSS”或侧栏进入对话，查看进度和结果。可在对话里查看 MOSS 自己的执行详情、停止或重试。

## MOSS 在哪里处理任务

MOSS 自动决定在哪里办，不会先问你是否要分房。安装、配置、查状态等平台事务留在主对话。需要改项目文件或多位 AI 协作时，先交给合适的已有项目房间，没有才新建。其他事项，你说“开个任务”或“后台做完回我”，MOSS 就直接开单成员任务房间。没明说时，只有既要独立成品、又要重新查找并交叉核对多份原始材料，才会开任务房间。拿不准时就在主对话办。分出去后，MOSS 会给出房间链接。想收回任务，告诉它“在这里做”。

- 项目房间沿用你在“新建房间”保存的主持人、成员和主持人权限。成员项目权限未设置时用只读，最高为“可写”。默认值为“自动”或“全放开”时都按“可写”处理。新房间的主持人不能再建房。要用项目目录，先把项目加入“常用项目”，再告诉 MOSS 用哪一个。不指定时仍是项目房间，只是使用草稿工作区。任务房间在目录中标为“任务”，固定用与 MOSS 同软件、同模型的单成员新会话，只能写草稿工作区，没有主持人权限。
- 可以在建房时告诉 MOSS 把房间放进哪个已有文件夹。归属明确时，MOSS 也可以选用已有文件夹。拿不准时就放在“未归类”，不会按项目目录自动归类。建好后，MOSS 会告诉你房间放在哪里。
- “MOSS 配置”里的“允许 MOSS 新建房间”默认开启。关闭后同时停用建房和跨房传话。命令行用 `codiscuss steward settings --create-rooms off` 关闭，用 `--create-rooms on` 恢复。
- MOSS 新建任务房间或项目房间不限数量，房间由你手动存档，不会在工作交付后自动存档。你也可以明确请 MOSS 存档由它创建的子房间。其他房间的存档、执行控制、成员调整和用户消息操作在对应房间处理。
- 要清理列表，在右栏“派出的工作”中点对应房间的存档按钮并确认。已存档的房间默认隐藏，可以用“显示已存档”查看。
- 从 MOSS 右栏打开“设置”，在“新建房间”一节编辑“MOSS 建房时的成员”，点“保存”后对之后新建的项目房间生效。已配对的手机或平板也能修改，设置保存在运行 MOSS 的电脑上。

MOSS 发给自己子房间的任务显示在发送卡上。“已完成”表示子房间已交回结果，卡上会补上摘要。MOSS 每轮都验收，合格后才在主对话简短汇报。要求返工时，原卡回到进行中，随后显示新结果。子房间需要决定时先问 MOSS，卡片显示“等 MOSS 决定”。超出授权才由 MOSS 在主对话问你，再把答案传回。如果子房间已有提问卡在等你作答，任务卡显示“等你决定”，不会催报或标为未回报。

## 通过通知渠道联系 MOSS

选好 MOSS 软件后，在已绑定的通知渠道发一条新消息即可联系 MOSS。回答会发回同一个渠道，长回答附网页链接。引用某条通知回复仍回到那条通知所属的房间，引用 MOSS 的回答则回到 MOSS。

MOSS 忙时，新消息会排队。支持实时插话且当前请求也来自同一渠道时，可直接补充到正在进行的任务。MOSS 有提问在等你时，从网页或通知渠道发给它的新消息都会先排队。回答网页上的提问卡后，消息会继续按队列处理。要先处理某条消息，可以在该排队项上点“立即发送”。渠道消息不能代替网页作答或审批。

## 设置主动汇报

在“MOSS 配置”的“主动汇报”中打开“让 MOSS 主动汇报”并保存。开关默认关闭，每次唤醒 MOSS 汇报都会占用所选 AI 软件的订阅额度。“活跃时段”和“简报时间”默认分别为 09:00–22:00 和 21:00，按运行 MOSS 的电脑时间计算。

- 在对话里直接交代一项职责，例如“有房间等我回答时提醒我”。MOSS 记下后会复述。如果你交代的是“等我超过两小时就提醒我”这类按时长的职责，它会说明目前不能按时长触发。可以在“交代给 MOSS 的职责”中删除它。
- 只有开启主动汇报、已有职责且处于活跃时段，房间状态变动才可能触发汇报。出现等你回答的事项时优先汇报，新出现的失败和刚完成工作的房间则合并到简报。MOSS 忙时等它空闲，没有相关变化就不会生成简报。房间一直在等待时，单凭等待时长不会再次触发。
- 一条汇报不需要再看时，在该卡片点“这条不用告诉我”，写一句原因。MOSS 会据此略过同类提醒。在“已屏蔽的提醒”中可以移除这条记录。
- 如果 MOSS 被唤醒后核实没有符合职责、未被屏蔽且仍需你留意的事项，就直接结束，不发回复，也不留汇报卡片。已经发生的唤醒仍会用掉订阅额度。

## 要注意什么

- MOSS 头像区分待机、工作中和等你，悬停可见“MOSS 待机”“MOSS 正在工作”或“MOSS 在等你回答”。房间目录显示“等你回答”“执行失败”或“进行中”等状态。重新打开网页时仍默认进入上次的房间。
- MOSS 可读取同一站点的房间状态。安装、部署、清理和删除需要逐次确认。
- 在对话右栏点“设置”，可修改模型、强度、项目权限、“工作目录”和“允许的技能”。手机上从标题栏打开右栏抽屉。未设置过项目权限时默认为“只读”。保存技能清单后，升级新增的技能需要手动勾选。
- 只读时仍可使用“使用帮助与排障”。语音安装、通知配置、部署、占用盘点和讨论报告需要先调高权限。网页确认框有“调到自动并发送”时，先保存为“自动”再发请求。管理面板发起占用盘点时只提示到 MOSS“设置”先调高。命令行可运行 `codiscuss steward settings --access auto` 后重试。
- 权限高于只读时，右栏软件摘要醒目显示当前档位。用完点“改回只读”并确认，权限不会自动改回。
- 点软件卡片上的“更换软件”后，MOSS 在原对话中换用新软件，原消息和对话链接保留。忙时提示“MOSS 正在工作，换软件会在它空闲后生效”，当前执行继续。新软件从一个新的 AI 会话开始，显示名为“MOSS”。“旧对话”仍可查看过去已存档的对话，或确认后永久删除。命令行用 `codiscuss steward history` 和 `codiscuss steward delete ROOM --confirm`。
- 在右栏“换个新脑子”旁可以查看当前会话的上下文用量。要清掉当前 AI 会话的上下文，点“换个新脑子”并确认，或运行 `codiscuss steward renew`。软件、模型、房间记录、职责和设置保留。MOSS 正在执行时会先做完再换。
- 换软件和“换个新脑子”都在新会话实际开始时留下分隔线，标出新会话使用的软件。
- 在线上站点或已配对的手机、平板上操作时，请求仍由已配对电脑执行。电脑上的本机服务需要保持运行。
- 在“统计”的“MOSS”一节，可看新建任务房间和项目房间、委派给已有房间、返工、未回报、改回主对话，以及执行次数和时长。这里也会显示通知渠道发送的排队回执次数。
- 使用命令行时，见[命令行](cli.md#平台主理人)。
