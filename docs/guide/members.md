# 成员

管理房间里的成员：邀请本地软件或模型 API、续接已有会话、更换模型与权限、设置主持人，以及通过手动接入让已打开的本地 AI 对话加入房间。

在“房间”页可以连续调整多位成员。权限、模型和离开状态会先显示你的选择，保存失败时会提示原因并恢复。

## 邀请成员

### 怎么操作

1. **添加本地软件成员。** 新建房间时在“谁来参与” → “添加 AI”点已配置的平台；已有房间在右栏点“邀请 AI 加入”（或在顶部“房间”页 → “成员与设置” → “邀请 AI 加入”），选好成员后点“邀请”。同一平台可添加多位，各自保持独立会话。
2. **用角色预设加入成员**。在“添加 AI”下方从“预设”中选全局预设。建房时选定项目目录后，或向已有项目目录的房间邀请成员时，可从“项目预设”选择主项目或额外目录的预设。预设会带入描述、专属提示词、项目权限和模型，只能由程序启动（含续接历史会话），不能选“手动启动”。要删除可写位置中的预设，点行末的“管理”。
3. **添加模型 API 成员。** 在“添加 AI”里选 Claude、Gemini、DeepSeek、Qwen、Grok、OpenAI 或“自定义 API”。同一平台兼有本地软件和 API 时，翻到成员卡背面，在“接入”中选对应的 API。官方预设会带入服务地址。 普通本机 API 成员可以按房间编号读取同站点其他房间的概况、消息、事件和附件。
   API 成员处理一次房间任务最多 45 分钟。连续 15 分钟没有模型或工具进展也会停止，执行卡会显示原因。
   排查时，在房间左栏点“执行”，进入“瀑布”，打开该次执行的“执行诊断”。最后续租由房间服务记录，最后模型或工具进展由接入软件报告。模型请求重试、适配器重启和接入程序重新投递分别记录。插话的确认时间需要软件提供对应回执。旧执行或软件未提供的记录显示“未知”。
4. **填写 API 配置并检查。** 点成员卡正面的“设置”区域翻到背面，填写“地址”“协议”“密钥”“模型”。如果所选模型支持看图且需要它读图片附件，打开“看图”。点闪电按钮检查配置，提示“检查通过：模型已响应”即表示可用；点“完成”回到正面。

### 保存与使用项目预设

点成员卡背面的书签图标“存为预设”。在“存为专家预设”的“保存位置”中，跨项目复用时选“全局”，要随项目保存时选“当前项目”。有多个可写目录时，从“目标项目”中选具体位置。从预设添加的卡片可以用“更新预设”保存修改。带技能的预设可在卡片的“高级配置”中编辑技能。

陌生项目的预设请求可写权限时，默认以只读加入。核对请求的权限后，可在卡片上勾选放开。只读目录的预设可以使用，修改后的配置可另存到可写位置。

## 续接已有会话

想让本地 AI 带着原软件里已经聊过的上下文进房间，可以使用“历史会话”。支持 Claude Code、Codex 与 Gemini（Antigravity CLI，命令 `agy`）。

### 怎么操作

1. 在新建房间或“邀请 AI 加入”里添加成员后，把成员卡上的启动方式切到“历史会话”。
2. 弹出的历史会话窗口会按时间列出该软件的已有会话，可搜索关键词，也可切换只看当前项目或全部；点一条会话，右侧会预览最近的对话。
3. 选中会话，点“接入此会话”，再完成建房或邀请。

### 要注意什么

- Claude Code、Codex CLI 和 `agy` 通过历史会话接入时，本机服务复制所选会话，在副本中继续工作。之后的房间消息保存在副本中。
- 经 Codex App 接入时不复制，任务直接送进 App 里的这个会话。
- Antigravity CLI 续接的历史会话沿用它原来的项目目录与 `agy` 权限，房间的项目权限对它不生效。

## 更换模型、名称与专属提示词

- **改模型与思考强度**：新建房间或邀请时在成员卡背面设置；已有房间在顶部“房间”页 → “成员与设置”里找到该成员，调整模型、思考强度，或点刷新重新读取模型列表（更改从下一次执行生效）。App 接入的成员在原 App 聊天里选模型与强度，网页不覆盖。支持切换入口的软件也可在这里切换 CLI 与 App。由手动接入转为本机唤醒的成员，“接入”后会标“接管已有会话”：它的项目权限沿用原会话，模型与思考强度同样可以在这里改；但它自己的窗口开着时，任务会直接发进那个窗口，用的是窗口里的模型，关掉窗口后才按这里的设置运行。改过还没用上时，模型一栏在上次实际所用的模型后标“（设置为 …，下次生效）”或“（设置为 …，它自己的窗口关闭后生效）”。
- **改显示名与分工描述**：右栏 → 成员菜单 → “名称与描述”（建房或邀请时点成员卡的名称与描述按钮，可翻面的卡片在背面设置），修改房间里的“显示名称”和分工说明。在房间里还有更快的入口：双击右栏或“成员与设置”页里的成员名称直接改名（Enter 或点别处保存，Esc 取消）。右栏的成员行不显示描述：鼠标指向某位成员，左侧浮出它的成员卡片，显示描述，并可点“编辑名称与描述”；手机、平板上点一下成员行，弹出的菜单顶部显示描述。编辑框里可点常见分工快速填入。分工说明会发给主持人和智能调度，帮助更准确地派活，也可存为该软件的默认描述。
- **设专属提示词**：建房或邀请时翻开成员卡，点背面的“专属提示词”按钮；已在房间里的成员，在顶部“房间”页 → “成员与设置”里找到该成员，点“专属提示词”一行的编辑按钮（和模型、项目权限放在一起）。写下只发给这位成员的要求（例如“回答先给结论”），从下一次唤醒起生效。专属提示词不改变权限；来自工作流的成员只读，要到工作流里改。手动启动和外部成员没有专属提示词。
- **给所有成员或某个平台设系统提示词**：“设置”→“系统提示词”里，“所有成员”一行发给本机唤醒的全部成员，各平台一行（Claude、Codex、Gemini、DeepSeek 等）发给用该平台的全部成员，包括预设和工作流里的专家。它们排在专属提示词之前，从下一次唤醒起生效；不修改各软件自己的 CLAUDE.md、AGENTS.md，所以不影响你在共议之外直接使用这些软件。命令行用 `codiscuss launch prompts`。

## 设为主持人、离开、请回与移除

“房间”页先列出在场成员，暂离成员集中在下方默认展开的“已离开”分组。点分组标题可收起或展开，成员卡片仍提供“请回”等操作。

调整默认发言顺序时，可拖动在场成员卡片的手柄，看到落点指示线后松手。手机手柄在卡片头部右侧，电脑手柄在左侧。键盘聚焦手柄后可用上下方向键移动一位，拖动时按 Esc 可取消。

- **设为主持人**：建房时点成员卡上的皇冠；已有房间在右栏 → 成员菜单 → “设为主持人”。讨论进行中更换主持人会暂停讨论。新主持人的项目权限会随原主持人提高：取它的软件支持的、不高于原主持人的最高一档（例如原主持人是“自动”而新主持人的软件没有这一档，就是“可写”），只升不降，改动时右下角会提示；原主持人的权限不变。不想要这个结果时，在成员表里改回去。
- **“离开”**：右栏 → 成员菜单 → “离开”。状态变为“已离开”，不再被唤醒，待处理请求会取消，会话保留。
- **“请回”**：右栏 → 成员菜单 → “请回”（或在“邀请 AI 加入”里选中已离开的成员，再点“邀请”），续接原会话回到房间。
- **“移除”**：右栏 → 成员菜单 → “移除”，将该成员移出房间名单。讨论进行中不能让当前主持人离开或移除。

## 项目权限能拦住什么

项目权限按成员单独设置，默认“只读”。可选“只读”“可写”“自动”“全放开”，软件不支持的档位会灰显。已在房间的成员，在右栏 → 成员菜单 → “项目文件”里直接切换，或在顶部“房间”页 → “成员与设置”里改，从下一次执行生效、会话保留。

只读的成员用共议命令发文件或下载附件时，路径也受限：发送的文件只能来自项目、额外目录、草稿、技能和它自己的运行目录，附件只能下载到草稿目录、知识目录或可写的额外目录，各软件都一样。

| 软件 / 接入方式 | 支持的档位 | 实际能拦住什么，拦不住什么 |
| --- | --- | --- |
| **Codex CLI** | 只读、可写、自动、全放开 | 原生沙箱可用时，只读档限制写入，可写档允许写入项目目录。读取范围可以超出项目目录。 |
| **模型 API** | 只读、可写 | 两档都使用 Pi（本机运行 API 成员的程序）自带的工具。只读档由本机服务拦截：读取只限项目、额外目录、草稿与技能，写入只放行草稿目录和可写的额外目录，命令只放行共议网站命令。Windows 上需要安装 Git for Windows（Pi 用 Git Bash 执行命令），没有时任务显示未送达并说明原因。可写档不拦截，可访问你本机账号能访问的文件。借给其他电脑房间的外部成员另行收窄。 |
| **Claude Code CLI** | 只读、可写、自动、全放开 | 只读档预先放行读写房间的 `codiscuss` 命令与草稿目录，可写档允许改项目和跑命令，自动档由软件审核，全放开跳过确认。你在 Claude Code 里已有的授权仍然生效。 |
| **Gemini（Antigravity CLI，`agy`）** | 只读、可写、全放开（后台不支持“自动”） | 使用会话级权限规则限制读写。 |
| **Codex App、Antigravity App、手动启动** | 沿用原软件设置 | 程序无法在外部强行拦截，只在任务里写明要求，实际权限以原软件设置为准。 |

如果某位成员的工作目录不在房间的任何项目目录里，它在自己的目录工作。查看成员卡上的房间目录权限；显示“只读（仅任务要求，程序拦不住）”时，原软件仍可能写入房间目录。实际限制取决于接入方式、权限档位和沙箱是否可用。

## 手动接入

如果你想沿用现有对话，先确认这位 AI 能在自己的窗口执行 `codiscuss`，并在对应成员卡上找“手动启动”。Claude、Codex 和 Gemini 的本地软件卡支持这个选项。“Grok”的 API 卡没有“手动启动”。

**用 Cursor CLI 手动参与。** 安装器选 Cursor 以安装参与技能。网页目前没有专用 Cursor 卡：可以添加一张 Claude、Codex 或 Gemini 卡，选“手动启动”，把“显示名称”改为 Cursor，再把该席位的启动指令私下交给你要使用的 Cursor CLI 窗口。在该窗口完成下方的注册、查请求和按请求回答。注册按席位凭据校验；改名只改显示，底层平台仍是所选卡片。共议不会据此自动唤醒或接管 Cursor 会话。`codiscuss member register` 只能注册已邀请的席位，没有专门的 `member add` 命令来创建 Cursor 身份。

### 怎么操作

1. **添加成员。** 新建房间 → “谁来参与” → “添加 AI”，在支持手动接入的成员卡上选“手动启动”。已有房间则在右栏点“邀请 AI 加入”，选成员和“手动启动”，再点“邀请”。建房或邀请完成后，右栏显示“待注册”。
2. **领取启动指令。** 在邀请结果页或房间输入框上方的待注册提示旁点“复制启动指令”，按钮会显示“已复制”。也可以在右栏打开该成员菜单，点“复制启动指令（含凭证）”。
3. **在原窗口注册。** 将指令私下粘贴给你要接入的 AI 并发送。它会按指令先运行 `codiscuss room view`，再运行 `codiscuss member register`；房间、身份和凭据由复制的说明提供。注册后，输入框上方的“待注册”提示消失；空闲的手动成员在右栏显示“已注册”。
4. **给它一项任务。** 在房间输入框输入 `@`，选它并发送问题。支持自动投递时，本机服务会尝试把请求送入它的会话。如果房间在等你手动触发，回到刚注册的窗口告诉它：“请用刚才的房间凭据查看分给你的待处理请求，读原问题，完成后把回答交回这条请求。”它用 `codiscuss room view` 查请求，再用 `codiscuss message post --request 请求编号` 绑定回答。回到网页，应能看到它署名的回答。如果网页显示服务正在投递或重试，先核对执行状态，避免让两个进程同时续接原会话。
5. **结束参与。** 在右栏打开成员菜单，点“离开”可暂停参与，待处理请求会取消。需要它回来时点“请回”，再复制新的启动指令到原窗口重新注册。点“移除”则将它移出房间名单。

### 要注意什么

- **凭据只交给该成员。** 启动指令含私有凭据。如果不想把凭据粘进聊天，在右栏成员菜单点“下载私有配置”，将文件保存到本机；然后点“复制参与说明”，把说明和文件的完整路径交给 AI。不要把配置文件或启动指令发进房间。
- **原窗口的行为因软件而异。** Codex 可通过 App 队列接收请求；Claude Code 原窗口能否实时收到取决于会话收件箱；Gemini（Antigravity CLI 或 Antigravity App，CLI 命令为 `agy`）的 CLI 后台续接后，已打开的旧窗口可能需要重启才能看到新发言。
- **权限与历史。** 手动成员沿用原会话的权限和模型。网页撤回或回退消息不会撤销它已改动的项目文件。开启讨论或 Goal 需要可由本机服务唤醒的主持人。
- **讨论中不想等这一次发言。** 当讨论未暂停且已有当前发言安排时，房主可在右栏的讨论操作区点“跳过”。普通房间里直接点名成员的问题没有这个讨论按钮。
