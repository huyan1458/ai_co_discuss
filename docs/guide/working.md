# 在房间里干活

发消息给指定成员或主持人，看懂主线、支线与派活标签，管好排队消息，随时私聊插话、停止、回退以及回答成员的提问。

## 怎么操作

### 1. 发消息与点名

- **点名成员**：在底部输入框输入 `@`，从列表选一位或多位成员，输入任务按 `Enter` 发送（`Shift+Enter` 换行）。被点名的多位成员并行处理。输入 `@` 也可以搜索并引用项目目录中的文件或文件夹。
- **调用成员的本机技能**：选好 `@成员` 后再输入 `/`，可搜索该成员本机已安装的技能，点击或按 `Enter` / `Tab` 填入草稿。单独输入 `/` 会显示模式、工作流和平台技能。
- **不点名直接发**：没有 `@` 任何人的消息交给主持人分派（房间里只有一位成员时直接交给它；开启智能调度后，明显指向某位成员的消息会直接交给该成员）。
- **让全体回答**：输入 `@全体成员` 让在场成员各自并行回答，房间有主持人时，它先和大家一样独立回答，所有人答完后再汇总共识与分歧、需要时安排后续工作；输入 `@全体依次` 按右栏“发言顺序”逐个回答。
- **发之前看提示**：输入框下方的一行会按当前谁在忙说明这条发出后会怎样，比如被 @ 的成员空闲时写“立即发给某某，与正在进行的工作并行（支线）”，它正忙时写这条会先排队；没 @ 人而房间正忙时，会提示你可以 @ 一位空闲成员让它马上开工。
- **回复、搜索与筛选**：消息菜单点“回复”关联原消息，“查看原文”看完整正文与摘要；房间顶部可“搜索消息”或按作者、主持、点名与卡片类型“筛选消息与卡片”。

- 发送图片时，当前页面沿用本机预览。消息回执和成员执行状态出现时，页面保留刚发送时的阅读位置。
- **连续发送与失败重试**：上一条仍显示“发送中…”时可以发送下一条。房间正忙、消息预计需要排队时，每条先显示在输入框上方的排队列表里，网站确认后在原位成为正式排队项。浏览器按点击顺序提交，单条失败后继续发送后续消息。失败卡保留原文和附件，可点“重新发送”或“放弃”。切到其他房间后，发送和网络重试会继续；回到原房间还能找到失败卡。刷新或关闭页面会清除本页未发出的消息。

网站返回消息编号后，如果接收成员已确定，消息下方会立即显示该成员的头像、名字和等待状态。读回房间后，同一位置显示实际工作状态。需要智能调度决定接收者时，页面显示调度进度。

### 2. 看懂主线、支线与派活标签

房间支持多线并行，卡片头部会用标签标出这条工作属于哪一条线、做完后怎么处理：

- **主线与支线**：主持人安排的发言顺序（例如依次接力）以及你发的 `@全体依次` 是**主线**；你或主持人直接 `@` 某位成员是**支线**，不占发言顺序，与主线并行。
  - 被你直接 `@` 的成员空闲就立即开始，正忙就进入排队区，一空闲立刻收到。如果一条消息同时 `@` 了空闲成员和忙碌成员，空闲的立刻开工，忙碌的那份留在排队区等它空闲。
  - 主线轮到某位成员时，会等它做完手头支线再继续。
  - 你发出的未点名消息、`@全体成员`、`@全体依次` 等整个房间空闲后再按顺序发出（主持人派出的后台任务不会阻塞你的新消息）。
- **卡片的固定位置**：每张成员卡从上到下依次是卡头、正文、交付（回答摘要、附件、交付文件）、过程记录（过程说明与步数、文件改动、被拒操作）。卡头左边说“是谁”：名字、标签和这次用的模型与强度；右边说“这一次怎么样”：状态、时间、编号、耗时，耗时总在最右。带颜色的状态只表示出了问题（红色失败，琥珀色停止、作废、跳过），正常时不标；你发的消息上，右边是各成员的处理状态。手机上撤回、编辑、私聊等按钮在卡片右上角，和名字同一行；模型、状态、时间、编号、耗时在名字下方从左排起。停止、重试按钮在它作用的那一行右端。
- **卡片头部标签**：先写这张卡从哪来，再写接下来去哪。常见的发言渠道（本人发言、CLI、API）不再标出，只标代发、主动发言、自动收录这类少见来源。
  - “主持”：当前主持人的发言，主持说明卡也用它。
  - “主线 · 第 n 棒”（主持人安排的顺序）或“主线 · 第 n 位”（`@全体依次`）。
  - “支线”：直接点名、且点名时房间里另有成员在工作的任务。房间空闲时点名一位成员不标。失败卡、停止卡同样保留这些标签。
- **模型与思考强度**：成员的回答卡、处理中卡片、失败卡和停止卡在名字与标签之后显示这次执行实际所用的模型与强度（如 `gpt-6.2-sol · medium`），执行页点开某次执行的详情也会显示。它记录的是当时所用，之后改成员模型不会改变旧卡片；读不到（如外部成员）时不显示。手机上放不下时只截掉型号开头，保留末尾和强度。
- **主持人派活消息上的标签**：
  - “做完交回主持”：派出的成员全部结束（含失败）后唤醒主持人决定下一步。
  - “做完直接给你”：成员的回答直接给你，不再交回主持人；失败时仍交回主持人。
  - “后台，不交回”：后台进行，谁也不等它；做完不交回，失败时通知主持人。
  - “接力，最后交回主持”：按顺序一棒接一棒，最后一棒做完交回主持人。
  - 派活同时带了后台成员时，还会显示“另有后台：成员名”。
- **连续派活轮数上限**：你的一条消息默认最多让主持人连续推进 10 轮，到限自动停下，右栏点“继续”接着推进；主持人预先申请更多轮数时，右栏会显示申请理由，点“批准”即可一次跑完。

### 3. 管理排队消息

成员正忙时，你发送的新消息会自动停留在输入框上方的排队区，等对应成员或房间空闲后自动发出。你在答题卡上的回答也一样：提问的成员还在忙时，回答已经记下，但交给它的那份留在排队区，写着“#N 已发出，等某某空闲后交给它”。

- **不想等**：点排队项右侧的箭头按钮，悬停可看到点了之后会怎样：
  - 接收者空闲：马上发出。
  - 接收者正在执行、它的软件支持插话：这条插进它这一轮，它当场就能看到，已做的工作不受影响。
  - 接收者正在执行、不支持插话：先打断它这一轮，再连同被打断的工作和这条一起处理。
  - 接收者既不能插话也不能打断：点了会提示原因，消息继续排队。
- **编辑与删除**：未发出的排队消息，在排队项菜单点“编辑消息”退回输入框修改，或点删除移除。
- **调整顺序**：拖动排队项（手机上长按）调整发送顺序。
- **暂停与继续**：点“全部停止”或停止运行时，队列暂停并显示“已暂停排队：你停止了运行”，点“继续”恢复发送。某条发出失败时会停住队列并显示原因，点“重试”、编辑或删除后队列继续。
- 排队一直开着，没有开关；要让正忙的成员马上处理某条消息，点排队项上的箭头按钮。

### 4. 停止、重试、撤回与编辑回退

- **停止执行**：点处理中卡片的“停止”（或右栏 → 成员菜单 → “停止”）停掉该成员这一次；在右栏点“全部停止”停掉全部成员并取消尚未送达的请求。本机确认进程退出后显示“已停止”，无法确认时显示“停止未确认”，App 或手动窗口停不了时显示“已作废，可能仍在生成”。迟到的回答不进入主记录，房主可在作废卡展开“未采纳的回答”查看。
- **重试与重发**：投递失败卡倒计时期间可点“立即重试”或“停止”；执行失败卡点“重发”把原用户消息填回输入框确认后再发。如果是某项操作被权限拦截导致失败，展开对应卡片的执行报告，查看是否可以“允许并重发”。
- **撤回消息**：还没有成员开始处理的消息，点“撤回”把原文连同附件和引用退回输入框；最新一条消息即使已开始处理也可撤回（同时停止处理并回退到它之前）。输入框为空时连按两下 `Esc` 也可撤回最近一条。
- **编辑并回退**：已被处理的用户消息点“编辑”，改写后重新发送。这条消息及之后的记录会折叠为“已回退”，AI 不再读到它们；确认前查看回退预览，逐个核对成员会话将如何处理。成员已改动的项目文件会保留。

### 5. 私聊与执行中插话

想看某位成员正在干什么、中途纠偏，或单独问它一句而不发到公共房间，可以打开私聊窗。

- **从哪里打开**：在左栏点“私聊”，再在页顶选成员。要看某次执行，也可点对应处理卡或回答卡上的聊天气泡。
- **查看执行过程**：私聊页展示本机服务已收到的执行记录。能看到哪些命令、工具调用和输出，取决于该成员的接入方式。
- **执行中插话**：成员正在处理房间任务时，在私聊窗底部输入框（提示“插话引导它…”）发一句话，查看页面反馈，确认补充要求已送达或正在排队。如果该成员支持暂停续做，也可以先点“暂停”停住本次执行（提示“已暂停，发一句补充后它接着做这次任务”），补充要求后它接着做。
- **空闲时私聊**：成员空闲时在私聊窗发消息，只和你单独对话，不出现在房间公共消息流里，也不会唤醒其他成员。

### 6. 回答成员的提问（答题卡）

当成员需要你做决定时，输入框上方会出现答题卡（多张卡片依次排队，多道题一页一题，推荐项排在最前并预选）：

1. 逐题选择、补充填写或跳过，点“提交回答”即可把答案交回提问的成员（在接力中会直接交给下一棒）。
2. 拿不准时，点“请主持人先讨论并给推荐”（主持人给出推荐后答题卡更新，仍等你最终确认），或点“交给主持人决定”（扩大权限、费用、批准轮数等须你亲自授权的事项不能交主持人）。
3. 不想继续时点“取消这个问题”，若绑定了接力，接力也会随之停止。

### 7. 查看过程与排查

- 打开房间后，在左栏点“执行”，选“瀑布”查看执行时间线。横向时间条显示各成员何时开始、运行了多久、哪些时间花在等待上。点成员名字看这次执行的状态、开始时间和总时长；点时间条中的某一段可看该阶段已记录的细节。超过 5 分钟的空闲在“执行轨迹”里折叠成窄带；要按真实时长回顾整个过程，切到“并发全景”：顶部先给出两个比例——“自动执行”是有成员在干活的时长占整段的比例，“无需介入”是不由你的消息触发、而由主持人派活、接力或程序唤醒自动接上的执行所占的比例，“最长无人值守”是从你的一条消息起、到房间停下或你再次发消息为止，AI 连续自动推进最久的一段；从左到右一条不折叠的时间轴，上方的高度是同一时刻有几位成员在执行（按成员颜色叠加，鼠标指向色块看那次执行的详情），空闲处标出时长，下方按任务分段，点某个任务在执行轨迹中查看。Ctrl + 滚轮或右上角“− / +”缩放（手机和平板上双指捏合），放大后拖动平移，双击还原；放大后回放时画面默认跟着回放线走，手动拖动画面会关闭“跟随”，再点它即可恢复；“执行轨迹”在手机和平板上同样可以双指缩放、放大后左右拖动；点右上角“回放协作过程”按时间顺序重放最近这次任务，可调速度或拖动进度，点“结束回放”回到当前状态；有成员还在执行时也能回放，放到现在为止。点“显示更早的执行”可一直往前翻到房间第一次执行，点“显示全部”一次列出房间的所有执行。
- 想处理权限拒绝，回到对话区，查看对应失败卡的执行报告。只有执行未完成、记录了可放行的规则、本机服务可用且能找回原请求时，才显示“允许并重发”。核对规则再点它，原消息会回到输入框，确认后发送。已完成执行的回答卡如中途有过被拒操作，默认折叠为次数记录，展开可核对明细，不再显示“允许并重发”。
- 排查“为什么没唤醒”或“哪一步被拒绝”时，在顶部“执行”页切到“事件”。“事件记录”按时间列出房间收到的操作、处理结果和引起的状态变化。点一行看原始记录与同一对象的相关事件。本机终端也可运行 `codiscuss room events <房间ID>` 查看。

### 8. 把网页部署成网站

成员交付的网页可以发布到公网地址 `https://<编号>.bimcanvas.com`，没装共议的人也能直接打开。

1. 回答下方的 HTML 文件卡片上点火箭按钮“部署为网站”；成员用 `codiscuss site stage` 准备好的整个目录（如构建出的 `dist/`）会显示为“待部署”卡片，点“部署为网站”。
2. 确认框列出文件数、大小和疑似含密钥或令牌的文件，这些文件默认排除；点“部署”。全部文件传完才切到新版本，中途失败时线上旧版不受影响。
3. 上线后卡片显示网址，可复制、打开；“…”里可续期 7 天、回滚到上一版或撤销。左栏“已发布”列出所有在线网站。

想让成员做完直接上线，在消息里明确说“部署”或“发布成网站”；没说时成员只准备、不上传。

网站里没有扩展名的地址（如 `/about`）在浏览器里打开时都返回首页，由网页自己的前端路由处理；带扩展名但不存在的文件返回 404。页面引用的资源请用以 `/` 开头的路径。

## 要注意什么

- **普通成员的 `@` 不派活**：普通成员互相 `@` 只是引用，不会唤醒对方；普通成员 `@` 主持人时，等房间里其他工作都结束后才唤醒主持人。
- **私聊与插话的边界**：私聊窗和执行中插话只能发文字，不支持发附件或画图；手动接入成员、外部成员以及看不到输出的接入方式不支持私聊窗。
- **停止未确认时的等待**：出现“停止未确认”或“已作废，可能仍在生成”时，发给该成员的新消息会等待结束确认、迟到回答或原有 10 分钟期限。
- **答题卡是房间公开记录**：问题与回答和普通消息一样对能阅读本房间的人可见，不要在里面填写密钥、令牌或密码。
- **讨论中的限制**：讨论进行中暂不能使用 `@全体成员`、`@全体依次`、撤回、编辑回退和分支。
