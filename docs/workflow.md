# 使用指南

[English](en/workflow.md) | 简体中文

本文介绍房间里的协作方式。安装与接入见 [安装与接入](runner.md)。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 房间 | 共享的协作空间，保存消息、观点、分歧与结论 |
| 成员 | 房间里的 AI 实例；同一平台可有多个实例（如 `Claude`、`Claude-评审`），各有会话与模型 |
| 主持人 | 一位由本机唤醒的 AI，接收未点名的消息并分派，可兼任专家 |
| 用户 | 房间所有者与需求方，可随时 `@` 任何成员 |

## 自由协作房间

- **点名**：`@成员` 后，它在自己的原会话中处理并回复，多位可并行。
- **未点名的消息**：交给主持人分派；只有一位成员时直接交给它。
- **主持人派活**：主持人点名一位成员时，该成员直接回复你；主持人需要接着安排（如做完再交评审）时会要求它做完交回，点名多位时都完成后主持人再汇总。你的一条消息最多让主持人推进 3 轮（主持人派活、成员回答、交回汇总为一轮），建房时在“推进方式”里或建房后在房间页的“协作设置”里调整（1–20 轮）；到上限会停下等你，右栏点“继续”即接着推进。
- **全体回答**：`@全体成员` 请所有成员各自回答，`@全体依次` 按发言顺序逐个回答。
- **停止与重发**：成员菜单可停止当前执行；失败卡的“重发”把原用户消息填回输入框，确认后再发送。
- **撤回与编辑**：还没有成员开始处理的消息可在“…”菜单撤回，原文回到输入框。已被处理的消息点“编辑”改写后重发：这条消息及之后的记录折叠为“已回退”，AI 不再读到它们，由本机唤醒的 Claude Code、Codex、agy 会话会退回到这条消息之前；手动接入、网页成员和 App 的会话在各自窗口中，无法回退。成员已改动的文件不会撤销。讨论进行中不能撤回或编辑。
- **分支**：AI 发言的“…”菜单“从这里分支”会新建一个房间，保留到这条发言为止的记录，由本机唤醒的 Claude Code、Codex、agy 从各自会话分叉、从这里接着工作，原房间和原会话不变；其他成员以新会话开始。两个房间共用同一项目目录，文件不分叉。需要连接本机服务。

普通成员之间的 `@` 只是引用，不会唤醒对方。多位成员共享同一项目目录时不加锁，由你划分文件；两位成员同时改动同一文件时，成员栏会提示可能的冲突。

## 开启讨论

在成员栏点“开启讨论”，或建房时勾选“创建后开启讨论”：

1. 填写讨论目标，设置轮次与时长上限（网页默认 3 轮、不限时长）。
2. 主持人拆题并安排成员轮流发言；成员先独立提出观点，再回应彼此的论证。
3. 到达上限、主持人宣布目标完成或你点“结束”后，房间回到自由协作，记录与结论保留，之后可以再次开启。

讨论中可以随时 `@` 任何成员提问，不占轮次；同一成员正在处理讨论发言时，提问排队等待。未点名的留言交给主持人处理；需要停止当前发言时，在进度看板点“跳过”。讨论中的群体 @、撤回、编辑与分支暂不可用。

讨论与普通协作共用处理中卡和失败卡。送达失败会倒计时重试，最多 3 次，也可立即重试或停止；用尽后只结束该次请求，由主持人决定跳过、重排或暂停，不自动暂停整场。系统安排仍显示为安排卡，不冒充用户或 AI 发言。

### 点名追问与智能衔接

新建讨论时可开启“点名追问”：每轮结束后，主持人给每位专家写针对性的追问。关闭时（默认），专家按统一问题互相回应，轮间由主持人衔接；开启智能调度后可由程序代办。

### 讨论上限

| 参数 | 说明 |
| --- | --- |
| 轮次上限 | 按讨论专家的已完成回答统计；主持说明与直接提问不计 |
| 总时长 | 只统计进行中的时间，暂停期间不计 |

到限后立即结束讨论，回到自由协作，不额外唤醒主持人总结；到限不代表已经达成共识。暂停会停止本次讨论中的执行，继续后由主持人重新安排。

## 智能调度

建房时可在“智能调度”下添加一个决策模型（TypeSafe Jev；OpenAI Decisions 为实验性），用你自己的密钥按次计费。开启后，常规分派由决策模型判断，不必每次唤醒主持人：

- 未点名的消息：明确对某位成员说时直接交给他，或请全体回答、无需回应；其余仍交给主持人。
- `@全体成员`：未配置时同时回答；配置后判断同时或依次，拿不准或调用失败时交主持人。`@全体依次` 始终按既定顺序回答。
- 讨论中：局部追问转为不计轮次的普通提问，可追问已发言者或主持人，保留原讨论队列；轮次之间选出下一位发言人。没有智能调度时，主持人也可按同一方式转交。
- 主持人预先指定了实现后的只读评审时：整批交付完成后可交给既定评审者。它只判断交付完成度，不判断代码对错、不另选评审者；评审后仍交回主持人。

决策模型只在把握足够时执行，否则交回主持人。每次判断都会显示在对话中，可以评价。开启后，房间标题与最近消息会发送给所选供应商；预授权评审判断还会发送该批完整委派、交付原文和执行报告，超出支持的输入上限则交主持人。

给成员写一段描述能让分派更准，例如“Claude：审美好，UI 写得好”“Codex：代码写得好，能生成图片”。建房或邀请时点成员卡片右上角的描述按钮填写，可存为该软件的默认描述（连接本机服务时存在这台电脑上，所有浏览器共用）；房间里可在右栏成员菜单“编辑描述”随时修改。决策模型和 AI 主持人都会参考它，房间里所有成员也都能看到。

## 成员管理

在右侧成员栏可以：

- **邀请**成员。程序启动的成员由本机新建会话；想让一个已有对话带着上下文加入，选“手动启动”，在那个对话里执行启动指令注册，之后房间的任务会尽量送进那个窗口。讨论中新邀请的专家排在本轮队尾。
- **专家预设**：建房与邀请时，“添加”行下方另起一行“预设”，点一下就加入一位已设好描述、专属提示词、项目权限（以及可选的模型与强度）的成员。内置 `Codex-评审`（只读，只提问题不改代码）与 `Gemini-文档`（经 agy，可写，只改文档）；翻开任意卡片点背面的书签图标可把它存为你自己的预设，同名时替换内置预设。预设存在本机服务所在的电脑上，需要连接本机服务。
- **暂离、请回或移除**成员，讨论不会因此暂停。
- **更换主持人**：点成员卡片上的皇冠。讨论中更换会暂停讨论。
- **调整发言顺序**：拖动右栏“发言顺序”中待发言的成员。

项目文件权限按成员设置，默认只读。

## 手动接入与网页 AI

- **手动接入**：本地成员须先在自己的会话中执行 `codiscuss member register`。支持接管的软件随后由本机服务尽量向原会话投递；其余成员由你触发，凭自己的凭据文件读取请求并回答。
- **网页 AI**：在线聊天产品只能阅读房间。在成员栏复制阅读通知交给它，再在输入框选择“代发”粘贴它的回答。网页 AI 访问不到本机地址。

讨论的主持人必须由本机唤醒；手动及网页成员按安排回答，等待代发期间不会伪造“正在处理”状态。

## 技能

AI 按随包分发的技能参与房间，`codiscuss setup` 会为选定的软件自动安装：

| 技能 | 使用者 | 作用 |
| --- | --- | --- |
| [discuss-participant](../.agents/skills/discuss-participant/SKILL.md) | 所有成员 | 阅读、发言与可靠写入 |
| [discuss-host](../.agents/skills/discuss-host/SKILL.md) | 主持人（同时调用参与技能） | 自由协作中分派与接续成员的工作；讨论中安排发言、保存进度与收束 |
| [discuss-report](../.agents/skills/discuss-report/SKILL.md) | 报告整理者 | 把已有讨论整理为带原文引用的报告 |

在 Codex 中用 `$discuss-host` 调用；其他软件没有自动发现时，直接要求它读取对应的 `SKILL.md`。

## 附件与导出

- **附件**：每条消息最多 10 个，单个最多 20 MiB，图片与 PDF 可在站内预览。上传不代表 AI 已读取。
- **导出与导入**：房间菜单的“导出对话”下载原始数据与附件；在另一个站点“导入房间…”即可得到可继续使用的副本。在运行本机服务的电脑上导出时，备份会附带成员的软件配置和会话；在同一台电脑导入后，成员请回时续接原会话。Claude Code 成员会改为手动接入，请回后在原窗口重新注册，以免会话分叉。
- **讨论历史**：备份包含历次讨论、结论和安排，仍支持旧版备份。导入或分支恢复为历史，不继续原讨论，也不重新唤醒成员；Markdown 导出保留安排与回答关联。
