# 使用指南

[English](en/workflow.md) | 简体中文

本文介绍房间里的协作方式。安装与接入见 [安装与接入](runner.md)。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 房间 | 共享的协作空间，保存消息、观点、分歧与结论 |
| 成员 | 房间里的 AI 实例；同一平台可有多个实例（如 `Claude`、`Claude-review`），各有会话与模型 |
| 主持人 | 一位由本机唤醒的 AI，接收未点名的消息并分派，可兼任专家 |
| 用户 | 房间所有者与需求方，可随时 `@` 任何成员 |

## 自由协作房间

- **点名**：`@成员` 后，它在自己的原会话中处理并回复，多位可并行。用界面上显示的昵称点名即可（如 `@Gemini`），输入 `@` 后从列表选择最方便。
- **未点名的消息**：交给主持人分派；只有一位成员时直接交给它。
- **主持人派活**：主持人派出的成员做完或失败后都会交回主持人，由它接着安排或汇总；简单问答主持人可以让成员直接回复你，失败时仍交回主持人。程序发现的问题（如成员执行失败）会以“程序通知主持人”卡片交给主持人处理；主持人也可以在回答后要求房间空闲时再被唤醒，自己接着推进。你的一条消息默认最多让主持人推进 10 轮（主持人派活、成员回答、交回汇总为一轮；主持人要求续跑一次也算一轮，程序通知不算），建房时在“推进方式”里或建房后在房间页的“协作设置”里调整（1–100 轮，或勾选“不限”）；到上限会停下等你，右栏点“继续”即接着推进。主持人事先知道任务要多少轮（如连写几集）时，会在开始时申请轮数：剩余不够就先停下，右栏显示申请理由，点“批准”后一次跑完，不再中途停下。
- **依次接力与循环**：几位成员要按固定先后做（写完再审、实现后评审）时，主持人会安排依次接力：一位做完直接交给下一位，最后一位做完才交回主持人，走完一圈算一轮。需要“改完再审”时安排成循环：每走完一圈交回主持人一次，评审要求返工就再走一圈，认可或需要取舍时由主持人验收。互不依赖的几位（如分别审不同问题的评审）可以排在同一棒同时做，这一组全部做完才交给下一位。接力中途还可以设检查点：某一棒做完先交回主持人把关，主持人认可再往下走；也可以只让中间一段循环（如写 ⇄ 审到通过，再交记录员）。工作流的 SKILL.md 里写明何时用哪种安排（见 [工作流](runner.md#工作流可选)）。右栏发言顺序显示进行到哪一位、第几圈（同时做的成员共用一个序号）。主持人派活时还可以带上一位不必等待的成员，它同时开工，派出的工作结束时不等它，它失败时主持人会收到通知。右栏可拖动调整还没轮到的成员（设了检查点的接力不能调整）。循环圈数受上面的轮数限制，需要多改几轮时把轮数调大。
- **全体回答**：`@全体成员` 请所有成员各自回答，`@全体依次` 按发言顺序逐个回答。
- **停止与重发**：处理中卡片或成员菜单可停止该成员当前这一次；右栏“全部停止”停止所有成员并取消还没送达的请求。本机确认进程退出后才显示“已停止”，无法确认时显示“停止未确认”；自己窗口或 App 里的会话停不了时显示“已作废，可能仍在生成”。后续回答不进入记录，只有房主展开“未采纳的回答”时能读取正文。停止未确认或停不了时，新消息等待结束确认、迟到回答或原有 10 分钟期限；继续讨论、主动重发不跳过等待，也不重新计时。被停止的成员下次工作时会被告知。失败卡的“重发”把原用户消息填回输入框，确认后再发送。
- **撤回与编辑**：还没有成员开始处理的消息可撤回，原文回到输入框；最新一条消息即使已开始处理也可撤回，相当于停止对它的处理并回退到它之前。输入框为空时连按两下 Esc 也可撤回最近一条。已被处理的消息点“编辑”改写后重发：这条消息及之后的记录折叠为“已回退”，AI 不再读到它们，由本机唤醒的 Claude Code、Codex、agy 会话会退回到这条消息之前；手动接入和 App 的会话在各自窗口中，无法回退。成员已改动的文件不会撤销。讨论进行中不能撤回或编辑。
- **分支**：AI 发言的“…”菜单“从这里分支”会新建一个房间，保留到这条发言为止的记录，由本机唤醒的 Claude Code、Codex、agy 从各自会话分叉、从这里接着工作，原房间和原会话不变；其他成员以新会话开始。两个房间共用同一项目目录，文件不分叉。需要连接本机服务。

普通成员之间的 `@` 只是引用，不会唤醒对方。多位成员共享同一项目目录时不加锁，由你划分文件；两位成员同时改动同一文件时，网页右下角会提示可能的冲突（只在你开着房间时发生的才弹），不写进消息记录，也不唤醒主持人。

## 开启讨论

在成员栏点“开启讨论”，建房时在“创建后”选“开启讨论”，或在输入框发送 `/discuss 讨论目标`（只发 `/discuss` 时由主持人从最近对话提炼目标，提炼不出就不开启；命令开启时用房间保存的默认上限）：

1. 填写讨论目标，设置轮次与时长上限。开启弹窗预填房间保存的默认上限；建房时设置，无进行中或暂停的讨论时可在“编辑议题”修改。只在开启弹窗里调整的值仅用于本场讨论。
2. 主持人拆题并安排成员轮流发言；成员先独立提出观点，再回应彼此的论证。
3. 到达上限、主持人宣布目标完成或你点“结束”后，房间回到自由协作，记录与结论保留，之后可以再次开启。

讨论中可用 `/discuss pause`、`/discuss resume`、`/discuss stop` 暂停、继续或结束。讨论与 Goal 不能同时进行。

讨论中可以随时 `@` 任何成员提问，不占轮次；同一成员正在处理讨论发言时，提问排队等待。未点名的留言交给主持人处理；需要停止当前发言时，点处理中卡片上的停止键或进度看板的“跳过”，讨论接着轮到下一位。讨论中的群体 @、撤回、编辑与分支暂不可用。

讨论与普通协作共用处理中卡和失败卡。送达失败会倒计时重试，最多 3 次，也可立即重试或停止；用尽后只结束该次请求，由主持人决定跳过、重排或暂停，不自动暂停整场。系统安排仍显示为安排卡，不冒充用户或 AI 发言。

### 点名追问与智能衔接

新建讨论时可开启“点名追问”：每轮结束后，主持人给每位专家写针对性的追问。关闭时（默认），专家按统一问题互相回应，轮间由主持人衔接；开启智能调度后可由程序代办。

### 讨论上限

| 参数 | 说明 |
| --- | --- |
| 轮次上限 | 按讨论专家的已完成回答统计；主持说明与直接提问不计 |
| 总时长 | 只统计进行中的时间，暂停期间不计 |

到限后立即结束讨论，回到自由协作，不额外唤醒主持人总结；到限不代表已经达成共识。暂停会停止本次讨论中的执行，继续后由主持人重新安排。

## Goal

Goal 让主持人持续推进一个目标：房间空闲时，本机服务会再唤醒主持人接着做，直到主持人确认完成或卡住、预算用完，或你结束。没开 Goal 的房间行为不变，成员做完就停下等你。

- **开启**：在输入框发送 `/goal 目标`，主持人照原文开启；只发 `/goal` 时，主持人从最近的对话提炼目标，提炼不出就不开启并说明缺什么。也可以在成员栏点“开启 Goal”，或建房时在“创建后”选“开启 Goal”，直接填写目标。输入框开头打 `/` 时，菜单最上面一组“模式”列出 Goal 与讨论；进行中时改为列出暂停、继续、结束等命令。需要一位由本机唤醒的 AI 主持人；Goal 与讨论不能同时进行。
- **推进**：主持人派出的活全部结束、房间空闲 30 秒后（你刚发言、还有成员在工作或有排队消息时不算空闲），本机服务唤醒主持人一次，消息流里显示“Goal 续跑 #N”。主持人这次没派活（只回复你或向你提问）时，不再自动唤醒，直到你回复。
- **预算**：默认不限。开启或编辑 Goal 时只需填写目标；需要控制预算时，展开“高级设置”设续跑次数或时长上限。到限后主持人收尾一次，Goal 结束。连续 3 次续跑执行失败时自动停止。
- **结束**：主持人对照实际结果核验后宣告完成，或同一阻碍连续 3 次无法解决时宣告卡住；你可以随时 `/goal pause`、`/goal resume`、`/goal clear`、`/goal edit 新目标`，或用成员栏的按钮。“全部停止”也会暂停 Goal。结束后消息流留一张结束卡，可“继续 Goal”沿用原目标重新开启。

Goal 不扩大权限：主持人仍受成员项目权限和连续派活轮数限制，不会自行邀请成员、提交、推送或部署。

## 智能调度

建房时可在“智能调度”下添加一个决策模型（TypeSafe Jev；OpenAI Decisions 为实验性），用你自己的密钥按次计费。开启后，常规分派由决策模型判断，不必每次唤醒主持人：

- 未点名的消息：明确对某位成员说时直接交给他，或请全体同时回答、按发言顺序依次回答（如接龙、报数）、无需回应；其余仍交给主持人。
- `@全体成员` 始终同时回答，不经智能调度判断；`@全体依次` 始终按既定顺序回答。
- 讨论中：局部追问转为不计轮次的普通提问，可追问已发言者或主持人，保留原讨论队列；轮次之间选出下一位发言人。没有智能调度时，主持人也可按同一方式转交。
- Goal 进行中、房间空闲时：判断最近的回答是否已在等你回复（向你提问、请你授权或拍板、已汇报完成）。有把握时不唤醒主持人，等你回复；拿不准或调用失败时照常唤醒。
- 循环接力每走完一圈时：判断本圈最后一位（通常是评审）是否明确要求返工，有把握才自动开始下一圈；认可、需要取舍或拿不准时交主持人验收。它不评价作品本身，也不改成员顺序。
- 主持人预先指定了实现后的只读评审时：整批交付完成后可交给既定评审者。它只判断交付完成度，不判断代码对错、不另选评审者；评审后仍交回主持人。

决策模型只在把握足够时执行，否则交回主持人。每次判断都会显示在对话中，可以评价。开启后，房间标题与最近消息会发送给所选供应商；预授权评审判断还会发送该批完整委派、交付原文和执行报告，循环接力的判断会发送主持人的安排和本圈各成员的完整回答，超出支持的输入上限则交主持人。

给成员写一段描述能让分派更准，例如“Claude：审美好，UI 写得好”“Codex：代码写得好，能生成图片”。建房或邀请时点成员卡片右上角的描述按钮填写，可存为该软件的默认描述（连接本机服务时存在这台电脑上，所有浏览器共用）；房间里可在右栏成员菜单“编辑描述”随时修改。决策模型和 AI 主持人都会参考它，房间里所有成员也都能看到。

## 成员管理

在右侧成员栏可以：

- **邀请**成员。程序启动的成员由本机新建会话；想让一个已有对话带着上下文加入，选“手动启动”，在那个对话里执行启动指令注册，之后房间的任务会尽量送进那个窗口。讨论中新邀请的专家排在本轮队尾。
- **专家预设**：建房与邀请时，“添加”行下方另起一行“预设”，点一下就加入一位已设好描述、专属提示词、项目权限（以及可选的模型与强度）的成员。内置 `Codex-review`（只读，只提问题不改代码）与 `Gemini-docs`（经 agy，可写，只改文档）；翻开任意卡片点背面的书签图标可把它存为你自己的预设，同名时替换内置预设。点“预设”行末尾的“管理”后，每个预设（含内置）出现删除按钮，删除的内置预设不再显示。预设存在本机服务所在的电脑上，需要连接本机服务。
- **暂离、请回或移除**成员，讨论不会因此暂停。
- **更换主持人**：点成员卡片上的皇冠。讨论中更换会暂停讨论。
- **调整发言顺序**：拖动右栏“发言顺序”中待发言的成员。

项目文件权限按成员设置，默认只读。

## 手动接入

- **手动接入**：本地成员须先在自己的会话中执行 `codiscuss member register`。支持接管的软件随后由本机服务尽量向原会话投递；其余成员由你触发，凭自己的凭据文件读取请求并回答。

讨论的主持人必须由本机唤醒；手动成员按安排回答，等待期间不会伪造“正在处理”状态。

## 技能

AI 按随包分发的技能参与房间，`codiscuss setup` 会为选定的软件自动安装：

| 技能 | 使用者 | 作用 |
| --- | --- | --- |
| [discuss-participant](../.agents/skills/discuss-participant/SKILL.md) | 所有成员 | 阅读、发言与可靠写入 |
| [discuss-host](../.agents/skills/discuss-host/SKILL.md) | 主持人（同时调用参与技能） | 自由协作中分派与接续成员的工作；讨论中安排发言、保存进度与收束 |
| [discuss-report](../.agents/skills/discuss-report/SKILL.md) | 报告整理者 | 把已有讨论整理为带原文引用的报告 |

在 Codex 中用 `$discuss-host` 调用；其他软件没有自动发现时，直接要求它读取对应的 `SKILL.md`。

## 附件与导出

- **附件**：每条消息最多 10 个，单个最多 20 MiB，图片与 PDF 可在站内预览。上传不代表 AI 已读取。
- **导出与导入**：房间菜单的“导出对话”下载原始数据与附件；在另一个站点“导入房间…”即可得到可继续使用的副本。在运行本机服务的电脑上导出时，备份会附带成员的软件配置和会话；在同一台电脑导入后，成员请回时续接原会话。Claude Code 成员会改为手动接入，请回后在原窗口重新注册，以免会话分叉。
- **讨论历史**：备份包含历次讨论、结论和安排；早期第 1 版备份不再支持导入。导入或分支恢复为历史，不继续原讨论，也不重新唤醒成员；Markdown 导出保留安排与回答关联。
