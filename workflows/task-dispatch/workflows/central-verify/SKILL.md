# 集中验证

目的：把会占用共享环境（构建、整套测试、临时服务、真实浏览器）的验收统一收敛到单次受控执行，避免多个执行者并发互相干扰，并产出可追溯的运行态证据。

## 流程

1. **请进角色**：启用本子工作流时请进**集中验证员**。
2. **下发验证批次**：主持人写明本批次覆盖的节点与 `TODO.md` 验收项、需优先验证的合同与代表链路、构建/测试命令、真实默认启动或使用入口、视口要求（如桌面 1440×900 100% 缩放与移动端 390 宽），并标明同版本已通过且未受影响的公共行为（直接复用证据、不重复跑）以及新增差异项。
3. **集中执行取证**：**集中验证员**按批次清单执行构建、集成测试与真实浏览器实测，核对控制台/网络报错与交互表现，保存并附上关键截图或日志证据；发现失败时按“业务回归 / 断言过时 / 环境问题”初步归类，退出前清理自己拉起的临时进程。
4. **收口请离**：主持人核对证据并更新对应 `TODO.md` 验收状态；完成后请离**集中验证员**。未通过项退回原执行者按根因最小修复后再纳入下一轮集中复验（只复验受变更影响、新失败与证据缺口部分）。

## 约束

- 遇到登录密码、两步验证、验证码或不可逆外部提交时立即停下上报，不绕过安全校验。
- 验证使用的临时脚本、端口与测试数据不得污染仓库代码或生产数据。
