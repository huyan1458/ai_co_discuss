# 文档标准

作品文件夹里各类文档怎么写、怎么用、什么时候该整理。主线 SKILL.md 和各模板是规定，本文件补三样：每类文档只回答什么问题、不该放什么、能数出来的整理信号。与主线冲突时以主线为准。

## 总则

1. 一事一处。一件事实只在一个文件里写全，别处只写指向。
2. 每个文件只回答一个问题。答不上“谁在哪一步读”的内容不放。
3. 规矩要能查。每条都配一个数得出来的信号；信号由状态检查的“体检”一节或人工清点给出，只提示，不算检查失败。
4. 拿不准的事当轮要有去处，不积压。
5. 修改记录归 git 和项目的进展记录，不写在文件头。
6. 等用户决定的事只放工作台“等用户定”。世界里的【待定】、README 第五节只写指向。

## 状态账本

回答：写或改某一集时，关键的东西现在有多少、在哪、在谁手里；人物现在什么状况；哪些小线和约定还悬着。

收录门槛（只管物资类条目，以及分集记录里物品的得到、用掉、失去；细化模板的“只记影响后面剧情的东西”），满足一条才记：
- 属于七类：燃料、食物与水、药、能源设备、载具、用来交换的东西、关键工具。
- 带名字、作者打算回头用的物件。
- 判断办法：少了它或数量变了，人物的某个选择会不会变。不会就不记，也不为它标“待确认”。

写法：
- 现状文件（主角、物资、据点、人物）：一条不超过 80 字，写“数量；位置或状态；来源集号”。不带引文，不写日期和经过。
- 分集记录：每集不超过 15 行，一行一个变化，带一句不超过 30 字的原文。引文只在这里出现。
- 线索：只用模板的四栏，加一句不超过 30 字的证据。不写“停了几集”（由状态检查计算），不写备注。只记两种：读者会等结果的悬念和伏笔；人物之间没了结的约定和欠账。广播口信、环境细节不记。已回收的整条删掉，回收写在分集记录里。
- 文件头不超过 5 行，只写本文件记什么、怎么写。
- 正例："红梅烟（整条）": "1 条；随船；来自第 15 集"
- 反例：一条里从某月某日写到某月某日，逐次记哪天用过、放在哪，带多处引文。

待确认的出口：
- 只有门槛以内的东西才标“待确认”。
- 记录员交账时单列本轮新增的待确认。主持人在主线第 2 步核对检查结果时三选一：记进待办、攒批补一句正文；定一个口径写进账并标“口径”；不追，删掉这一条。

谁读、谁写、谁核对：照主线“谁读什么”和第 5 步。写手、编剧、批评家·人物不读。

该整理的信号：待确认合计超过 15 处；现状文件有超过 80 字的条目；文件头超过 5 行；同一轮改稿补账超过一次；线索账里“已回收”的条目还在。

## 排线表

回答：一集里各条线同时在发生什么；一条线在全书怎么走。

不放：物件、数字、对白、经过；小线和约定（归线索账、伏笔总表）。

写法：
- 格子不超过 25 字，一格一件事，其余照模板。
- 断线检查的“判断”栏不能只写“有理由”：写出理由是什么，并注明依据来自读者的通读报告还是编剧的阶段构思。空档达到 5 集且中间没有括号呼应的，下一次阶段构思时交编剧复看这一列。

谁读、谁写：照主线“排线表”一节。

该整理的信号：超过一成的格子超过 25 字；判断栏有不带理由的“有理由”；阶段通读后第三节没更新。

## 世界

回答：前半，这个世界的规则是什么、哪些不能违反；后半，规则落到纸面上有哪些画面可取用。

不放：
- 等用户决定的事（归工作台）。
- 要修的旧文之类的任务（归工作台）。
- 讨论经过；每节只留一个出处。
- 剧情方案的候选（归 README 第四节）。世界里的【候选】只指世界条目。
- README 已有的集目、人物、用户决定。

写法：
- 前后两半照模板分开。对正文有约束力的内容放前半，即使它是一幅画面；可用可不用的放后半。
- 状态标注照模板。后半用过的条目在行尾注“已用 NN”。
- 批评家·设定以前半为审稿依据；编剧取材读后半。

该整理的信号：超过 4 万字节（超过后把后半拆成 素材.md，前半留在 世界.md）；出现“待用户”字样；后半里有带约束力的规则；“文件状态”一类的日期落后一个阶段以上。

## 工作台

回答：现在有什么没做完，派给了谁，卡在哪。

写法、清理时机、核实的定义：照主线“工作台与清理”和模板。补两条：
- 主持人每次接手房间，先逐条核对“正在做”是否仍成立，对照 git 最近的提交和进展记录末尾，再做别的。
- 伏笔总表的“打算”只写：在哪个阶段收、带进下一部、全书不证实。定为“只当质感”的整行删掉。“待排”不超过 5 行。

该整理的信号：超过 8000 字节；“最后更新”早于进展记录的最后一条；“正在做”有超过两行的条目或超过 5 条；“待排”超过 5 行；伏笔总表超过 25 行。

## 文风

回答：这本书怎么写。

不放：剧情事实、世界规则、单集的修改意见。

写法：照模板和主线第 4 步。补上限：规矩部分（模板一至七节）一千五百字以内；标杆样本不超过 5 段；用户标注不超过 30 条。超了由写手归并：已升为规矩的标注删掉，同类合并，交用户过目。

该整理的信号：以上任一上限被突破。

## README（作品）

回答：这部作品已经写出了什么，用户定了什么，大纲是什么。

不放：等用户决定的事（归工作台，第五节只留“留白”和一行指向）；世界条目的候选（归世界）；随集变化的状态（归账本）。

该整理的信号：第五节里有“待用户决定”的条目；第四节里有世界条目；集目一行超过两句。
