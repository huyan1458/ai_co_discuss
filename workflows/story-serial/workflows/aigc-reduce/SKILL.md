# 降 AI 味

目标是让正文读起来、测起来都不像模型的默认腔调。分数是验证手段：改完分数降了但文字变差，不算完成。

三件事：**查**（现在多少分、哪里高）、**修**（改到通过）、**记**（把这次学到的写进知识库）。动手前先读知识库，它记着哪些做法验证过有效、哪些无效，不要重试已经证伪的做法。

## 工具与知识库

`scripts/zhuque.py`，只依赖 Python 标准库。密钥读环境变量 `ZHUQUE_API_KEY`，没有则读 `~/.codiscuss/aigc-reduce/key.txt`；缺密钥时请用户提供，不写进本技能文件夹、作品文件夹或任何仓库。

```text
python -X utf8 <本技能文件夹>/scripts/zhuque.py check 文件…            查分：整体结论和每个片段的分数
python -X utf8 <本技能文件夹>/scripts/zhuque.py check 文件 --windows   按约 270 字的窗口逐个给分
python -X utf8 <本技能文件夹>/scripts/zhuque.py locate 文件 [--sentences] [--top N] [--threshold 分数]
                                                                    定位：对高分块逐段去掉重测，找出拉高分数的段落（和句子）
python -X utf8 <本技能文件夹>/scripts/zhuque.py usage                  本机记录的调用次数和扣减额度
```

本技能文件夹就是这份 SKILL.md 所在的文件夹。

知识库在 `~/.codiscuss/aigc-reduce/知识库.md`。没有这个文件时，先把本技能的 `references/知识库.md` 复制过去再用。原因：工作流文件夹对成员只读，知识要在本机越积越多，不能写回这里。

分数含义：低于 0.5 是人工特征，0.5 到 0.99 是疑似 AI，0.99 以上是 AI 特征。整体结论由各片段按字数加权得出。

额度：免费额度每月 50 万 token，每个汉字约扣 1.67。查一遍 7600 字的正文约 1.3 万；`locate` 每定位一个块约 3000 到 5000。同一段文字的结果有本机缓存，重复查不扣。批量实验前先跑 `usage`，预计要用掉当月额度一成以上时先告诉用户。

## 谁做什么

- **主持人**查分、定位、复测、记知识库。脚本要命令行：你没有命令行（以 API 方式主持）时，交给一位能运行命令的成员去跑，把结果交回你。
- **写手**按定位结果改正文。正文是写手的，主持人不直接改；风格上的取舍仍归写手。
- 写手读不到本技能和知识库，所以派活时把要用的东西摘进派活正文（见“修”）。

## 查

1. 把这一集的正文另存成一份 UTF-8 文本，放在你的草稿目录，去掉不属于正文的东西：标题以外的交稿附注、任务书。原因：附注是作者的推理说明，混进去会拉偏分数。
2. `check` 看整体；达到用户的目标就停，不动原文。用户没给目标时，按“人工特征占比过半、没有 AI 特征片段”。
3. 没达到就 `locate --sentences`。它对每个高分块给出两种结论之一：
   - **点名了某段或某句**：去掉它分数就大幅下降。问题集中在这一处。
   - **没有单独一段能解释**：分数由整块的写法累加而成，改一两句没用。

报告给用户时写清：整体分数、高分块的位置（第几段、开头几个字）、每块属于上面哪一种。用户只要求查分时到这里为止。

## 修

改之前确认哪些不能动：任务书【定死的】、已写出的故事事实、事件顺序、人物知道什么、用户已定的句子。改的是怎么说，不是说什么。

派写手时，派活正文里写：

- 要改哪几块：位置、开头几个字、分数、属于哪一种；
- 每块怎么改（下面两条），以及知识库“有效做法”里适用的一两条，原文摘过去；
- 哪些不能动（上面那几样）；
- 改完原地存盘，回答里列出改了哪些块、有没有删掉信息。

两种块的改法：

- **点名了句子**：先试删掉它，或并进前后句只留一个词的信息量。人物、物件、信息必须保留时，换成从视角人物的感知写出来，不要摆成一幅静止的画面。
- **整块累加**：整块重写。不要在原句上逐句替换词语、拆句、删修饰，这三样单独做都验证过无效（见知识库）。把这一块要交代的事实列出来，合上原文，按知识库“有效做法”重新讲一遍。

写手交回后，你对改过的块复测；没过就再 `locate` 这一块，再派写手，循环。一块改了三次仍在 0.5 以上，停下来把三版和分数交给用户，不要继续硬改。

全部改完后把整篇再 `check` 一次：单块的分数和它在全文里的分数基本一致，但片段切分位置会变，以整篇结果为准。

改动动了对白、人物的行为或事实时，按主线的写审循环请两位批评家再审一圈，审过才算定稿；只动了叙述口气的，主持人通读确认即可。已记过账的集改了事实，请记录员按定稿更新状态。

交付时列出改了哪些块、每块前后的分数、有没有删掉信息。删掉的信息逐条写明，由用户决定要不要补回。

不做的事：插入错别字、异体字、零宽字符，机械地同义词替换，用改写工具洗稿，在文中加无意义的口头语。这些会让文字变差，检测器更新后也会失效。

## 记

每次查和修都会产生证据，结束前由你更新知识库：

- 只记测过的：写明原文是什么类型、改了什么、前后分数、文本字数、日期。没测过的想法记进“待验证”，不写成结论。
- 新结果和旧结论矛盾时，两条都留，写明条件差在哪；旧结论被多次推翻再删。
- 同一种做法在三段以上不同的文字上都有效，才从“有效（样本少）”升为“有效”。
- 检测器的模型更新日期变了（网页底部有“模型更新时间”），在知识库开头记一笔，旧结论要抽样复测。
- 知识库里不写具体作品的剧情，只留能说明写法的短例句。

## 用于预防

同类高分块在几集里反复出现时，读知识库的“预防”一节，把适用的做法整理成对文风的修改建议交给用户：落在写手动笔前会读的文风（正反样本、作家人格），不做成事后的禁用词清单。原因：样本比禁令有效，清单越长，模型越容易换成另一套固定说法。文风由用户审定，你不直接改。
