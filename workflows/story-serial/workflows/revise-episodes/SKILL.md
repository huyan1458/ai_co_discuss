# 修改已写的集

角色沿用主线：写手（可以多请几位同平台的会话做并行写手）、批评家·人物、批评家·设定、记录员。主线的规矩照样适用：先存盘再发、推理写进附注、审稿只指问题不写替换句、同一个文件同一时刻只有一个人改。

## 流程

用户读已写的集挑毛病、补细节、换设定时，不走主线的任务书和编剧，按下面的简化流程。新写一集仍走主线。

1. **分拣**：用户的意见先由你逐条判断：常识问题直接回答；只改一句话的小毛病直接定改法；会动前提、设定或用户已定的事，先给用户选项。牵涉几集的，先竖查排线表受影响的列，再列影响清单：哪几集要改、哪几集只查、哪些不动，以及牵涉的事实（谁在哪、东西的来去、谁知道什么），交用户确认后，把受影响的格子按方案填好，再动手。用户明确采用的新方向，同时写进世界或 README；新埋的伏笔记进工作台的伏笔总表，暂不做的记进待办清单。
2. **派写手改一次**：派活写明位置、问题和改的方向，不写替换句；方向只写读者要看懂什么、现在卡在哪，理由只进附注，不要写成“补上理由 X”，否则写手会把 X 放进台词；牵涉多集时附一段“排线表核对”：查了哪几列、查出什么牵连、哪几集因此进了改动范围。写手原地改，回答里只报改了什么。写手和两位批评家用一次依次派活：写手一棒，两位批评家同一棒同时审，**只审一圈，不循环**，审完交回你。按问题类型只牵涉一类时，可以只派对应的那位批评家；牵涉多集的修改必须有批评家·设定，由他读排线表受影响的几行，核对“排线表核对”和正文对不对得上，这一段缺失或漏了牵连的集，判需要返工。
3. **验收**：你读文件核对，通过后按定稿校正排线表里受影响的格子，再按主线“工作台与清理”清理一次工作台。批评家只剩几个字的勘误、可选意见，或写手暂时派不出去时，你可以直接改，并在回答里逐条说明改了什么；动情节、动对白的仍交写手。
4. **记账**：改动涉及物资、人物位置、线索时才派记录员，挂在下一次派活旁边一起派出，不用等它交回；没有账目变化就不派。记录员单列的本轮新增待确认，按主线第 2 步处理。

**多个写手并行（默认做法）**：一批修改牵涉 3 个以上文件，或者分成几项互不相干的修改，默认按文件分给多个写手并行，不必先问用户，也不让一个写手排队一集一集做。只有文件很少，或者改动前后依赖（后一处要等前一处定稿才能写）时才串行。原因：修改工作的文件之间依赖少，串行排队只是在等。

- **怎么分**：同一件事在两集之间来回呼应的，交给同一个写手（比如同一对配角的几场戏），免得两人各写各的；同一个文件同一时刻只派给一位。分工、口径和逐条改法写进一份共用的派活文件，各写手都读这一份，派活消息里只写谁管哪几个文件、先读哪份文件。
- **怎么请**：请与写手同平台、同模型的会话做并行写手，给可写权限，显示名标作“写手2”“写手3”……邀请同平台成员时，程序会先请回同名的暂离成员；请回的如果原来担任别的角色，先把模型和显示名改好再派。用完设为暂离，不移除，下次直接请回。
- **交代前情**：新请进来的写手没有前情，派活时写明要先读的文件（README、文风、世界里相关的规则、要改的集和前后集）和写手的规矩（先存盘再回答、原地改、推理写进附注、只改指定的文件）。
- **代价**：写手一多，批评家一次要审的量和你验收的量都会变大。批评家可以同时审几条线的稿子；验收时逐份核对，回修仍然按原来的分工派回。

**大任务拆小**：一次要改很多集、或要大段扩写时，按集拆成几批，最重的一批先做。原因：单次执行越长，越容易在压缩上下文或连接上超时失败，拆小了失败也只损失一批。

**写手失败或卡住**：先看文件有没有存盘、改到哪一步，已经落地的不让重做，只补没改的部分；偶发的网络错误重试一次；同一个会话反复卡住（长时间没有输出、压缩上下文超时），就把它移出、换一个新会话接手，派活里补上前情。这些你自己处理，不等用户决定；只有登录失效这类你做不了的事才请用户处理。
